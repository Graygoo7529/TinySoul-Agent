# Workspace

Use `workspace.read` when an exact text Link and relevant 1-based line range are known. Use `workspace.search_text` to locate a literal term in an explicit file, directory prefix, or the current Workspace before reading a narrower range. Use `workspace.analyze` only after selecting the exact text Links whose complete contents fit the analysis budget. Workspace inspection is read-only; use create, append, patch, rewrite, delete, or restore actions for mutations.

`workspace.create` creates a new bounded text artifact and `workspace.rewrite` replaces an existing complete target inside the action; both return only committed resource metadata to Context. Pass exact Workspace source links through `reference_links`; a summary in WorkingContext is not a substitute for the source body. Use `workspace.append` for additive text and `workspace.patch` for a precise existing-span replacement. Choose a complete artifact, a natural fragment, or several related changes from the task context and current Workspace limit; no fixed chapter size is required. When a structured failure identifies an output or artifact limit, change the requested scale or use the genuinely different append/patch mechanism. In user-facing documents, cite stable public URLs, DOI links, or arXiv links when available; keep `workspace:` links as internal evidence handles. A transient `retry_same` result may be retried with the same parameters when its disposition permits it; this is not a duplicate-call error.

Prefer `workspace.convert_with_markitdown` for ordinary PDF or DOCX documents when the goal is structured Markdown. Prefer `workspace.convert_with_pypdf` for PDF-specific page-level extraction, embedded resources, image-heavy pages, or stronger page traceability. Both actions create a Markdown target and bounded sibling asset resources; inspect the returned status and links before using generated images as later references.
