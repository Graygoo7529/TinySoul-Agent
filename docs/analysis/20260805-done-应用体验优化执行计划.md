## 背景与目标

前后端联调暴露五类体验问题：Endpoint 在长 Turn 下整体挂起；`stop_turn` / Ctrl-C 不即时；LLM action 超时偏紧；Phase1 协议失败直接结束 Turn；进程重启与超长会话导致当天对话/trace 不可恢复或被截断。

目标是构建可持续使用的 TinySoul 桌面应用体验：

1. 后端在任意 Turn/LLM/Action 负载下保持 Endpoint 可服务；
2. 用户中断即时可感知，错误与停止事件即时可达前端；
3. LLM action 时长与真实工件/思考成本匹配；
4. Phase1 局部失败可反馈、可重试，不误伤控制调用；
5. 当天会话与完整 MessageStack 级 trace 可在重启后经同一事件协议恢复；
6. 前端信息呈现更清晰（轮级统计、运行态、失败卡、渐进深读）。

本计划不引入 Session REST、不引入第二套历史事实源、不建立审批或阻塞状态机。不提供旧协议兼容层。

## 已确认设计

1. **Endpoint 与 Program 解耦服务路径**：阻塞 engine 调用不得占用 ASGI 事件循环。HTTP 业务 handler 使用同步 `def`，由 FastAPI/AnyIO 线程池执行；`/v1/health` 与 WebSocket 帧路径保持纯异步（`wait_after` 已 `asyncio.to_thread`）。
2. **ActiveDayLease 读写语义**：User Turn 与 Endpoint 的 active-day 访问持共享读 lease；日切 `ensure_active_day` 持排它写。新增 `tinysoul.infra.concurrency.ReadWriteLock`。WorkspaceEngine 自身锁继续保证 mutation 线性化；Program 串行分派保证日切不与活跃 Turn 并发写根。
3. **Turn 取消令牌**：`TurnCancellation` 由 TurnRunner 在每个 Turn 创建；`stop_turn` / `exit_program` 经 InputDispatcher 在发出控制信号的同时置位。SignalBus 在 Phase 边界的消费仍是权威控制流；token 只加速在途 LLM/Action 收敛。
4. **即时停止**：供应商 HTTP 调用在 worker 线程执行，等待循环短片检查 cancel/deadline；取消时立即放弃等待，孤儿请求后台完成后丢弃，不回写 Context/Session/ActionResult。Action 批次走既有协作取消与进程终止；`ActionExecutionCancelled` 由 runner 收敛。
5. **Ctrl-C 分级**：第一次有活跃 Turn 则 `stop_turn`，否则 `exit_program`；第二次 `exit_program`；再按恢复默认 `KeyboardInterrupt` 硬退。一律经 AppCommandGateway，与 Terminal/Endpoint 同源。
6. **LLM action 超时**：项目配置 `[action] llm_action_timeout_seconds`（默认 300）在 catalog 加载期填充未声明专用超时的 `llm_action` owner timeout；catalog 专用值覆盖通用默认。完整工件 write/rewrite/script 180→240s；analyze 90→180s。`LLMActionTaskRunner` 5 秒协作收尾语义保留。
7. **Phase1 局部失败**：重试耗尽不抛 turn 级异常；返回空 domain 选择 + phase note（对齐 Phase2）；cycle 结束后进入下一 cycle。TurnRunner 连续 Phase1 失败计数达 3 次才收敛为 Turn failed 并携带累计 feedback。无有效 domain 时先消费有效控制调用再带反馈重试。
8. **持久事件 Journal**：Endpoint-owned，路径 `runtime/endpoint/events/`，分段 NDJSON（默认约 8MB/段），总量上限（默认约 256MB），append-only 含 sequence，启动续号。内存 buffer 保持热缓存。`/v1/events` 协议不变：`after` 在内存窗口内走内存；更早读 journal；超出保留范围才 `gap=true`。journal 写失败不反向影响业务，降级为仅内存并在 status 暴露摘要。不进 archive，按大小滚动淘汰最旧段。
9. **前端恢复与呈现**：前端与后端成对重启是正式重启验收路径；连接/重连（含 lease 坐标变化）后以 status 的 `latest_event_sequence` 快照为目标，从 `after=0` 分页全量重放完成后再挂 WebSocket。同一前端进程内的重发现由唯一连接 owner 驱动，待验证 lease 不覆盖 active connection。恢复轮细微标识；已结束轮的重型 model payload 可骨架化，详情/导出时按 sequence 深读回填；Turn 卡片展示耗时、cycle/action 计数、token/model；运行态计时与 stop 反馈闭环；失败卡展示 reason/module/kind + feedback。前端不再建立独立的固定事件删除窗口或静默页数上限，历史边界由 Endpoint Journal 提供。

## 验收标准

1. 长 Turn（含长 LLM action）期间，`/v1/health`、`/v1/status`、`/v1/control`、WS 心跳响应延迟与空闲一致；`stop_turn` 可下达。
2. Turn 任意阶段 `stop_turn` 后，用户数秒内看到 `turn.stopped`；Ctrl-C 分级语义生效。
3. `core.answer` / `core.reason` / `workspace.describe` 等具备充足超时；通用默认可配置；完整工件与 analyze 专用值生效。
4. Phase1 选择失败不再直接 end turn；有效控制调用不丢失；连续失败有界收敛。
5. 后端重启后，前端重连可恢复当天对话与完整 trace（含 MessageStack）；超长会话可经 `/v1/events` 深读早期事件。
6. 前端：轮级统计、运行态计时、失败错误卡、恢复标识与渐进加载可用。
7. Full suite + typecheck + 前端构建通过；文档与实现一致；联调问题文档对应条目标记 `done`。

## 非目标

- 不新增 `/v1/session/*` 或 Session Explorer。
- 不要求恢复进行中的 Turn（重启即中断）。
- 不要求后端独立重启时保留当前前端进程；同进程 lease 重发现只提供稳健恢复，不替代成对重启验收。
- 不要求跨 Business Day 浏览（前端只呈现当前 active day 的 Turn projection；跨日仍靠 archive/Session 模型侧 inspect）。
- 不引入前端本地持久化 model payload。
- 不宣称硬杀供应商连接或回滚供应商侧计费；只保证本地控制流即时收敛与迟到结果丢弃。

## 实施结果

- Stage A：`server.py` sync handlers；`ReadWriteLock`；`ActiveDayLease` 读写语义。
- Stage B：`TurnCancellation` 贯通 Turn/Cycle/Phase/LLM/Action；Ctrl-C 分级；`stop_turn` 即时放弃在途等待。
- Stage C：`[action] llm_action_timeout_seconds=300`；catalog 专用 240/180。
- Stage D：Phase1 局部失败 + 连续 3 次 Turn failed；控制调用保留。
- Stage E：`EndpointEventJournal` + buffer 深读 + status `event_journal`；补充 Journal/内存边界游标、manifest 重建，以及读取损坏后 `gap + memory tail` 降级测试。
- Stage F：status 快照目标的 REST 全量重放、单 owner lease 重发现、同实例 Turn 恢复、compact history、骨架化/深读/加载更早、Turn 统计与失败卡、stop pending。
- Stage G：同步 `AGENT.md`、endpoint/design/demand/analysis 文档，并重新执行完整门禁。

### Follow-up correction result

- Endpoint replay now carries an explicit Journal scan boundary and never
  appends a later memory event after a Journal byte/record boundary.
- Journal startup rebuilds its manifest from owned segments, repairs a partial
  final record, and exposes stable failure metadata when storage degrades.
- Accepted user input is persisted in the observation envelope; completed
  model payloads are compacted without deleting the UI history window.
- Lease rediscovery runs after status/WS failure and replaces stale endpoint
  coordinates only after the new instance passes status validation.
- Same-instance recovery preserves the authoritative active Turn; a new
  instance closes unresolved historical Turns. Phase1 terminal failures carry
  bounded accumulated feedback.
- Full replay no longer has a silent frontend page cap: it consumes a stable
  status sequence snapshot with a monotonic cursor before attaching WebSocket.
- Backend connection orchestration has one React owner; pending leases do not
  replace active identity, and stale Client/stream/recovery callbacks are ignored.
- A Journal read failure reports `gap=true` and continues with the available
  hot-memory tail, while healthy byte/record page boundaries remain strict.
