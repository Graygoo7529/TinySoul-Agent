# 主对话对话流呈现优化执行计划

日期：2026-10-06

状态：待逐项确认与实施

范围：`visualization/src/features/chat/`（ChatView.tsx、ConversationRows.tsx、LiveStatus.tsx、ActivityGlimpse.tsx）与 `visualization/src/features/trace/ActionGlimpse.tsx`。只改对话流呈现，不动 turnController 读写编排、presentationStore 事件缓冲与问答卡片交互。

## 目标

主对话页是维护者与 agent 的日常界面。当前已结束 turn 在对话流里几乎不留痕迹——`agent.action` 交互行被完全隐藏，回合落定后只剩一行 "Completed"，用户不点 Details 就看不到 agent 做过什么；终态文案中英混杂；一个为动作摘要设计的组件在生产代码中零引用。本计划修复对话流的信息断层，并统一落定态的语义呈现。

## 改进点 1：ActivityGlimpse 容器级状态色

### 现状分析

`features/chat/ActivityGlimpse.tsx:35` 的 gist 容器无论 plan 还是 result、成功还是失败，都是同一样式（`border-line/70 bg-bg-sunken/70`）。文本级状态色已存在（失败反馈红字 :72、exit code 着色 :141、写入绿字 :110），真正缺的是**容器级**的视觉区分——扫一眼无法分出"计划"与"结果"、"成功"与"失败"。

### 修改范围与内容

`ActivityGlimpse.tsx`：

- gist 容器样式按 `data.stage` 与 `data.result?.status` 分流（新增纯函数 `glimpseTone(data): string` 返回容器 className）：
  - plan：中性描边 + `bg-bg-sunken/70`（现状）；
  - result 成功：左侧 2px `border-l-success` + 极淡 `bg-success-soft/30`；
  - result 失败：左侧 2px `border-l-danger` + `bg-danger-soft/40`；
  - result 超时：`border-l-warning` + `bg-warning-soft/40`；
- result 类 gist 顶部加一行小状态行：状态图标（✓/✗/⏱，复用 `components/trace/semantic.tsx` 的 actionIcon/状态语义）+ 语义词（成功/失败/超时）+ 耗时（`data.result.durationMs`，有则显示）；
- 保持 `glimpseBody` 的全部富格式逻辑与 props 签名不变，只改容器与顶部状态行；`ActivityGlimpse.test.tsx` 的 6 组用例随新 className/状态行同步更新断言。

### 预期效果

trail 中动作 gist 一眼可辨阶段与结果：计划中性、成功泛绿、失败泛红、超时泛黄；失败动作不再需要逐字读反馈才能发现。

## 改进点 2：已结束 turn 的动作摘要

### 现状分析

- `ConversationRows.tsx:101-102`：`agent.action` 交互行直接 `return null`——对话流中动作完全不可见；
- `features/trace/ActionGlimpse.tsx`（278 行）是一个为"对话内动作过程卡"设计的完整组件，但**生产代码零引用**（仅测试引用）——死代码；
- `LiveStatus.tsx` 在 turn 落定后折叠为一行标题 + 可展开的 trail 开关（:333-348），但 trail 数据只存在于当前会话挂载期间的活动缓冲（presentationStore）；从 Session 投影回看历史 turn 时没有 trail 可看；
- TurnFooter（`ConversationRows.tsx:37-60`）有 "N recorded actions / failed / timeout" 的纯文本计数——数据已经在 interaction 流里，只是没有可读呈现。

### 修改范围与内容

- `ConversationRows.tsx`：在 TurnFooter 上方新增 `TurnActionsSummary` 组件（同文件内或独立小文件）：
  - 数据来源：`items` 中 `role === "agent.action"` 的交互（TurnFooter 已经在用同一过滤，:41），无需新数据通道；
  - 折叠态一行：`✓ 5 个动作 · 12s`（失败时 `2 失败` 红字），右侧 chevron；
  - 展开态：每个动作一行紧凑行（状态图标 + 语义动作名 + target 摘要 + 耗时），行点击仍 `openTurnProcess` 进 Details（复用现有 `pushActionDetail`，需要 call_id——interaction 上有 action/outcome 字段，若缺 call_id 则打开整 Turn 过程面板）；
- `features/trace/ActionGlimpse.tsx` 处置：评估其渲染结构是否可直接作为 `TurnActionsSummary` 的展开行组件；可用则移用并接线，不可用则**删除该文件与其测试**（不留无引用死代码）；
- 历史 turn（Session 投影）同样生效：interaction 流含 agent.action，摘要组件与视图模式无关。

### 预期效果

任何已结束 turn 在对话流里都留下一行可扫读的动作账（"做了什么、几个失败、花了多久"），按需展开看每个动作；回看历史对话时同样可见。死代码清零。

## 改进点 3：终态语义文案统一

### 现状分析

- `LiveStatus.tsx:640-657` 的 settledHeadline 中英混杂："Failed / Stopped / Waiting for you / Completed" 与 "无需整理 / 部分完成 / 需要进一步指示 / 预算已耗尽 / 已结束" 并存；
- `ConversationRows.tsx` 的 TurnFooter badge（:45）又是另一套："Completed / Failed / 原值"；`components/trace/semantic.tsx` 的 `TurnStatusBadge`（:120-141）是第三套（英文小写原值）；
- `exhausted`/`awaiting_user`/`partial` 等终态在对话里只剩徽章，没有一句解释性文案（用户不知道"等待你的指示"意味着可以继续补充输入）。

### 修改范围与内容

- 新建唯一终态文案来源：在 `features/chat/presentation.ts`（或 semantic.tsx）增加 `turnStatusText(status): { label: string; hint: string | null }`——
  - answered/completed → "已完成"；failed → "失败"；cancelled/stopped → "已停止"；waiting_question/waiting_budget → "等待你"；exhausted → "预算已耗尽"（hint："可以为该轮补充 cycle 预算"）；awaiting_user → "等待你的进一步指示"（hint："直接在下方继续输入即可"）；partial → "部分完成"；skipped → "无需整理"；finished → "已结束"；未知原样返回；
- `LiveStatus.tsx` settledHeadline、`ConversationRows.tsx` TurnFooter、`semantic.tsx` TurnStatusBadge 三处统一改用它（图标与色调保持各处现状）；
- TurnFooter 在终态徽章旁增加 hint 小字（仅 awaiting_user/exhausted/partial 三态显示）。

### 预期效果

同一终态在对话区、详情区、状态栏措辞一致；用户看到"等待你的进一步指示——直接在下方继续输入即可"，知道下一步能做什么。

## 改进点 4：TurnFooter 强化

### 现状分析

`ConversationRows.tsx:37-60`：footer 是 11px 灰字行——终态徽章 + 耗时 + 动作计数 + 右侧 ghost xs "Details" 按钮。无时间戳（一天多轮对话无法分辨每轮发生时间）；Details 入口视觉上近乎脚注。

### 修改范围与内容

`ConversationRows.tsx` TurnFooter：

- 徽章后增加起止时刻小字（`14:32 → 14:33`）：起始时刻从 turn 首条 interaction 的时间字段取，结束时刻取末条；Session 归档无耗时字段时只显示时刻；
- Details 按钮从 ghost xs 升级为 outline xs + 图标（PanelRightOpen 已有），保持位置不变；
- 动作计数文本改由改进点 2 的摘要行承担，footer 不再重复（去掉 "N recorded actions" 串，保留 failed/timeout 红色计数）。

### 预期效果

每轮对话有明确的时间坐标；Details 入口可见但不喧宾夺主；footer 信息不重复。

## 实施顺序与验收

建议顺序：1（glimpse 容器色）→ 3（文案统一）→ 2（动作摘要，含死代码处置）→ 4（footer）。

验收标准：

1. gist 容器按阶段/结果着色，失败泛红一眼可辨；ActivityGlimpse 测试更新后通过；
2. 已结束 turn 显示可折叠动作摘要行，历史 turn 同样可见；`ActionGlimpse.tsx` 或接线或删除，无零引用文件；
3. 三处终态文案同源且全中文，awaiting_user/exhausted/partial 有引导小字；
4. footer 有起止时刻，Details 为 outline 按钮，动作计数不重复。

边界：不动问答卡片已验收的交互与样式；不动 LiveStatus 运行态的 trail/thinking 动效；不动 turnController、presentationStore、事件流；`agent.action` 仍不渲染为独立对话行（摘要行取代其呈现职责）。
