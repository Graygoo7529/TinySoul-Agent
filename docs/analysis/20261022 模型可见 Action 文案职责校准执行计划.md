## 目标与范围

保持自然、简洁的 Hint，让模型在正确的阶段得到需要的信息：Catalog / Domain Skill 帮助选择行动，Action Skill 主要帮助当前模型任务使用输入、生成结果。修正 answer 的交接表达，以及连接复用、服务可用性两处能力说明；简单校准旧计划与清单。

拟调整 12 份现有模型文案/模板文件和 2 份归档计划。只改文案与实施记录，Action schema、执行器、TaskPrompt 协议及 Context 装配不变；不新增配置、加载机制或批量覆盖脚本。

## 已核对的设计语义

- Phase2 使用所选域的 Catalog 与 Domain Skill；`phase2.py` 通过 DomainSkillProvider 获取域指导。
- `ActionTaskFactory.create/selection_input` 在内部模型任务中挂载 Domain / Action Skill。此时外层 Action 已经确定，不适合再提示它如何选择或调用其它 Action。
- `core.answer` 内部任务负责生成用户回答。是否继续读取、分析、修改，或以 `core.ask` 等待同轮回复，应在选择阶段决定。需要结束当前 Turn 时，answer 可以是聚焦的问题、确认或请求指示。
- Workspace analyze / compose / search 的内部任务分别分析材料、生成产物、选择或排序候选。参数与输出协议由现有 schema、TaskPrompt 和 owner 负责；Skill 不重复这些定义。
- Workspace append / inspect / read 直接执行，没有内部 Task 消费其 Skill。Home 的 `skills_action` 是专用 mount 空间，普通 `home.inspect` 不读取它。本轮只撤回这些模板新增的重复段落，不据此声称改善了模型实际输入。
- ACP 空闲连接可跨 Turn 复用；Turn 收尾的 Job 和 session 清理不等于主动断开可复用连接。MCP 服务说明采用可读的可用性描述即可。
