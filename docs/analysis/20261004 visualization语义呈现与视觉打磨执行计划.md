# visualization 语义呈现与视觉打磨执行计划

状态：`pending`。2026-10-04 已完成本轮代码对照和代表页面分析；以下方案供维护者讨论，尚未实施。设计确认后按批次推进，不以本文的诊断验证代替实施验收。

分析基点：`f161be3`。视觉与动效基线：`c479ca0`。接口迁移参照：`35f1440`。范围以 visualization 为主；后端只在已有事实不能被准确呈现时补充所属 owner 的明确投影。

## 1. 判断与整体方向

当前前端已经恢复了原版主对话的大部分视觉骨架。继续整体换肤、缩小活动视窗或调整一组动画常量，收益低且容易再次损伤已打磨的体验。本轮应在原有材质和运动方式上提高信息的准确性、可读性和操作可达性。

主要目标：

1. 主对话能直接读懂“准备做什么、正在做什么、实际得到什么、现在需要我做什么”。
2. Home/Memory/Context 等阅读界面先提供连续可读的内容与明确来源，再披露技术结构。
3. 运行状态、动作结果、重要事实和待办互不冒充；装饰服务这些差异。
4. 新页面复用现有组件、资源路由、设置布局和 Inspector 导航，不建立另一套业务状态或万能表现框架。

## 3. 后端语义与前端责任

| 内容 | 正式来源 | 前端责任 |
|---|---|---|
| 排队、运行、等待、取消意图、终态 | TurnSnapshot / 请求回执 / Session 正式投影 | 解释状态与可用操作；不根据动画、定时器或最后一条事件推算正式结果 |
| reasoning、intent、行动计划、执行事实、结果 | 有 scope 的 Observation、Action call/execution/result | 显示真实记录、保留来源与调用身份；计划不标记成功，取消/未执行/未知不伪造结果 |
| 当前 todo、milestone、已安装背景 | Context owner 已安装快照 | 渲染现态；活动条目只是变化说明，不反向计算另一份计划 |
| 等待回复/预算 | 具体 Turn、question/request 身份 | 每个提交绑定目标，失败保留草稿；等待仍占根位置，不显示成可直接开始下一根 work |
| Home / Memory / Workspace | 各 owner 的读取与服务 lease | 保留 view/day/link；浏览不触发模型 Context 加载，不取得 Reflection 专属写权限 |
| 长文分页 | 同一资源、视图与读取绑定下的顺序内容和 continuation | 只拼接实际取得的连续文本；处理过期/缺页，不从当前磁盘或其他日期补造 |

现有契约足够支持本轮主线。优先不改后端：`target_link/source_link`、正式回复文字、finish 失败和内容片段都已经存在。若实施时发现缺少实际消费者必需的来源/范围字段，应列出该场景、现有不足和 owner 投影后再讨论；不添加前端专用持久日志、通用摘要生成接口或第二套生命周期。

## 4. 主对话设计

### 4.1 恢复动作的语义表达，保留原版预览壳

在现有 trace registry / facts / semantic 边界形成一份轻量、纯函数的动作表现描述，供活动标题、紧凑预览和 Details 共用。参考 c479ca0 的 descriptor 职责，适配当前 canonical action ID；不复制旧 derive、旧字段别名、整个业务状态树或大量按动作拆分的文件。

先覆盖真实常用路径：

| 行动 | 主行 | 次级内容与展开 |
|---|---|---|
| Workspace 读/写/编辑/移动 | “读取/写入/编辑”＋可读文件名；移动显示来源→目标 | 完整 Link、计划修改片段；只有返回事实才能称为已写入/实际变更。参数推导的 diff 标为拟修改，不能冒充实际文件差异 |
| Home / Memory Inspect | “阅读”＋文档名/资源身份 | 展示实际摘录与继续读取入口，保留 owner 与来源日期 |
| Search | “搜索”＋查询/范围；结果说明“本页 N 项”或正式总数 | 标题、命中片段、真实依据；翻页数量不是全量总数，Score 不是置信度 |
| shell / script / Job | “执行命令/运行脚本/启动后台工作”＋目标 | 命令/来源、真实 stdout/stderr 摘录、退出码、是否截断；启动成功不等于 Job 完成 |
| 活动记忆与持久写入 | “更新活动记忆”与“写入持久记忆”分别表达 | 仅从所属 Action 事实描述范围；不把 memorize 说成持久 Memory 写入 |
| MCP / ACP | 可读服务/工具/代理名及委派要求摘要 | 完整调用名与参数放详情；连接、委派、等待与结果各归实际记录 |

主行建议保持一个动词、一个主要对象和一个状态；不让所有 ID、domain、时间、计数同时争夺注意。保留现有 action family 的专用结果视图和未知动作的通用结构化兜底。长目标、长摘要和缺少预览必须都有明确、可键盘访问的详情入口。

plan / execution / result 的边界继续可辨；不把独立结果更新回写成已展示计划正文，不打破预览落位后的高度稳定。增加摘要时先限制默认披露长度，完整信息由用户展开。

### 4.2 等待的视觉语义与回应入口

推荐“原位提醒”：保留当前 LiveStatus 和活动展开状态，等待时将主标题改为具体的“等你选择”或“需要增加执行预算”；旋转和扫光停止，改用静止的淡暖色状态标记。排队使用中性静态状态，准备/运行沿用原版动态，停止保留明确文字和现有停止语义。

利用现有问题提示和滚动 owner，在等待抬头提供“定位问题/查看预算”入口。只有用户正在跟随当前轮时，才允许一次将新问题带入可视范围；手动阅读历史时只提示。定位到问题本体，不一律跳到聊天末尾，不抢键盘焦点。超长选项可以自然滚动，提交区保持可达；不要复制一份问题表单到 Composer。

不默认在等待到来时折叠或搬动全部 Activity。可讨论的替代是用户主动进入“回应聚焦”视图：收起过程后突出问题，提供返回过程入口。它只改变局部披露，不卸载问题草稿，不代表 Turn 已结束。该替代需与维护者确认，默认计划采用原位提醒。

预算等待明确显示单位为执行轮以及实际请求信息，不转换成剩余时间或完成百分比。问题与预算同时存在时分别显示真实请求，不由一个标题隐藏另一项。Reflection 同样复用上述表现与显式目标绑定。

选择回复气泡优先显示关联问题中匹配的选项标签与评论，机器 ID 留在详情；缺少问题映射时使用已有正式回复文字，不猜测标签、不按固定字符串格式强行切割。原问题、全部选项、选中结果仍可完整阅读。

### 4.3 WorkingZone 的重点与全文

- milestone 继续是事实寄存器；保留旗标/事实语义，长文可就地展开，不能加统一完成勾。
- todo 保留 owner 顺序和状态。在较多条目时，以有限预览与“查看全部 N 项”披露，明确隐藏数量；用户展开后不因新事件强制收起。具体默认条数通过长计划截图确认，不先改变轨迹窗口常量。
- 明确区分待办、进行中、完成、取消。历史/结束 Turn 中保留原始 todo 状态，但停用旋转，避免暗示历史任务仍在执行。
- 当前事项与最近事实使用原版浅凹面分区，不新增彩色大面板或进度仪表。上下文容量与 todo 数量都不代表长期目标完成度。

## 5. 内容阅读与次级页面

### 5.1 Home / Memory 连续阅读

首先修复传输片段与 Markdown 语法边界混淆：同一次、同一文档的连续 items 按原序无分隔符拼接，再交给共享 Markdown 渲染；不插入空行，不各片补围栏，不把 2000 字符片段当成独立段落。

分页仍按需读取。已加载部分作为连续前缀，末尾清楚显示“继续读取”；不能无限自动读取全文，不能拼接不同 ref/view/day 或已失效 continuation 的片段。保留 fragment 定位，结合原文行范围和 Markdown 节点位置映射到实际块；对跨片段同一行或跨行块，定位该块并说明范围，不使用失真的片段边界作为文档结构。

在相同读取区域复用文本/代码/表格的既有渲染和资源路由。普通正文设置约 68–76ch 的阅读上限并居中，宽表格/代码在自身区域处理溢出；不要压缩整个页面字体。左侧目录保持原位，大标题使用可读名称，完整 Link 放次级来源行及复制入口。

Home 的选择器说明“当前有效内容 / 已接受基线”，差异入口显示真实差异状态；查看 actual/effective 不执行审核。Memory 清楚区分“当日活动记忆 / 持久知识”，来源日、文档类型、redirect 按实际元数据呈现。引用与反链只画真实 owner 边，采用简洁关系列表，不新增推断知识图谱。

Workspace 保留真实当天文件、manifest、编辑器和 Trash 语义。打磨树节点长名、路径、保存/错误状态和窄屏目录入口即可，不恢复 CAS、自动回滚或一个统一任意文件 API。

### 5.2 Context / Session / 过程详情

Context 保留 Background / Trace / Working 分组，在卡片标题中使用“身份规约、历史对话、当前输入、Home、Memory、本轮轨迹、计划、工作区”等语义标签。对于尚未识别的插件段，保留真实名称并中性展示，不杜撰解释。State/Heap/Stack/Map、segment ID 和完整时间放技术详情；主视图保留所属轮、来源日、捕获时点与资源数。

可用一条低饱和比例带显示各槽的**已投影字符数构成**，但只有数值可加且语义一致时才画；不当作 token 上下文占用率。优先保证语义卡片，比例带不是本轮必做装饰。

Session map 继续作为历史导航：突出话题标题、解释摘要、事实来源与“未归类”；共享成员和回路不伪装成唯一树父子关系。问题/选项/回复保持成组，展开可到原始 Turn，前端不提供外部 organize 写入口。

Details 保留现有 Process → Action → ModelCall → Context 导航、阶段底色和相邻抽屉。Action 首屏先给实际结果、对象和短反馈；参数、frame data、原始 JSON 置于明确披露层。模型请求正文是调试工作本身，仍可完整读取，不一概隐藏结构化内容。

### 5.3 Runtime / Search / Settings

Runtime 保留现有 Execution、Jobs、ACP、MCP、Environment 分页。运行页首先解释“正在做什么/等待什么/下一项”，结束结果直接显示可读摘要和失败原因。`finish_failures` 归必要收尾失败，附属 `cleanup` 单独折叠。Job 执行终态与资源释放分别表达，不把“已请求停止”当成“已停止”。空页面保留克制说明和相关入口，不为填空制造统计卡片。

Search 沿用现有 query、scope、Conditions、结果再筛选。剩余优化是把 `filter: { ... }` 与 select/rerank 等技术标签转成“限定来源 / 从结果中筛选 / 重新排序”的可读条件摘要，结构化原值放详情；清楚区分 source.where 与结果 filter。当前页、候选覆盖、截断与真实证据有需要时显示，不造理由、不把 rerank 说成排除结果、不隐式发起模型检索。

Settings 沿用新近完成的 SettingsPicker、字段披露和唯一草稿，不再规划整体重排。处理能力 token 的可读标签、必要字段说明对比度、连接/模型行长标识。标签与正式值分开，保留搜索原始配置 key；本地修改、已保存待激活、实际运行配置仍各自准确。

## 6. 视觉与动效约束

延续 c479ca0 的格纸背景、轻着色用户气泡、深色流入终端、凹面回答板、细刻线、玻璃抽屉和品牌渐变。新区域使用同一组现有 token，不引入第二套主题。

| 场景 | 材质与颜色 | 动效意图 |
|---|---|---|
| 正在准备/计算/执行 | 原版 accent 流光与浅晕 | 继续原有呼吸与文本扫光；不为每个活动行增加持续运动 |
| 等待回应/预算 | 很淡的暖色边缘与明确标签 | 停止运行旋转；可有一次柔和显现，默认不持续催促式闪动 |
| 用户聚焦的输入/选项 | accent 细边、内高光、低强度外晕 | 焦点/选择变化时短过渡，键盘焦点始终可见 |
| 完成/取消/未知 | 中性静态表面，结果由标签区分 | 完成按原版收束；只有真实成功使用成功色 |
| 资源阅读/设置 | 稳定正文底面、轻分隔、可读标题 | 高光只用于焦点、展开或提交反馈；长文不持续漂移或闪烁 |

可在新问题卡与当前选中资源周边增加小范围低透明度晕光。默认不扩大为全页面光斑，不给所有面板加玻璃和阴影。Details 的 Phase3 绿色表示阶段，并非动作成功，状态色仍由结果控制。

正文、关键标签、输入内容优先满足对比度；次级时间/来源保持弱化但可读。按实际底色检测正常文本 4.5:1、必要控件/图形边界 3:1，不以更改全局 fg-faint 为捷径。明暗主题分别验收。

减少动效同时尊重系统与应用设置：除了 CSS，也要核对 Motion、滚动跟随、打字与延迟展开；减少动效时立即得到同样信息与布局，不改变业务先后顺序。主对话只给当前新增内容必要入场，不因历史恢复、切页或快照重读重播。
