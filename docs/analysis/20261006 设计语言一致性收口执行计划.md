# 设计语言一致性收口执行计划

日期：2026-10-06

状态：待逐项确认与实施

范围：`visualization/src/styles/index.css`、`visualization/src/components/ui/`（Badge.tsx 等）、`visualization/src/components/shell/`、`visualization/src/store/appStore.ts`，以及散点文案所在的少量组件文件。

**定位**：这是跨页面的一致性收口计划，在前五份计划之后或穿插实施。原则是收敛而非扩张——把对话区已验证的设计语言抽象为全应用共享的少量规则，消除双轨命名与硬编码，不引入新的视觉风格。

## 目标

现有 "Luminous" 设计系统（三层表面、domain 色调、统一缓动、reduced-motion 三层兜底）已成熟，但存在几处系统性毛边：光效只集中在对话区、遮罩色硬编码、Badge tone 双轨命名、中英文案混杂、大内容区加载只有裸 Loader2、一处开发者机器路径硬编码。本计划逐项收口。

---

## 改进点 1：三档语义光效 utility

### 现状分析

光效动效集中在对话区（live-border、text-shine、selection-glow）；设置卡片、集合列表选中行、详情面板可点击行等其他页面几乎没有状态反馈光泽。已有 token `--focus-glow`、`--selection-glow`（index.css）证明色值语言已确立，缺的是语义化的三档 utility。

### 修改范围与内容

`styles/index.css` 增加三个 utility 类（色值一律 `color-mix` 派生自 `--accent`，不写硬编码 hex；`@media (prefers-reduced-motion)` 与 `.ui-reduced-motion` 下全部降级为静态边框变化，沿用现有三层兜底机制）：

```css
/* hover 引导：可交互元素的轻微外晕 */
.glow-hover:hover { box-shadow: 0 0 12px color-mix(in srgb, var(--accent) 22%, transparent); }

/* 选中确认：内层光泽 + 边框高亮 */
.inset-glow-selected {
  box-shadow: inset 0 0 8px color-mix(in srgb, var(--accent) 28%, transparent),
              0 0 6px color-mix(in srgb, var(--accent) 14%, transparent);
}

/* 处理中呼吸：运行/加载脉冲 */
@keyframes pulse-breath { 0%,100% { opacity: 0.6; } 50% { opacity: 1; } }
.pulse-breath { animation: pulse-breath 2s ease-in-out infinite; }
```

应用点（随前五份计划落地时顺带应用，不单独大面积改）：设置集合对象列表选中行、详情面板可点击行 hover、Memory 目录选中行。本计划只交付三个类与约定，不批量改组件。

### 预期效果

全应用的光效反馈只有三档语义（引导/确认/处理中），任何新组件按需取用，不再各自发明阴影值。

## 改进点 2：设计 token 收口

### 现状分析

- 遮罩色硬编码两处：`Modal.tsx` 的 `bg-black/40`、`InspectorHost.tsx` 的 `bg-black/25`——未 token 化；
- Badge tone 双轨命名：`green/red/yellow/blue` 与 `success/danger/warning/info` 并存且互相映射，domain 色又借 tone 名（purple/teal/orange/pink）表达——新增域时要记两层映射；
- `--term-*` 终端色系列未进 `@theme` 映射（index.css :141-161 附近只映射了颜色与 domain-soft 等），TSX 里用不了 `bg-term-bg` 类工具类；
- 圆角无语义阶梯：`rounded-md/lg/xl/2xl` 散用（靠约定维持）。

### 修改范围与内容

- `index.css`：新增 `--scrim`（`rgb(0 0 0 / 0.4)`，暗色主题同值）并映射进 `@theme`；Modal/InspectorHost 两处改用它；
- `--term-bg`/`--term-bg-2`/`--term-fg`/`--term-green`/`--term-cyan` 补进 `@theme` 映射（生成 `bg-term-bg` 等工具类）；
- Badge tone 收口：**不改 Badge 的公开 tone API**（避免大面积调用点改动），在 `Badge.tsx` 内把 `green/red/yellow/blue` 标记为 deprecated 注释并加语义别名（`success/danger/warning/info` 直通），新代码只用语义名；存量调用点随各页面改造逐步切换，不强制一次性替换；
- 圆角：在 index.css 注释中固化为约定（行 sm(6)/卡片 lg(12)/容器 xl(16)），不建工具类——纯文档化收口，零代码风险。

### 预期效果

遮罩与终端色全部 token 驱动；Badge 语义名单轨化（向后兼容）；圆角约定成文。

## 改进点 3：中文文案收口（chrome 层）

### 现状分析

语言策略已确认为**中文为主、机器标识保留英文**。当前混杂点：Settings 底栏等已是中文（好），但壳层与散点仍英中并存——TopBar "整理" vs 其他英文按钮、StatusBar 原始状态串、`DiffGlimpse`/`TerminalGlimpse` 的"收起/展开输出（N 行）/行变更/处更多变更"（`ActivityGlimpse.tsx:150,180,186,201`）、`LiveStatus` settledHeadline（已由对话流计划的改进点 3 覆盖，不重复）、`BackgroundPanel` 的"没有读取到整理背景"、设置区若干英文 `title` 提示（如 `SettingsBottomBar.tsx:65,73,93` 的英文 title）。

### 修改范围与内容

- 逐文件把面向用户的静态文案统一为中文：TopBar、StatusBar（状态值仍走语义映射）、BackgroundPanel、QuestionForm placeholder（"Additional thoughts (optional)…"→"补充想法（可选）…"等——注意同步测试断言）、SearchPanel/ReferencesPanel/ReflectionDialog 的英文段落、设置区的英文 title 属性；
- 机器标识（action id、link、枚举原值）保留英文原文，必要时原值收 tooltip；
- 不建多语言框架；settings 既有 i18n 表（`settingsText`）继续沿用，新文案直接中文常量。

### 预期效果

界面语言统一为中文；机器标识保持精确；无中英同屏混杂。

## 改进点 4：骨架屏组件

### 现状分析

大内容区加载普遍用 `<Loader2 className="animate-spin-slow" />`（Home 目录、Memory catalog、Workspace 树、ProcessPanel 等）——空白区一个旋转图标，无内容预期。`index.css:357-365` 已有 `shimmer` keyframes 未被组件化使用。

### 修改范围与内容

- `components/ui/` 新增 `Skeleton.tsx`：`Skeleton({ className })`（`animate-pulse` 或复用 shimmer 的圆角条）+ `SkeletonLines({ rows })` 组合件；
- 应用三处（与各自页面计划协同，不越界）：Home 目录加载态（`HomeDirectory.tsx:101-105`）、Memory catalog 加载态、Workspace 树加载态——替换为 3-5 行骨架条；
- 其余 Loader2 场景（按钮内、小区块）保持不变。

### 预期效果

内容区加载有结构预期（一排占位条而非空白转圈），感知等待更短。

## 改进点 5：projectRoot 默认值修正

### 现状分析

`store/appStore.ts` 的 `projectRoot` 默认值硬编码了开发者机器路径 `B:/WorkSpace/TinySoul-Agent`，且持久化到 localStorage——跨机器分发时会留下错误兜底值。

### 修改范围与内容

`appStore.ts`：默认值改为 `null`（语义"未发现"）；消费方（Tauri 发现失败的兜底路径）显式处理 null——提示未检测到项目根而非使用错误路径。

### 预期效果

跨机器运行无错误路径残留；"未发现"是显式状态而非隐藏假设。

## 实施顺序与验收

本计划五项互相独立，可任意顺序；建议 5（一行级）→ 2（token）→ 3（文案，量最大）→ 4（骨架屏）→ 1（光效随各页面计划落地）。

验收标准：

1. 三个光效类存在且 reduced-motion 降级正确；
2. 无 `bg-black/40`/`bg-black/25` 硬编码；`bg-term-*` 工具类可用；Badge 语义别名可用且旧 tone 不破坏；
3. chrome 文案全中文，机器标识保留英文；相关测试断言同步通过；
4. 三处内容区加载态为骨架屏；
5. `projectRoot` 默认 null，消费方显式处理。

边界：不改主题机制与 uiPrefs 层；不改任何动效的时序参数；不批量替换存量 Badge tone 调用点；文案收口不涉及模型可见文案（prompts 属后端 owner，不在本计划）。
