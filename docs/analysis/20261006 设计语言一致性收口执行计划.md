# 设计语言一致性收口执行计划

日期：2026-10-06；2026-10-27 按当前设计 token 与共享设置复核

状态：待逐项确认与实施

范围：`visualization/src/styles/index.css`、`components/ui/`、`components/shell/`、`store/appStore.ts` 及散点文案组件。跨页面改动随对应页面计划落地，不扩张到预期外界面。

**定位**：收敛现有 Luminous 语言，不引入新风格、不为假设消费者创建工具类或兼容别名。项目共享主题与动效偏好继续由 presentation/uiPrefs 管理，本计划不改变其保存协议。

## 改进点 1：语义光效收口

### 最新基线

现有 focus/selection glow、live-border 和 reduced-motion 已可用；Tailwind 已有 `animate-pulse`，无需再写一套相同的 pulse-breath keyframes。

### 修改范围与内容

只新增两个有真实消费者的 utility，色值由 `--accent` 经 color-mix 派生：

```css
.glow-hover:hover {
  box-shadow: 0 0 12px color-mix(in srgb, var(--accent) 22%, transparent);
}
.inset-glow-selected {
  box-shadow: inset 0 0 8px color-mix(in srgb, var(--accent) 28%, transparent),
              0 0 6px color-mix(in srgb, var(--accent) 14%, transparent);
}
```

- hover 引导使用 glow-hover，选中确认使用 inset-glow-selected；处理中直接复用现有 `animate-pulse`；
- 仅在设置集合选中行、详情可点击行、Memory 目录选中行随页面计划使用，不全站铺光；
- `prefers-reduced-motion` 与 `.ui-reduced-motion` 下降级为静态边框/背景变化，不改变布局。

预期效果：光效只承担引导、确认、处理中三种语义，不重复实现已有脉冲动画。

## 改进点 2：遮罩 token 收口

### 最新基线与删减

Modal 的 `bg-black/40` 和 InspectorHost 的 `bg-black/25` 仍是真实硬编码。其余旧假设已删除：

- Badge 当前只有一套颜色 tone 类型，并不存在 success/danger 等语义别名双轨；不再新增兼容别名；
- `--term-*` 已由 term-block 使用，当前没有 `bg-term-*` 工具类消费者；不为此扩张 @theme；
- 圆角阶梯已在视觉系统设计中明确，不再增加平行注释或工具类。

### 修改范围与内容

新增 `--scrim` 并映射到 @theme；Modal 与 InspectorHost 改用它。若两种遮罩强度确实需要区分，用同一 token 的透明度派生，而非再建两个语义不清的颜色值。

预期效果：覆盖层遮罩统一受主题 token 管理，其他已经清晰的设计不做无消费者抽象。

## 改进点 3：中文文案收口（chrome 层）

- 将 TopBar、StatusBar、BackgroundPanel、QuestionForm、SearchPanel、ReferencesPanel、ReflectionDialog 和设置 title/空态等面向用户的静态文案统一为中文；
- Diff/Terminal gist 已中文化的部分保持，不重复修改；
- action id、ref、provider/model ID、枚举 value 和用户输入保留原文；需要时给中文说明而非翻译机器值；
- Settings 继续使用现有 settingsText/catalog.zh-CN/ui.zh-CN，不建多语言框架；同步更新真实行为测试，不把文案快照扩散到所有组件。

预期效果：界面语言一致，精确协议身份不受损。

## 改进点 4：结构化加载骨架

- 新增轻量 `Skeleton` / `SkeletonLines`，复用现有 shimmer 与 reduced-motion 降级；
- 只替换 Home 目录、Memory catalog、Workspace 树三处大内容区的单独 Loader2，使用 3–5 行有结构占位；
- 按钮、小面板和短操作中的 Loader2 保持，不全站替换。

预期效果：加载时即可预期目录结构，减少空白转圈；不引入新的页面骨架。

## 改进点 5：projectRoot 默认值修正

- appStore 的 projectRoot 默认改为 null（“未发现”），不再硬编码 `B:/WorkSpace/TinySoul-Agent`；
- autoConnect、ConnectScreen、Tauri discovery 与持久化 merge 显式处理 null；已有用户自己保存的有效路径继续可用；
- 未发现时显示可操作的未检测提示，不静默回退到开发者机器路径。

预期效果：跨机器分发不残留错误根目录，未发现成为显式状态。

## 实施顺序与验收

建议 5 → 2 → 3 → 4 → 1（随页面计划应用）。各项独立可验收。

1. 两类光效与 animate-pulse 职责清楚，reduced-motion 正确；
2. 两处遮罩无硬编码，未新增无消费者的 Badge/terminal 别名；
3. chrome 静态文案中文化，机器标识保留；
4. 三处目录加载为骨架屏；
5. projectRoot 无开发者路径默认，null 流程可用；
6. `npx tsc --noEmit` 与 `npx vitest run` 通过。

边界：不改主题/presentation 保存机制，不改已有动效时序，不批量改 Badge tone，不处理模型可见 prompts，不扩张到其它页面。
