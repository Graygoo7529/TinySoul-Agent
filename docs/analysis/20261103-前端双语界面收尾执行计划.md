## 1. 目标与现状

将已有的项目共享语言能力落实到完整前端：选择 `zh-CN` 或 `en-US` 后，所有正式用户入口的固定界面文案、状态摘要、提示与无障碍文本使用所选语言；当前输入、业务事实和原始诊断保持原样。语言切换不关闭弹窗、不丢失草稿、不重新连接、不重放业务请求。

后端 `PresentationService` 已是语言的唯一持久 owner，`uiPrefsStore` 已表达 saved/pending，Interface 已能保存 locale。本轮复用这条链路。主要修改在 `visualization/src`，无需新增 Python 翻译系统、Endpoint 协议、第三方 i18n 框架或 Rust 命令。

### 1.1 已完成并复用的基础

- `InterfaceLocale`、默认 `zh-CN`、TOML 读写、HTTP patch/response、TypeScript API 与契约 fixture。
- `uiPrefsStore`、`presentationController` 的即时预览、串行保存、失败待提交、连接 epoch 隔离；App 设置 document lang。
- `src/i18n` 双语字典、按身份投影 ConfigCatalog、协议摘要入口；旧 `settingsText(source)` 已删除。
- Shell、连接页和部分 Settings 已接入。既有业务测试、配置保存机制和 FakeEndpoint 可继续复用。

## 2. 确定的设计边界

### 2.1 语言事实和生命周期

```text
后端项目 presentation/configs/interface.toml
           │ 现有 Presentation API
           ▼
uiPrefsStore：已保存值 + 待保存修改
           │ 有效 locale
           ▼
useI18n / 显示格式函数
           ├── 界面固定文案和已知状态摘要
           ├── ConfigCatalog 显示投影
           └── 原文内容：直接呈现
```

- 仍只支持 `zh-CN` / `en-US`，默认固定 `zh-CN`。
- 未连接、logout 和切换后端使用现有 resetPresentation 语义。连接后读取所属项目的共享设置；旧项目迟到响应不能污染新项目。
- 保存失败保留 pending locale；显式重试或放弃重读沿用现有流程。其它客户端在重新读取后更新，不增加实时广播。
- locale 不进入 address/token、本地持久偏好、Agent 配置草稿、运行方案、Context 或模型选择。
- locale 变化只刷新显示投影；不能给 App、页面或表单加 `key={locale}` 来强制重挂载。允许现有 Presentation 保存请求；不得因换语言额外检索、执行 Action、重复提交问答或重启 Agent。

### 2.2 内容分类

| 内容 | 处理方式 |
| --- | --- |
| 按钮、标题、空态、提示、输入约束、tooltip、aria-label、图表固定图例 | 稳定 message ID，随 locale 渲染 |
| 已登记的状态、阶段、Memory kind、来源分类、只读原因 | 按现有稳定值映射显示标签；底层值和控制分支不变 |
| ConfigCatalog title/description/choice label | 按 descriptor 的稳定身份投影；中文未登记项及英文使用 source fallback |
| 用户输入、问题正文和选项、Agent 回答、思考/执行输出、Home/Memory/Workspace 正文 | 保留原文，不能因碰巧等于字典值而翻译 |
| 用户命名的模型/provider/action、方案名称、路径、ref、命令、JSON 字段与值 | 原值呈现；外围的“名称”“引用”“结果”等标签翻译 |
| API 原始 message/details、Observation 自由文本、未知协议值 | 保留诊断，已知 code 可加本地化摘要；不解析 message 改变控制流 |
| UI 生成并进入请求的可编辑说明，如 Home review prefill | 仍是提交内容，保持当前文案及编辑值；仅本地化其标签/placeholder，不让 locale 改写模型输入 |
| Trace 导出的 JSON、manifest、证据与 `exportNarrative.ts` 叙事 | 保持现有导出协议和文本；导出按钮、进度和结果提示双语。本轮不扩展为多语报告功能 |
| dev 验证页面、测试样例、注释、协议示例 | 不作为正式界面文案迁移对象；正式页面中的示例若可提交为请求内容，同样按内容处理 |

技术术语如 Agent、Turn、Cycle、Phase、Home、Memory、Workspace、ACP/MCP 可以按现有产品术语保留。阶段解释必须反映 AGENTS 中的真实语义：Phase1 更新语境与选域，Phase2 生成行动，Phase3 执行；观察到的意图与实际执行、Turn 结束与长期目标完成不能因翻译合并。

## 3. i18n 实现结构与调用约定

### 3.1 按职责组织，保留一个入口

沿用 `src/i18n`，整理为下列职责。只在实际调用边界需要时拆文件，不创建语言 registry、插件加载或通用模板平台。

```text
src/i18n/
  index.ts                  公共导出
  types.ts                  Locale、MessageId 相关类型、UiText
  messages/zh-CN|en-US/      common、shell、connection、settings、chat、trace、runtime、
                            workspace、home、memory、history、context、resources
  catalog/                  中文 descriptor 文案及纯投影函数
  protocol/                 已知 code/value 的文案映射
  core.ts                   字典组合、插值和纯翻译
  react.ts                  useI18n：订阅有效 locale
```

core 和字典不导入 React、业务 store 或 Settings parser。ConfigCatalog adapter 可以使用现有 catalog 类型/匹配能力，但固定文案和 store 类型不再反向加载 Settings 模块。`Locale` 沿用 API 的值域，避免重复声明两套语言集合。

### 3.2 语义 ID 与完整性

- 将 `settings.text.<hash>` 及重复的固定语义整理为可读 ID，例如 `settings.object.empty`、`settings.interface.saveFailed`、`chat.question.submit`、`workspace.directory.back`。不保留旧 key alias，不再用 source 文本或 source hash 生成业务 ID。
- 同一含义的通用 Retry/Cancel 可复用；不同业务含义不因中文恰好相同而合并。未知动态值不强行变成 MessageId。
- 静态状态表保存稳定 value、样式和 message ID，不在模块导入时调用翻译函数。
- 插值使用 `t(id, { count, name, ref })`，句子由字典掌握语序；不拼接“选择”+动态标题。需要链接或 code 的句子由组件组合，字典仍为纯文本，不存 HTML 或 React 元素。
- 类型检查约束两种语言的 key；测试覆盖各分组 key 集合、合并前 ID 冲突、占位符集合一致。固定 UI 缺 key 是开发缺陷，不把混用另一种语言当正常路径。Catalog/未知协议的 source fallback 是另一种合法语义。
- 两种语言都保留“简体中文 / English”自称；不能用英文文件禁止汉字来验证质量。计数涉及的英文单复数用少量明确文案或 `Intl.PluralRules` 处理真实消费者，不引入完整 ICU DSL。

### 3.3 响应式渲染与缓存

- React 消费 `useI18n()`，hook 只订阅有效 locale；翻译函数在 locale 不变时保持稳定引用，避免影响依赖它的 memo/effect。
- 纯翻译和格式化函数显式接收 locale。纯业务派生继续处理 typed 事实，不读取全局语言 store；在已有 presentation/view 层加入翻译。
- Settings search、静态导航/状态数组的展示、Memory kind label、drawer title、图表 label 等都在渲染期投影。包含已翻译结果的 memo 显式依赖 locale。
- `searchConfig(catalog, query, locale)` 显式处理 locale。搜索继续匹配 source title/description、当前语言显示文本和稳定 path；locale 不改变命中身份或跳转协议。
- formatter 对显示日期、时间和数字使用明确 locale；不更改时区、后端 CalendarDay、ISO 日期、排序规则、表单数值协议及 `ms/s/KB/MB` 等技术单位。
- 不把 locale 放入加载资源/订阅事件的 effect 依赖以触发重新读取；应把加载事实与翻译显示分开。

### 3.4 已显示提示、抽屉与错误

单纯调用 `t()` 后保存字符串，会冻结语言。为已有 Toast、Inspector 标题、持久显示的本地校验提示使用轻量 `UiText`：原始 string 表示动态原文；固定文案用 `{ id: MessageId, params?: MessageParams }` 表示。只在确实保存显示内容的 UI 结构使用，不让所有业务对象携带 i18n 类型。

Toast 和 Inspector host 在渲染时解析 UiText。Toast 的按钮标签也保留 ID，切换不重新启动消失计时、不替换回调；Inspector 的 entry 身份、绑定 ref、导航栈和 render closure 保持。当前展开的详情标题会更新，当前资源不重新加载。

错误继续复用 `TinySoulApiError` 的稳定 code/message/details 和各 feature 现有 kind；在捕获边界保留必要的结构化信息，在显示层生成摘要。未知错误显示原文；已知错误摘要不能把原始诊断覆盖掉。不要把 error 变成重新分类业务失败的第二套状态机，也不要给每个错误堆叠 fallback 链。

本地校验（非数字、重复名称、越界等）直接保存原因或 MessageRef 与必要参数，不保存已经翻译的句子。可用性判断、重试行为和表单定位仍取决于原来的稳定 kind/code/path。

现有 `rawText(value) => value` 不产生保护；逐一按真实来源分类后删除这个空包装。动态内容直接表达为 `{value}`；固定布尔/状态投影改用稳定 ID。动态内容保护由类型边界、数据流审查和代表性测试承担。

## 4. Settings catalog 与动态内容收尾

1. field 使用后端 path pattern；choice 使用父 descriptor 身份 + value；document 使用 documentSet + documentKind + path；collection/surface/group 使用 id。
2. `en-US` 使用当前后端 source，中文已登记身份投影，未知身份保留 source。查询和页面必须复用同一规则。
3. `editors/collection.tsx` 等真实显示处接入 collection 投影。document/group/surface 只在实际显示其 descriptor 的位置使用；没有消费者的独立 adapter 导出和只为它写的测试删除，不添加空 UI 来消费它。
4. translated descriptor 是临时显示副本，不写回 ConfigDraft/catalog/store；原对象继续用于路径、值域、默认值与约束。不能因为使用翻译过的 title 就改变编辑语义。
5. `ActionsPage` 的 action.tool.description、semantic/example 和名称继续原样显示；granted/supported/available/selection 等稳定事实的标签本地化。所有权限与模型用途判定仍由原 owner 提供。
6. 补齐 presets、模型对象编辑器、通用字段、Network/ACP/MCP 状态和本地校验。未知 model/provider/choice 不要求新增字典，也不因为缺翻译而被过滤。

## 8. 验证设计

### 8.1 契约按 owner 覆盖

| 验证 owner | 最小代表性检查 |
| --- | --- |
| i18n core | 两种语言分组/key/占位符一致，无合并覆盖；参数插值不改动态值；固定 ID 的读取 |
| catalog adapter | 测试自有小 descriptor：field/choice/document 完整身份、source fallback、原对象不变；有实际消费者的其它 descriptor 才覆盖 |
| Presentation controller | 将现有失败重试、reset 和迟到响应测试扩展到 locale；pending 立即预览，放弃重读、切换项目恢复正确语言 |
| App + 公共 UI | document lang 与有效 locale 一致；已打开 Toast/Inspector 更新但不重置生命周期 |
| Settings search | 查询保持不变切换 locale，命中身份相同且标题更新；编辑值/约束不被翻译 |
| 问答/输入 | mounted 切换后保留输入、选择和 comment，提交 payload 仍为原值 |
| 资源/诊断 | 文件正文、模型文本、action description 恰好等于某个固定文案时仍不替换；已知摘要与原始诊断都可见，未知值原样 |
| 正式页面 | 每个主要页面家族有代表性双语入口断言；不为每个按钮复制两套业务测试 |

优先扩展现有测试及 FakeEndpoint/reset helpers。主线用例继续验证行为；仅语言契约用少量确切文字断言。避免全页面长快照、全部文案逐项断言、双语言重复跑整个业务测试矩阵、锁定真实 assets/providers/action catalog 清单。

AST/文本盘点用于本次人工审计与遗漏定位，不新增“全仓库禁止中文/英文”的脆弱测试，不把所有字符串都误判为界面文案。只验证两份字典 key 一致不能证明两个语言的正文已经翻译，需要人工对照和 UI 检查。

### 8.2 交互验收

通过现有 FakeEndpoint/前端开发运行环境构造稳定场景，在 `zh-CN → en-US → zh-CN` 中检查：主导航、Settings 搜索、一个活动问答、一个已打开详情、一个资源编辑草稿和已显示错误。至少观察一个窄屏弹窗及 Trace/图表，确认文字没有遮挡关键按钮；不以截图像素快照固化布局。

用本地假数据即可，无需真实 provider、外网模型调用或个人配置。涉及滚动/焦点和 Tauri 本机能力的检查应分别记录自动化与实际手工观察结果，不能把 cargo check 说成桌面 UI 验收。

## 10. 可行性、风险与 AGENTS 核对

### 可行性

合理可行：共享配置/HTTP/store 链路已经存在；本轮没有新后端能力依赖。大部分工作是前端显示迁移，现有 TypeScript、Vitest、FakeEndpoint 足够验证。UiText 只解决当前 Toast/Inspector/本地提示已经存在的跨渲染需求；catalog adapter、状态值和 store 均优先复用，不建立新的执行或配置机制。

改动面较大，不能按“补几个遗漏词”估计。真实技术风险是缓存失效、已存文本、React 依赖、动态内容混入和英文布局；P1 先明确显示投影，后续按页面族迁移，可分别验证这些风险。

| 风险 | 处理 |
| --- | --- |
| 大量机械迁移误伤协议/用户内容 | 先分类再迁移，按数据流审查；请求 payload 与动态原文有代表性保护测试 |
| 把 t 放入模块常量或 memo 后冻结语言 | 静态表存 ID；纯函数显式 locale；mounted 切换测试 |
| 用重挂载刷新导致草稿/滚动/订阅重置 | 不使用 locale key；沿用输入/资源生命周期，检查网络调用次数 |
| 字典语义漂移或英文溢出 | 对照真实 owner/状态，按功能审阅文案并检查窄屏与弹窗 |
| 追求“零原文”制造复杂翻译体系 | 技术身份、动态正文和未知 descriptor/diagnostic 明确保留，不建设机器翻译或后端 locale negotiation |
| 再次提前归档 | 按模块、消费者、交互和门禁四类证据核对；两份计划都在真实完成后归档 |

### AGENTS 对照

- 单一 owner：语言事实仍归 PresentationService；临时显示结构只属前端，不成为业务事实。
- 模块边界：业务 typed 输入/输出、Action、LLM、Context、Reflection、Session、Search 与运行生命周期不改；前端只解释显示。
- 原始事实可解释：翻译摘要不取代 message/details、正文、ref 或执行状态；模型可见内容不跟随 UI locale 改写。
- 公共能力复用：一个 i18n 入口，纯翻译与 React/Settings adapter 分工清楚，既有 store/FakeEndpoint 继续使用。
- 无兼容负担：清除旧 hash ID、空包装和无消费者导出；不增加兼容别名。
- 测试服务语义：契约按 owner 覆盖，跨模块只验证代表性链路，不固定可编辑 assets 与正文。
- 文档忠实：撤销提前完成记录，基础链路通过与全局迁移完成分别记录。

没有阻塞性的设计决策：默认语言、共享存储、动态内容边界及显示层范围均沿用已确认意图。导出文件和可提交说明保持其内容语义，是对“界面语言不改变模型/业务内容”的具体落实。当前状态为准备实施；若实施发现需要改变请求内容、Endpoint 契约或 owner 权限，先提出冲突和影响再继续。
