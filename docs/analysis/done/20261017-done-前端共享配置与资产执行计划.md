日期：2026-10-17

## 1. 目标与已确认语义

将当前界面设置保存为项目共享 TOML，并为项目展示资产提供明确的读取入口。前端通过 Endpoint 读取和修改，Gateway 的 `PresentationService` 拥有展示配置语义，复用 Infra 的 TOML 和文件设施。

用户已确认：

- 服务绑定项目目录，独立于 Agent generation；保存展示配置无需 Agent 空闲，也不触发 generation 重建。
- 前端消费已经支持的配置类型；新增文件也须由对应配置类型解释。
- 不增加实时同步协议；请求失败沿既有前端请求错误流程反馈。
- 主题、字体可以作为真实消费者迁移到共享配置。
- 不考虑历史兼容；优先保证正常主线和必要结束边界，避免复杂恢复机制。

本计划采用以下具体设计，均可直接落实：

1. 目录命名为 `presentation`，与前端源码目录 `visualization/` 区分。
2. 七项现有界面设置整体迁移：主题、界面字体、代码字体、字号、行高、密度、减少动画。它们共同属于项目共享偏好。
3. 设置调整即时预览并自动保存；前端显示保存结果，失败允许重试或重新读取。它们不进入 Agent 配置草稿或运行方案。
4. 新配置文件通过受支持的配置文档保存操作创建。当前文档为 `interface`；缺失时读取默认值，首次保存物化 TOML。以后增加真实配置类型时，增加对应类型、路径声明和前端消费者。
5. 资产提供项目目录内的列表、读取、图片预览和下载。资产由项目文件或模板提供；本计划不增加上传、删除、重命名或通用文件编辑器。
6. 新连接、重新连接、进入界面设置页或手动刷新时读取共享值。同一项目的其它客户端在下次读取时看到修改，不承诺即时推送。

## 3. 目录与持久事实

### 3.1 模板及项目目录

新增模板文件：

```text
tinysoul/assets/common/presentation/
  README.md
  configs/
    interface.toml
```

项目初始化后的组织：

```text
<project>/
  tinysoul.toml
  configs/                         # Agent 配置
  presentation/
    README.md
    configs/
      interface.toml               # 项目共享界面设置
    assets/                        # 有实际资产时创建，可继续分目录
      images/<实际图片文件>
      fonts/<实际字体文件>
```

图中 assets 子目录表示组织方式，不为占位创建图片或字体文件。没有资产目录时列表为空，读取请求不创建目录。随包交付的实际展示资产以后放入 common/presentation/assets，由现有模板机制复制。

`presentation` 不进入 Agent 的 include、document_sets、运行方案、Home、Workspace 或按日归档。运行期间只读写项目副本。项目 reset 沿用当前“重建项目、仅保留 `.env`”的语义，presentation 同样恢复模板；本功能不新增另一套保留策略。

`presentation/README.md` 说明文件归属、配置保存方式、资产放置与读取，以及 reset 行为。主项目模板 README 增加该目录说明。

### 3.2 界面配置

`presentation/configs/interface.toml` 的根字段：

```toml
theme = "light"
font_sans = "inter"
font_mono = "jetbrains"
font_size = 14
line_height = 1.5
density = "comfortable"
reduced_motion = false
```

| 字段 | 类型 / 范围 | 消费者 |
| --- | --- | --- |
| `theme` | light / dark | App 根样式、NavRail、Markdown 图表 |
| `font_sans` | inter / system / serif | 全局界面字体 CSS 变量 |
| `font_mono` | jetbrains / system / cascadia | 代码与等宽字体 CSS 变量 |
| `font_size` | 整数，12–18 | 全局字号 |
| `line_height` | 有限数值，1.3–1.9 | 全局行高 |
| `density` | compact / comfortable / roomy | 控件间距和密度 |
| `reduced_motion` | boolean | CSS 与 MotionConfig |

稳定文档 ID 为 `interface`，由服务映射到固定相对路径。字段名沿用 Python/TOML 的 snake_case；这是字段命名，不是模型稳定 ID 的命名调整。前端 camelCase 与协议字段仅在一处转换。

配置默认值和校验归 `InterfaceSettings`。模板显式写出默认值，前端启动前的内存默认值只用于尚未连接时渲染；连接成功后以服务器返回值为准，不把启动默认值自动写回服务器。

字体配置保存的是现有字体选项，不保存 CSS、JavaScript、任意 URL 或字体二进制。现有 npm 字体资源继续随前端构建，系统字体仍取决于客户端环境。资产目录中的字体文件不会仅因存在就自动变成字体选项。

### 3.3 新增配置文件的语义

`interface` 是单一项目配置文档，不引入多个界面 profile、活动文件指针或继承关系。文档缺失时，GET 返回默认值并标明 `exists=false`；有效的首次 PATCH 创建目录和完整 TOML，后续同一 PATCH 修改已有文件。GET 永远不触发写入。

后续确有其它展示配置消费者时，在服务中声明其文档 ID、类型和相对路径（可含子目录），沿用相同读取、合并、校验、保存步骤。用户通过对应前端功能保存时即可创建物理 TOML。未知文档 ID 不接受；只放入一个任意 TOML 不会自动生成页面或消费语义。

本次只实现已消费的 `interface` 类型，使用直接类型分派即可；不建设动态类型注册、任意 JSON Schema 编辑器、扫描发现或插件加载框架。

## 4. 后端 owner 与生命周期

### 4.1 服务边界

在 `tinysoul/gateway/presentation.py` 增加 `PresentationService`，作为展示配置和资产的单一门面。同文件容纳当前紧密相关的 frozen dataclass、StrEnum 和服务异常；不要为单个消费者先拆出空壳 models/repository/registry 层。

服务由明确的 project_root 构造，持有解析后的 presentation 根目录和写锁。`InterfaceSettings` 在动态输入边界校验字段、枚举和范围；`InterfaceSettingsPatch` 明确表达提交字段，避免把无约束 dict 传播到内部。Endpoint 请求模型只处理传输形状，服务同时校验从磁盘读取的值。

通用 TOML 和文件能力继续归 Infra。使用 `ConfigFileToml` 读取并编辑文档，完整候选经 owner 校验后调用其原子 save。这里只有单文档提交，不需要叠加多文件 rollback、revision 或持久缓存。该序列化器会重新排版 TOML，不承诺保留注释，行为与现有结构化配置编辑一致。

### 4.2 装配与可用性

- `EndpointHost` 首次 bind 时从 `runtime.project_root` 构造服务，并显式注入 `EndpointEngine`；后续 generation bind/unbind 保留同一实例和项目绑定。
- `EndpointPresentationEngine` 仅进行协议映射和错误转换，直接消费该服务，不向 `EndpointEngineContext` 请求 Agent services/config。
- 不向 Agent、kernel、plugins、SDK generation lease 增加展示服务；不从不透明的 `project_identity` 反推目录。
- Agent 忙碌、等待用户或正在切换 generation，不影响已经存在的 Endpoint 提供展示接口。Endpoint 不存在或已停止时仍不可访问；本计划不改变冷启动失败时的服务器启动语义。
- 服务不启动 watcher、后台任务或网络客户端。Host 的既有 HTTP 停止流程收敛请求；单次短文件操作通过 `JoinedOperations` 完整 join 后传播取消，避免遗留写线程。无需额外的后台服务状态机。

### 4.3 保存流程

```text
PATCH 指定字段
  → 取得服务写锁
  → 读取当前项目 TOML（缺失则取类型默认值）
  → 合并本次声明字段
  → 校验完整 InterfaceSettings
  → 原子写入该项目文件
  → 返回完整已保存配置
```

只提交修改字段，后端每次从当前文件合并。两个客户端分别修改主题和字号时，后保存的请求保留前一个请求写入的其它字段；同一字段按最后成功写入的值生效。不建设冲突合并协议。所有展示配置都不调用 Agent apply/reload，也不改变 `can_reload`、pending activation 或运行方案。

### 4.4 失败边界

磁盘 TOML 解析、字段校验和文件 I/O 失败由 `PresentationService` 整理为有限的 `PresentationError`；Endpoint 映射为既有错误 envelope。请求形状错误继续使用 `request.invalid`；展示语义错误使用稳定 `presentation.*` code，分别表达无效配置、无效路径、未知文档/资产、超出读取上限及 I/O 失败。返回短消息，可附无效字段，不返回 traceback、绝对服务器路径或原始正文。

配置读取失败不以默认值伪装成功，更不写默认值覆盖文件。服务错误停留在 HTTP 请求边界，不加入 Runtime Trap，也不增加 Runtime bridge。

## 5. Endpoint 与资产读取

### 5.1 配置协议

以下路径使用当前 Endpoint 的 `/v2` 前缀，保持现有协议版本和统一鉴权。

| 操作 | 接口 | 行为 |
| --- | --- | --- |
| 读取支持的配置文档 | `GET /v2/presentation/configs/{document_id}` | 当前支持 interface，返回值、默认值和文件是否存在 |
| 保存支持的配置文档 | `PATCH /v2/presentation/configs/{document_id}` | 合并 changes；文件缺失则创建；返回完整保存结果 |
| 列出共享资产 | `GET /v2/presentation/assets` | 返回 assets 下真实文件的相对路径、媒体类型、字节数 |
| 读取共享资产 | `GET /v2/presentation/assets/content?path=...` | 返回该资产字节，受既有资源大小上限约束 |

配置响应示意：

```json
{
  "id": "interface",
  "path": "configs/interface.toml",
  "exists": true,
  "values": {
    "theme": "light",
    "font_sans": "inter",
    "font_mono": "jetbrains",
    "font_size": 14,
    "line_height": 1.5,
    "density": "comfortable",
    "reduced_motion": false
  },
  "defaults": {
    "theme": "light",
    "font_sans": "inter",
    "font_mono": "jetbrains",
    "font_size": 14,
    "line_height": 1.5,
    "density": "comfortable",
    "reduced_motion": false
  }
}
```

PATCH 示例为 `{"changes":{"theme":"dark"}}`。`path` 相对 presentation 根目录，只用于展示来源；写入目标由文档 ID 决定，不接收客户端物理文件路径。错误码、request/response model、OpenAPI、JSON Schema 及示例在实现接口时一并落地。

### 5.2 资产边界与实际消费者

资产路径相对 `<project>/presentation/assets`，允许子目录，拒绝绝对路径和向上逃逸；通过 Infra 的目录边界解析确认实际目标仍在根目录内。列表稳定排序、按请求读取真实目录，不另存 manifest 或数据库。缺失目录返回空列表。

读取复用 Endpoint 的 `max_resource_bytes` 上限，按上限进行有界读取；资产媒体类型由服务推导，未知类型作为二进制下载。不新增分片上传、转码、缩略图服务、缓存版本或 Range 协议。

界面设置页增加轻量“项目共享资产”折叠区，按需加载列表，显示文件名并支持图片预览、下载及刷新；空目录显示放置说明。预览使用前端支持的普通图片格式，其它文件下载；不执行 HTML/脚本。展示地址通过现有带 Bearer 的 transport 获取 Blob，再创建 Object URL；不把 token 放进 URL，也不直接使用未经鉴权的 img src 请求。

本次不定义 `presentation:` 模型引用、不复用 Workspace ref，不将项目展示文件混入 Agent 的资源检索、工作区或模型语境。

## 6. 前端状态与交互

### 6.1 单一界面偏好入口

保留 `uiPrefsStore.ts` 作为全部七项界面偏好的内存 owner，去掉 persist 包装，合入 theme。`appStore.ts` 删除 theme/setTheme/toggleTheme 及其持久化字段，保留自身导航、项目选择和 toast 等状态。

共享偏好的网络读写集中在 `features/settings/presentationController.ts`，组件只读 store 并提交变化。此 controller 管理一次读取/保存和已有连接 epoch，不拥有独立连接生命周期。不要使用已有聊天 `presentationStore`，也不要让 App、InterfacePage 和 NavRail 各自编写请求逻辑。

删除旧偏好 localStorage 的读取、merge 和写入逻辑，不导入、迁移或上传历史偏好。连接地址、token 等启动连接所需信息仍按当前客户端机制保存；当前导航标签等客户端状态也不变成共享配置。

### 6.2 连接、加载与生效

1. 尚未连接时使用轻量内存默认值渲染，显示共享设置需连接后编辑，不在离线期间积累稍后上传的修改。
2. `completeConnect` 后读取 interface，无需等待 `status.ready=true`。读取失败只影响界面设置状态，不把已成功的 Agent 连接改成失败。
3. 首次加载成功后统一应用 theme、CSS 变量及 MotionConfig；NavRail 与 Markdown 图表同时读取这一入口。
4. 成功重连或进入 InterfacePage 时刷新；页面提供手动刷新。保存进行中或有保存失败的待提交值时，普通刷新不覆盖本地修改，用户可明确选择重新读取。
5. 用现有连接 epoch 守住异步结果。断开或切换项目时清空展示文档状态和待提交值，恢复启动默认值；旧请求不能刷新新项目，也不能被重试到新项目。
6. 同一 Endpoint 的 generation/day 切换不清空共享偏好；它们属于项目，不属于 Turn 或 generation。

### 6.3 自动保存与反馈

沿用当前“调整即看到效果”的体验：枚举和开关在选择完成时提交；数字输入在 blur/Enter 确认有效数值后提交，输入中的空字符串等只是控件内部文本。

store 只保留服务器确认值、一份待保存字段 patch 和请求状态。界面显示值为确认值叠加待保存 patch。controller 同时最多执行一个保存请求；保存期间继续修改的字段合并为下一次 patch，成功响应不能覆盖较新的本地编辑。不维护提交历史、离线队列或自动重试链。

保存状态放在 InterfacePage 顶部，分别显示“正在保存”“已保存到项目”或“保存失败”。成功后采用服务返回的完整值；失败保留本次未保存选择，停止自动提交并给出“重试保存／重新读取”，同时沿现有 toast 提醒。NavRail 的主题切换使用同一 controller，也能反馈保存失败。

“恢复项目界面默认”将服务返回的七项 defaults 作为一次 patch 保存，不删除文件，也不恢复旧本地存储。读取失败时禁用保存和恢复默认，防止误把启动默认值当成已读取的项目配置。

该流程不接入 Settings 的 Agent draft、底部“应用配置”、运行方案或 pending activation 计数。界面页说明文字直接表达“保存在当前项目；本界面即时更新，其它客户端重新读取后更新”。

### 6.4 Blob 复用

从 `features/resources/blobUrl.ts` 中提取被两处真正共用的鉴权响应转 Blob、AbortController 和 Object URL 回收部分到 `hooks/useBlobObjectUrl.ts`。原 Workspace hook 保留自身 ref/day 适配；新增 presentation hook 只处理资产相对路径。连接变化、切换预览和组件卸载都撤销旧 Object URL。

不顺带重构整个资源浏览器，也不建立通用资产管理系统。
