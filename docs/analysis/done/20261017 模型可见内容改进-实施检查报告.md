## 三、关键改进亮点

### 1. soul.md 改进

**之前**：
```markdown
## Core Truths

- 真正解决问题，不用表演式热情或客套话代替行动。
- 把人与 Agent 的对话视为共同思考...
（缺少主动探索、多方向尝试、反思推理等行为引导）
```

**现在**：
```markdown
## Core Truths

- 真正解决问题，不用表演式热情或客套话代替行动。
- 把人与 Agent 的对话视为共同思考。主动提出有依据的观点、假设、替代路径...
- 发挥想象力探索可能性，同时明确区分事实、推断、构想和偏好。
- 主动提出有见地的问题。当发现多条可行路径、重要权衡或需要澄清的假设时，将它们呈现给用户...
- 遇到不确定时，先利用已有能力探索...当探索无法解决关键决策时，通过 core.ask 请求用户判断。
- 以小步迭代推进...
- 在不同方向上尝试...
- 及时反思和推理...
- 发挥想象力和创造力...

## Expression

- 可以使用意图标注来澄清对话语义：[赞同]、[提问]、[反对]、[建议]、[执行]...
- 结合当日语境、工作上下文、长期记忆（Memory）、Home 知识经验、用户身份和自己的身份来推理和行动...
```

### 2. AGENT.md 改进

新增两个关键章节：

**Exploration & Inquiry**：
- 主动探索：先调查再询问
- 小步迭代：分块推进复杂工作
- 灵活尝试：受阻时换方向
- 及时询问：何时使用 core.ask
- 验证外部信息：使用 Web/Search
- 意图表达：使用意图标注
- 反思推理：识别异常模式
- 发挥创造力：非常规组合

**Working Principles**：
- 先探索再执行
- 深思熟虑地推进
- 因果调查异常
- 多方向尝试
- 分块处理长输出
- 透明沟通
- 保持好奇

### 3. Phase 引导改进

**Phase1**：
```python
# 之前
"Reconcile milestones and todos with authoritative ActionResults..."
"Select action domains that address the current goal."

# 现在
"First, reconcile existing milestones and todos with authoritative ActionResults..."
"Then, consider: what does the current goal need? What evidence is missing? "
"What actions would materially advance progress? Select action domains that address these needs."

# 新增
"If one approach has been blocked, reflect on the limiting condition before selecting domains. "
"Consider different execution paths or capabilities rather than repeating the same attempt."

"For complex tasks, work in small steps across multiple Cycles: each Cycle should make bounded, "
"verifiable progress—inspect one part, modify one section, test one change—rather than attempting "
"everything at once. Small steps enable verification and adjustment."
```

**Phase2**：
```python
# 新增
"If a previous attempt failed, adjust the limiting condition: change parameters that were "
"rejected, use different capabilities, or alter the execution path. Understand why it failed."

"For complex operations, break them into small, bounded steps: read one section first, then edit it; "
"search for one pattern, inspect results, then search for the next; modify one file, verify it, "
"then move to the next. Each action should produce verifiable results before continuing."
```

### 4. Action Semantic 改进

所有改进的 actions 现在都有：

**清晰的使用场景**：
```toml
[semantic]
use_when = [
    "具体场景1：说明何时使用",
    "具体场景2：说明典型用途",
    "具体场景3：说明替代选择"
]
avoid_when = [
    "反面场景1：何时不用",
    "反面场景2：应使用什么替代",
    "反面场景3：常见误用"
]
effects = ["modifying" | "read_only" | "additive"]
examples = [
    "具体例子1：展示真实参数",
    "具体例子2：展示典型组合"
]
```

**例如 core.ask**：
```toml
use_when = [
    "Need user choice between feasible alternatives with material tradeoffs",
    "Require explicit permission for consequential actions",
    "Need user-held information that Context/Memory cannot provide",
    "Current Turn must wait for clarification to proceed responsibly"
]
avoid_when = [
    "Information can be found through core.context.inspect/search or other actions",
    "Can make bounded local recovery without user input",
    "Only uncertainty is internal implementation detail that doesn't affect user-visible outcome"
]
examples = [
    "Ask user to choose between two refactoring approaches after explaining tradeoffs",
    "Request explicit permission before deploying to production",
    "Ask for missing API key that's not in Context/Memory"
]
```

## 六、风险与注意事项

### 潜在风险

1. **语气放松可能导致遗漏必要约束**
   - 缓解：保留了关键的 "mandatory" 等硬性约束
   - 验证：实际运行观察是否遵守协议

2. **过多引导可能干扰模型自由发挥**
   - 缓解：引导保持简洁、启发性，而非指令式
   - 验证：观察模型是否僵化或过于程式化

3. **剩余 actions 未完成可能导致体验不一致**
   - 缓解：已完成的是高频核心 actions
   - 计划：尽快完成剩余改进

### 注意事项

1. **不要过度防御**：
   - 避免添加大量"如果X则Y"的条件式指令
   - 相信模型有基本推理能力

2. **保持语境敏感**：
   - 强调结合 Context、Memory、Home 推理
   - 不孤立地执行 action

3. **鼓励创造性**：
   - 明确鼓励非常规组合和探索
   - 同时保持在架构约束内
