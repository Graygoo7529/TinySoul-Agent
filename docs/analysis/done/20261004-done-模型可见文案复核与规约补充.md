## 发现与处理

- Web Action 会捕获 `WebProcessingError` 与 `WebProcessTimeout`，但异常内部 message 属于 owner 的执行诊断，不应自动成为模型文案；此前直接使用 `str(exc)` 让内部实现细节越过了 Action 边界。
- 已改为由 Web Action 按 failure reason 明确选择简短模型反馈。只有输入/配置约束、结果说明和执行语义进入 `tinysoul/prompts/plugins/capabilities/web.py`；Catalog 的具体 timeout 数值、worker/provider 诊断和原始异常 message 留在 owner 内部或结构化 frame data。
- 对现有候选字面量复核后，CLI 描述、SDK 服务提示、检索候选不变量、Session map 持久化错误等没有进入模型决策反馈，继续由原 owner 管理，没有扩大提取范围。
- 已在架构测试中约束 Web Action 不得直接暴露异常 message，并在 `AGENTS.md`、`docs/design/prompts.md`、`docs/design/capabilities/web.md` 和 `tinysoul/prompts/README.md` 补充模型文案的判断、编写、异常反馈和验证规约。
