# 前端测试环境稳定化执行计划

日期：2026-10-30

状态：done

## 目标与边界

在继续界面改进前，让测试各自承担清晰职责：Vitest 保护稳定业务逻辑和关键交互，真实后端 E2E 验证跨模块主线，浏览器专项验证真实 Motion/渲染，视觉截图只服务人工验收。

- 只修改 `visualization/test/e2e/`、指定的 Vitest 测试及本计划；不修改产品组件、后端业务实现或 Endpoint。
- 不通过放宽业务断言、跳过失败或伪造状态换取通过。测试暴露真实产品问题时，暂停该处并单独讨论。
- 不追求测试数量下降或覆盖率数字，只去除有明确 owner 的重复覆盖。
- 保留真实 Agent/owner/HTTP/WebSocket 的 E2E harness，只有模型输出脚本化。

## 改进点 1：运行边界与测试后端

状态：done

### 现状

`playwright.config.ts` 对所有浏览器测试启动完整 Agent，导致 codeblocks 和 trail-motion 被无关后端问题阻塞。测试 harness 仍保留 TEXT/JSON、`links/link/text` 等旧协议假设；启动器的 Python 回退和进程收尾也需适应当前 uv 环境。

### 修改范围与内容

- `playwright.config.ts`：只负责 codeblocks 与 trail-motion，不启动后端。
- 新增 `backend.config.ts`：负责 chat-flow 与 presentation，复用真实后端 global setup。
- `backend_server.py`：按当前契约返回 `TextAnswer`，使用 `refs`、`question/details`、`ref`。
- `backend.global.ts`：优先识别项目 `.venv`，日志使用 UTF-8，teardown 等待进程实际退出。
- `visual-review.config.ts` 保持独立人工验收入口。

### 预期效果

纯浏览器测试不再依赖 Agent；真实后端测试只在需要时启动，失败日志可读，运行目录与进程能够可靠回收。

## 改进点 2：chat-flow 聚焦真实主流程

状态：done

### 现状

当前脚本混合 Reflection、用户问答、Context tabs、模型 Context、Activity、动效几何和 Turn 入场，包含旧回执身份、旧 Home 引用、旧问答字段和重复 dialog 定位。流程长、维护成本高，也与 Vitest 重复。

### 修改范围与内容

- 用户主流程：连接 → 普通回答 → 提问/选择/comment → 只读问答与最终回答 → 刷新后 Session 恢复。
- Reflection 主流程：发起整理 → 回复问题 → 整理完成 → 不写入 User Session。
- 使用当前 `request_id`/`turn_id` 身份语义、共享问答 Dock、明确的 Inspector 容器和当前输入控件。
- 删除已有 Vitest 覆盖的 Context/模型/Activity 细节、重复 Turn 入场以及精确 CSS/动画帧断言；保留必要的步骤顺序和真实内容验证。

### 预期效果

E2E 只验证真实跨模块主线，不与面板单测重复，不再通过产品修改迎合旧脚本。

## 改进点 3：trail-motion 与 visual-review 稳定化

状态：done

### 现状

trail-motion 使用真实生产组件和几何断言，价值明确，但包含长固定等待与敏感毫秒阈值。visual-review 有 22 张截图、大量固定延时、通用 dialog 定位与旧问答输入控件。

### 修改范围与内容

- `trail-motion.pw.ts`
  - 在无后端的浏览器配置中运行真实 LiveStatus/CSS。
  - 用步骤和 DOM 状态等待替代长固定等待，保留几何容差，去除对机器耗时过度敏感的断言。
  - 保留新步骤置顶、底部裁切、旧 Gist 不残留、视口不回缩和积压释放验证。
- `visual-review.pw.ts`
  - 截图前等待页面真实内容和必要布局状态，不依赖大量 `waitForTimeout`。
  - 使用明确的 Drawer/Dialog 范围和当前问答控件；用 `test.step` 标记各页面阶段。
  - 保留代表性页面、暗色与窄屏截图以及非空文件检查，不建立像素门禁。

### 预期效果

Motion 测试聚焦真实动效；视觉巡检能稳定捕获目标页面，失败时能定位具体阶段，不把动画时序和截图字节数误当业务正确性。

## 改进点 4：Vitest 小范围去重与测试卫生

状态：done

### 修改范围与内容

- `models/pages.test.tsx`：移除与 `collectionDrafts.test.ts` 重复的 `moveItem` 纯函数用例。
- `draft/store.test.ts`：保留 Store 刷新、stale 解决和草稿接线，减少与 `draft/model.test.ts` 重复的纯 rebase 场景。
- `turnController.test.ts` 与 `ChatView.test.tsx`：Controller 保留身份、错误、重试和状态转换；ChatView 保留 DOM 不重建、气泡不重复、滚动与问答交互，仅合并实际重复的收敛场景。
- 清理触及测试中可明确修复的 React `act` 警告，不删除业务断言。

### 预期效果

同一契约由 owner 完整覆盖，跨层只保留代表性行为；降低后续界面修改时的测试维护成本。
