# GPT-5.6 模型接入执行计划

## 背景

TinySoul 已通过 OpenAI Responses adapter 支持文本、图像、JSON object、模型侧 function calling、加密 reasoning 回放和提示缓存。development profile 使用 `sublyx_proxy` 作为独立端点与凭据身份，并复用 `openai` adapter；standard profile 保留默认禁用的官方 OpenAI provider。

本次基于 `reference/openai-gpt-5.6-调用说明.md` 接入 `gpt-5.6-sol`、`gpt-5.6-terra` 和 `gpt-5.6-luna`，同时修复删除 `kimi_coding` provider 后遗留的配置与初始化测试断言。

## 执行项

- `done`：在两个初始化 profile 中注册三个独立 GPT-5.6 ModelSpec，使用真实 1,050,000 token 上下文窗口和现有 OpenAI provider options。
- `done`：按任务复杂度把 Sol、Terra、Luna 插入任务模型链，并保留 `gpt_5_5` 回退。
- `done`：修正 Kimi provider/model 的现行配置断言，补充 GPT-5.6 profile、能力和任务路由测试。
- `done`：把三个新模型纳入显式开启的真实 provider JSON/image/tool/reasoning smoke test。
- `done`：同步 LLM 设计文档并完成定向测试、全量测试和类型检查。

## 设计边界

- 不新增 provider adapter；代理 provider id 继续只表达端点与凭据。
- 不接入 Responses 内置工具、流式、Realtime、Batch 或严格 JSON Schema。
- 128,000 token 是供应商输出上限，不写入模型级 request override；各任务继续拥有自己的生成预算。
- 272K token 以上的计费变化不伪装为技术上下文窗口，成本控制不混入本次模型接入。

## 验证结果

- GPT-5.6 配置、项目初始化和真实 provider 测试矩阵定向验证通过；真实 provider 用例因未显式开启联网测试而跳过。
- 完整 `tests` 测试套件通过，仅保留既有 Starlette/httpx 弃用告警。
- 使用 TinySoul Conda 解释器执行 `ty check`，类型检查通过。
