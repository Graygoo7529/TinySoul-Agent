## 目标与原则

- 目录层次表达职责：chat/trace/runtime 三个过平区域按文件内已有职责分层；
- 超长文件沿**已有内聚边界**切分，不新造抽象、不预留无消费者的接口；

- 纯移动用 `git mv` 保留历史；import 只改相对前缀；每个改进点独立可验收。

## 改进点 1：死代码与冗余导出清理（P2）

### 现有情况

启发式扫描发现 209 个未被外部 import 的导出，其中绝大多数是组件 props/状态类型（隐式消费，惯例保留）或仅测试引用（保留）。逐项核实出的真死代码约 12 项。

### 修改范围与内容

- **删除（零引用）**：`utils/format.ts` 的 `formatNumber`、`formatTime`、`shorten`；`components/trace/semantic.tsx` 的 `actionIcon`、`domainTone`、`domainHueClasses`、`linkNamespace`、`ActionStatusBadge`、`TurnStatusBadge`；
- **取消导出（仅自身文件内部使用）**：`utils/format.ts` 的 `nowSeconds`；`trace/entries.tsx` 的 `pushModelCall`、`pushTurnProcess`；`trace/eventWindow.ts` 的 `currentEventHead`；`api/v2/transport.ts` 的 `V2_PATH_PREFIX`；`api/v2/errors.ts` 的 `apiErrorDetail`；`trace/resultViews.tsx` 的 `GenericView`；
- 每项删除/取消后跑门禁；若有隐藏引用则该处改用真实引用，不保留兼容别名。

### 预期效果

导出表面积收缩到真实消费者；后续读者不会被无人使用的导出误导。无界面变化。

## 改进点 2：命名冲突修正（P4）
