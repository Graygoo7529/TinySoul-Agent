- 日期：2026-10-28。

## 1. 已确认的范围与设计约束

1. 新增可选 `context.max_window_tokens`；development/standard 模板都设为 `262144`，即 256 × 1024 tokens。
2. 每个模型的 `context_window_tokens` 按官方规格填写，允许 `1050000`、`1000000` 等十进制值，不做统一倍数取整。
3. 实际使用 `min(模型窗口, 全局窗口上限)`；未设置全局上限时，使用模型窗口。
4. 保留“模型候选数组＋模型顶层选定值”，模型升级通过当前 family TOML、provider bindings 和 adapter options 表达。
5. 新增 `gpt-astra`，升级 GPT Sol/Terra/Luna、Kimi 主模型、GLM、MiniMax。内部稳定 ID 不随版本变化。
6. `kimi-coding-latest` 保留 K2.7 Code / Highspeed，继续承担较低成本的编码模型角色；不替换为旗舰 highspeed。
7. provider 沿现有命名方式修改远端模型 ID；本轮不做代理目录、权限或全端点可用性巡检。
8. 前端可以修改，复用现有设置草稿、字段编辑器、候选选项、family 列表和运行方案比较组件。
9. 正常配置、调用、压缩和结束路径优先；不引入新容量状态机、自动模型迁移平台、重复配置或兼容别名。
10. 本轮文件交付范围是仓库模板、代码、测试和文档；已初始化项目的个人 TOML 不由模板升级隐式覆盖。

## 3. 全局窗口与有效窗口

### 3.1 字段语义

```toml
[context]
max_window_tokens = 262144
compression_trigger_ratio = 0.8
compression_target_ratio = 0.5
```

- `max_window_tokens` 是本次完整 LLM 请求的运行窗口上限，计入输入估算、工具/schema、推理与工具回放、图片估算、结构开销和预留输出。
- 配置缺失时，owner 默认值为 `None`，使用模型自身窗口。TOML 不写 null；清空配置通过既有 delete mutation 表达。
- 已设置时必须是正整数；bool、0、负数、小数和字符串按既有 ConfigError 流程拒绝。
- 模板明确写入 256K；Python 类型默认不写死 256K，避免“删除字段仍然被隐藏默认值限制”。
- 覆盖范围是 Agent 装配的共享 LLMTaskRunner，包括 User、Reflection 和 Action 内部复用此 runner 的 LLM Task。Embedding、决策模型和执行进程不属于这个窗口策略。
- 自行注入的 runner 仍由宿主装配；不从 Agent 反向修改注入对象私有配置。

### 3.2 计算与所有权

```text
model_window = ModelSpec.context_window_tokens
effective_window = model_window                     # 未设置全局上限
effective_window = min(model_window, max_window)    # 设置了全局上限

used = estimated_input_tokens + reserved_output_tokens
trigger = int(effective_window * compression_trigger_ratio)
target = int(effective_window * compression_target_ratio)
```

占用严格大于 trigger 才进入现有容量流程；恰好等于时允许调用。模型较小时保持其真实限制，不能被全局上限扩容。切换候选模型时重新计算有效窗口，不以首选模型窗口代表整条模型链。

Context 配置 owner 解释字段；Agent composition 显式传递基础值；LLM 的 `ModelContextPolicy` 统一计算有效窗口并估算请求；Kernel 消费容量事实进行本轮投影回收。LLM 不导入 Context 配置类型，也不自行读取 TOML。

`ContextEngine` 不新增第二份 token 容量策略或主动截断消息的逻辑。它继续负责构造、既有压力恢复、Inspect 展示保护和段生命周期；无需为这个仅供 LLM 检查消费的数值添加一组无消费者的 Engine builder/getter。

### 3.3 类型和诊断命名

- `ModelSpec.context_window_tokens` 和 `CurrentModelCapabilities.context_window_tokens` 继续表示模型标称窗口，不覆盖为运行预算。
- `ModelContextUsage` 的窗口字段改为 `effective_window_tokens`；其 trigger 计算和容量 payload 使用同名字段。
- `kernel/loop/pressure.py` 的回收计算读取 `effective_window_tokens`，更新相关测试和说明。直接替换原诊断字段，不同时保留两套含义相近的 key。
- 不为诊断新增持久状态；模型标称值和全局配置仍可通过已有配置查询取得。
- provider 明确返回 context-limit 时，继续通过同一个容量策略形成使用事实，保留 `provider_reported_limit`，不新增失败种类或恢复分支。

示例：GPT 标称 1050000、全局 262144 时，触发水位为 209715，压缩目标为 131072。若预留输出是 32768，它也占用该预算，不能把 209715 全部理解为可装入的输入 token。

当前估算器使用 UTF-8 字节等作保守估算，本轮不更换 tokenizer、不增加在线计数请求，也不把它描述为供应商精确计费 token。

### 3.4 失败与结束行为

保持现有三层失败边界：配置问题在 owner 解析处为 ConfigError；LLM 直接构造参数不合法使用 LLMContractError；容量不足沿当前 ModelContextOverflowPolicy 返回局部结果或经 Runtime bridge 请求恢复/结束。

`REQUEST_RECOVERY`、`RETURN_FAILURE` 和其它现有策略的职责不变。必要回收由现有 User/Reflection 压力恢复完成；无进展时沿现有结束边界收敛，不增加忽略上限、自动扩大窗口或逐层重试。

### 4.3 GPT 配置与 adapter

- 四个模型均使用 `adapter = "gpt"`，继续复用 OpenAI Responses。
- 保持图片输入、JSON、工具调用、推理和缓存等现有 GPT 能力集合；Astra 使用同一集合。
- 保持 `native_replay = "encrypted"`、`prompt_cache_mode = "implicit"`、`prompt_cache_ttl = "30m"`、`prompt_cache_boundaries = ["background", "trace"]`、`verbosity = "medium"`、`reasoning_summary = "auto"`。
- `reasoning_context`、`store` 继续省略，沿用现有本地回放方式和供应商默认。
- Astra/Sol 不支持 none；模型候选去除 none，并设置 `sampling = "omit"`、`choices.sampling = ["omit"]`。
- Terra/Luna 保留 none 候选；只有显式选择 none 且 sampling 没有设为 omit 时，才允许传递 temperature/top_p。
- 修正 `GptAdapter.normalize_sampling`：未填写思考强度代表远端默认推理，不等于 none；除显式 none 外移除 temperature/top_p。此规则只在 GPT 专用 adapter 中处理，不推给通用 Responses adapter 或其它 family。
- 不增加 `gpt6` adapter、按型号字符串分支或新 API 模式。已有 SDK 足以表达上述请求字段，不因配置升级强制更新依赖。
- 任务输出预算、model request overrides 与模型窗口继续分别表达生成预算、请求覆盖和容量；不把输出预算自动提升到官方最大值。

### 4.4 Kimi 配置

```toml
[llm.models.kimi-latest]
reasoning_effort = "max"
# 其余模型字段见目标表

[llm.models.kimi-latest.adapter_options]
variant = "k3"
choices.reasoning_effort = ["low", "high", "max"]
prompt_cache_mode = "implicit"
prompt_cache_ttl = "5m"
```

K3.1 官方声明与 K3 参数约束相同，继续使用 K3 分支：始终保留 content 回放、移除固定采样参数、不发送 K2 thinking 配置。已有 Turn PromptCache.key 和缓存请求映射继续复用。

Kimi coding 保持现有模型、K2 variant、thinking enabled、content 回放及其候选约束，不增加它不支持的 reasoning_effort。它在目录中继续可见，不能因版本较旧而违背已确认的成本定位。

本轮不引入动态候选发现或按调用自动改思考强度。K3 改变强度会影响前缀缓存命中，模型级选定值在同一运行世代中保持稳定；配置变更沿既有 apply/reload 生效。

### 4.5 GLM / MiniMax 配置

- GLM 5.3 使用现有 `glm` adapter，text/JSON/tools 能力保持；`thinking = "enabled"`，`choices.thinking = ["enabled"]`，增加三档候选及顶层 high。`native_replay = "content"` 继续驱动既有 clear_thinking 映射，不另设重复配置。
- MiniMax M3.1 Flash 使用现有 `minimax` adapter，保留图片和工具能力；`thinking = "adaptive"`，`choices.thinking = ["adaptive"]`，增加五档候选及顶层 high。
- MiniMax 固定 reasoning_split=true、采样省略和 content 回放继续复用；已有基础请求使用 max_completion_tokens，符合新文档。
- 不把“模型不允许关闭思考”扩大为整个 API mode 或 adapter 一律禁止；限制由当前模型的 choices 表达。
- 不仅因服务端存在自动缓存，就补入可能使当前 adapter 发送不支持参数的 prompt_cache capability；不在本轮扩展 MiniMax JSON 或工具选择能力。

## 5. 配置、前端与运行方案

### 5.1 配置 Endpoint

- 在现有 Context budget 分组登记 `context.max_window_tokens`：整数、tokens 单位，说明“未设置使用模型窗口；配置上限与模型窗口取较小值”。
- `GET /v2/config/catalog`、saved/active 配置查询、PATCH/apply/reload 共用既有设施，不新增端点。
- 设置/清空都进入普通草稿；后端解析候选，保存与激活边界不变。待激活状态仍由全局配置状态页面解释。
- `llm.models.*.context_window_tokens` 的字段说明明确为模型标称窗口，区别于统一运行上限。

### 5.2 Context 设置页

在现有预算区显示两个并列但单位明确的项目：

```text
上下文预算
  全局窗口上限  [262144] tokens
  留空使用模型窗口；实际窗口取模型窗口和此上限的较小值。
  窗口包含输入、工具、回放及预留输出，压缩按下方比例执行。

  图片字节预算  [既有数值] bytes
```

复用 `FieldSection` / `SettingsField` / `DraftNumber`；正整数输入不人为设置最大值，不增加范围不明的 slider。清空产生 delete 草稿，环境/CLI 等高优先级来源仍按原规则只读或覆盖，不能声称删除某一来源必然删除其它来源的值。

现有 ContextUsageCard 统计字符和图片字节，不把它伪装成 provider token 计数或添加一套前端实时容量估算器。

模型页仍显示精确的标称窗口，补充全局上限说明和前往 Context 配置的链接即可；不增加持久化的“有效窗口”字段，也不在前端重新维护容量决策。

新增 Astra 和更新后的模型自动进入已有 family 胶囊、搜索及模型选择器。候选档位仍从后端 adapter catalog + 模型 choices 取得，禁止在前端写死 GPT/Kimi 新版本列表。

### 5.3 运行方案声明语义

`PresetDefinition` 当前用字段全集比较验证 values；直接扩充 `_BUDGETS` 会使未声明新字段的方案失效，也不符合“只应用声明项”的目标。应同步调整：

1. `_BUDGETS` 登记 `context.max_window_tokens`，作为新捕获方案可包含的预算。
2. 核心任务/路由组仍按当前结构必需；预算字段只允许已登记的 key，但不强制每份方案包含完整预算全集。
3. `include_budgets = false` 时禁止预算字段；true 时允许声明全部或部分预算。
4. 新建/重新捕获且选择包含预算时，正常捕获该字段；未配置时沿现有 null 表达“恢复 owner 默认”。
5. 未声明该字段：应用时保持当前值。显式声明 null：按现有 replacement 流程删除该配置声明。两者不可混同。
6. `changes()`、`replacements()` 已按声明遍历，继续复用，不补齐缺失项、不另建迁移器或修改 schema version。
7. 前端 `budgetSummary`、`PresetContent`、`PresetChanges` 已可呈现新字段；只需字段翻译及代表性测试，不复制预算白名单。

这项改动落实统一声明语义，不按“旧版本方案”增加兼容分支。

### 11.3 架构与完成边界

- 配置字段由 Context owner 解释，LLM 接收显式基础值；没有反向依赖或配置隐式读取。

- 配置错误使用 ConfigError，直接 LLM 契约错误使用 LLMContractError；局部失败、Runtime 恢复和结束边界复用原实现，没有新增失败类型或恢复状态机。
- 模型升级是原 family TOML 的普通修改，Astra 不自动改写任务链；Provider 定义、key/header、代理配置和其它 family 未扩展。
- 前端继续使用 Endpoint 投影、共享草稿与 apply/reload；运行方案只更新声明项，未增加 active/saved 双重方案逻辑。
- 正常主线与必要结束边界已覆盖；测试没有把可编辑模型版本或目录数量固化为长期契约。计划全部条目、实现与文档已核对，按 AGENTS.md 归档完成。
