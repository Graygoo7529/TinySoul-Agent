# 本地测试失败修复与耗时收敛执行计划

状态：`done`。已按 AGENTS.md 核对实现、测试范围与本地门禁；保留历史偶发失败的观测边界，不将一次通过表述为消除了所有主机抖动。

## 目标与边界

重新核对 AGENTS.md 的失败分层、Context prepare/install 和测试 owner 原则，修复网络配置验收中暴露的真实缺陷，缩减与被测契约无关的装配成本。保留 Fast/Full 的现有选择语义，不通过跳过失败、扩大业务超时或吞掉异常换取通过。

## 已确认的问题

1. Context 的 Segment 打开被取消后，Turn 收尾仍会消费固定 Signal 批次。`consume_signal_batch` 只在已打开 Segment 的分支赋值 `ordered`，随后无条件读取，产生 `UnboundLocalError`；这是实际实现缺陷。
2. SDK 测试仅替换 LLM，却为多数场景加载完整 Home 技能资产并启动文件 watcher。采样中 Home 查询反复协调目录、读取摘要，与排队、回复、预算等被测契约无关；整文件一次诊断运行约 140 秒，并出现等待首次 LLM 调用超时。
3. HTTP/SDK 贯通测试使用 1/20 两种 Cycle 预算重复执行完整长流程。普通提问/回复已有独立 SDK 测试，贯通测试保留预算暂停及恢复这一条代表路径即可。
4. Windows 事件循环关闭也有可测开销。异步装配测试中使用无上下文管理的同步 TestClient，会让每次请求另建事件循环。HTTP 用例改为既有 AsyncClient/ASGITransport 写法，显式管理客户端并与 Agent 共用当前循环；不共享活动 Agent、不绕过资源释放或改变默认事件循环。
5. 首次 Full 的 Endpoint 贯通测试出现 `workspace.io_failed`，单独运行通过。仅有失败摘要尚不足以确定底层原因；后续验证临时记录原始异常链，不在产品失败 payload 中加入 traceback。

## 验证与效果

- 修改前 SDK 单文件诊断：36 passed、1 failed，139.93 秒；失败为 watcher 重载测试等待首次模型调用超时。更早 Full 中同类超时也出现于长 HTTP 流程。
- 修改后 Context + SDK 聚焦：65 passed，92.03 秒。范围更大且已包含收尾回归；仅删去一个重复参数分支。时间为当前主机观测，不承诺固定加速比例。
- Endpoint 契约聚焦：22 passed，12.36 秒；真实 owner 贯通用例 8.90 秒（此前孤立运行约 13 秒）。
- HTTP 装配三个用例聚焦通过；类型检查通过。三项 HTTP 用例的业务断言均保留。
- Fast：1373 passed，15 deselected，309.92 秒。该次全量运行尚使用修改前已导入的同步 HTTP 装配测试，异步版本另有聚焦验证；不据此宣称全套提速。
- Full：1378 passed，10 deselected，343.23 秒；覆盖最终异步 HTTP 用例及完整非 external 门禁。最终 typecheck 通过。
- 此前 Endpoint 的一次 `workspace.io_failed` 在聚焦、Fast、Full 中均未复现；临时诊断只观测到测试主动构造的失败，没有据此修改 Workspace 业务恢复或重试语义。

### 耗时结论

SDK 聚焦的资产负担减少，但整套 Full 仍约 5 分 43 秒，未出现明显整体提速。最终最慢用例为 Action 配置多次激活（22.14 秒）、wheel 构建及安装初始化（18.17 秒）、完整插件组合及 restart（11.59 秒）；其余还有真实 CLI、进程和世代重载的必要成本。异步 HTTP 改造保证同一事件循环及客户端明确关闭，不把该调整夸大为已解决装配性能。

本轮没有修改 suite 选择规则、扩大超时、降低业务断言或新增 skip。原有普通提问/回复由 SDK owner 用例保留，HTTP 贯通保留预算路径，watcher 仅在实际观察/重载/启动失败场景开启；配置/资产生成与发布包仍由原有 generation/release 契约验证。缩减目标是避免每条 SDK 测试重复加载可编辑 Home 内容，不减少真实 owner 的生命周期覆盖。

网络设置功能与本次测试修复独立说明；OpenCode DeepSeek prompt-cache 的远端 503 不属于本地测试通过即可关闭的验收项。
