### 最慢配置集成测试的剖析

`test_endpoint_action_activation_inherits_and_restores_runtime_policy` 的 Full 测试总时间为 18.19 秒，其中 call 约 17.93 秒。它把非法配置、路由保存、retrieval 配置、domain/action 可见性继承、恢复默认与多次 reload 放在一条完整 HTTP/Agent 流程中。

对它单独运行 cProfile，测试仍通过，但插桩后的 pytest 时间增至 40.24 秒。剖析用于定位调用量和热点，不能用这个时间与未插桩基线直接比较。

生产热点位于 `tinysoul/infra/config/descriptors/models.py` 和 `tinysoul/infra/config/{editing/controller,sources/project}.py`：`ConfigCatalog.match` 对每次查询线性扫描所有字段，并反复拆分路径；配置保存、状态读取和 reload 又多次加载与投影整个项目。

建议分开实施并比较收益：

1. 测试调整：把继承/覆盖/删除后的回退、retrieval 参数和非法值校验交给各自 owner 的小数据测试；真实 HTTP→配置保存→reload→新 generation 保留代表性链路。
2. 生产优化：针对不可变 catalog 预解析 pattern、建立候选索引或有界实例缓存；在一次配置操作内复用已取得的解析结果和路径身份。具体方案另行检查调用边界。
3. 保持配置可见性：不能为了加速删掉必要校验，或引入会漏读外部编辑的全局文件缓存。当前 `_projection` 已复用一次 `effective_values`，不把已有优化重复列为新改动。

## 3. 测试职责与组织

继续遵守 `tests/<module>/test_<切面>.py`，按 owner 放置。用少量 marker 区分执行成本，不再平行建立另一套按测试层级镜像的目录树。

| 建议套件 | 职责 |
| --- | --- |
| Fast | owner 的业务逻辑、类型协议、轻量跨模块边界；不依赖完整项目初始化、真实外部服务或反复启动 Agent |
| Integration | 真实 Agent/generation、文件 owner、Endpoint、受控进程与本机协议之间的代表性协作 |
| Packaging | 正式模板、资源分发、初始化与 wheel 安装验收；可合并当前 Generation/release 的用户入口 |
| External | 明确开启的真实模型、公网服务、额外可执行工具验收 |
| Full | Fast + Integration + Packaging，仍是完整本地门禁 |

调查时这些套件尚未实现；实施后已同步 `scripts`、pytest 配置、README 和 AGENTS.md。把测试移出 Fast 只改善反馈速度，不能冒充 Full 已提速；Full 仍需靠减少重复装配、简化测试和实际性能优化改善。

优先按语义拆分大文件：

- `agent/test_sdk.py`：请求/输入与等待、generation/service lease、日切与 Reflection 协作、真实执行与来源生命周期。
- `agent/composition/test_builder.py`：插件装配契约、配置激活、Endpoint 挂载；HTTP 协议断言归 gateway，配置求值归 infra/kernel owner。
- `llm/adapter/test_provider_openai_sdk.py`：消息与工具映射、流式事件、reasoning/replay 和失败分类。该文件约 3144 行，但 82 项仅约 0.24 秒；拆分目的是可读性，不是速度。
- `kernel/loop/phases/test_phases.py`、`llm/execution/test_task_runner.py` 等按真实协议切面整理，避免把所有 fixture、fake 和测试继续堆在同一文件。

不把一个长测试机械拆成多个各自启动完整 Agent 的测试，这可能更慢。先识别每段断言的 owner，再决定最小装配范围。

### 环境与辅助对象复用

已有 `tests/support/project.py` 缓存正式模板，应该保留这个能力，但只让资源验收与必要真实装配消费正式模板。普通 parser/policy 测试直接构造小型测试配置；Agent 集成使用测试自有的最小模型/provider 配置和 Home，仍通过正式 builder 装配规定的插件。

不能假设标准 Agent 支持任意裁剪必需插件，也不应复制一套测试专用 Agent 调度器。测试工厂只提供显式输入、少量关闭无关来源的设置，以及可靠的 start/close 生命周期。

可以共享只读 fixture、不可变 catalog 和模板；活的 Agent、可变 owner、Job、客户端和当前 Turn 维持测试级生命周期，避免通过扩大 fixture scope 引入顺序依赖。

具体整理点：

- 合并确实重复的脚本化 FakeLLM、结果构造、观察记录和启动/关闭辅助逻辑，保持小接口，不设计通用测试 DSL。
- `tests/action_helpers.py::builtin_catalog` 目前读取正式 retrieval 配置，导入多个插件，并自行补装 retrieval schema。这是测试侧重复生产装配；kernel 单元测试改用自有小 catalog，正式装配一致性在少数集成测试覆盖。
- 将公共 Action 辅助放入现有 `tests/support`；`local_tmp` 只是 `tmp_path` 别名，可随相关测试整理删除。
- 统一有界等待与失败诊断，优先等待明确的 Event、完成结果或进程 ready 消息，避免各文件复制轮询代码。
- 暂不先引入并行执行。当前模板缓存的“检查存在再生成”会在共享 run root 的 worker 间竞争；隔离实例目录、模板和工件后再评估是否值得增加并行依赖。

## 4. 环境可迁移与稳定性

### 已有基础与实际缺口

当前默认工件已经落在仓库 `.local-test/runs/<uuid>`，且 `.gitignore` 已忽略，不需要再造临时目录体系。本次静态检查找到的少量绝对盘符字面量用于路径拒绝/脱敏输入，不是实际工件落盘地址，不应把它们都当成环境硬编码。

主要缺口如下：

| 位置/现象 | 影响 | 建议 |
| --- | --- | --- |
| PowerShell 入口与 conftest 各自设置运行环境 | 标准入口与直接 pytest 的 cache/清理行为不同；非 Windows 使用不便 | 以 Python 实现统一运行入口；PowerShell 仅选择解释器并转交；环境准备逻辑只有一处实现 |
| 只隔离 `LOCALAPPDATA`，未设置 `TINYSOUL_INSTANCE_DIR` | Linux/macOS 或继承了该 override 时，实例记录可能落在用户目录 | 每次运行显式把实例目录指向 run root；子进程继承；环境路径测试自行覆盖所需变量 |
| 部分 `ConfigEnvironment.from_project_root` 调用使用宿主环境 | 代理、凭据和 TinySoul 配置变量可能改变普通测试 | 普通配置测试显式 `env={}` 或测试自有映射；网络继承测试显式构造场景；保留 PATH/SystemRoot 等运行必需环境 |
| `anyio_mode=auto`，同时安装 pytest-asyncio，没有固定 backend | 依赖实际安装的异步插件/backend 集合 | 建议保留已使用的 AnyIO，显式选择 asyncio，直接声明测试依赖；核对后移除未使用的 pytest-asyncio |
| 本机工具探测后 skip | 换机器可能少测一条路径而仍显示通过 | Python 内可替代的适配逻辑在本地验证；真实可执行工具进入明确的 External 验收 |
| 业务输出来自系统日期/时区、平台和编码 | 机器配置可能改变结果 | 日切测试注入统一时钟；显式 UTF-8；保留确有平台语义的用例和 marker，不复制平台差异为一般业务假设 |

本机 AnyIO 可用 backend 只有 asyncio；未固定 backend 的风险是其他机器安装额外 backend 后收集集合变化。TinySoul 根调度本来就是 asyncio，不需要为无实际产品需求的 backend 做全套参数化。

拟议运行目录继续使用 `.local-test`，分别保存本次 pytest/temp/instances，以及小型日志和时间报告。成功后清理大体积临时资源、保留最近报告；失败保留本次工件并打印路径。测试输入与持久化试验全部位于各自 `tmp_path` 下。标准入口与直接 pytest 应共用配置，并避免隐式遗留大量 `direct-*` 目录。

缓存应只保存可重建信息，与可变测试环境分开；如保留 `--lf` 信息，不把实例状态、文件 owner 或上一轮项目目录一起复用。已有 `ArtifactRoot` 可作为显式诊断选项继续保留，不能成为特定机器才能通过的默认前提。

### 时序、进程与本机网络

- 多处固定次数轮询和很短的 deadline 可改为显式握手与单个有界 watchdog；测试逻辑通过先后事件表达，而不是“某台机器应在 10ms 内完成”。`asyncio.sleep(0)` 有时表达主动让出执行权，不能一概删除。
- 超时与取消仍需少量真实时限测试，但批次策略、join 顺序等可用受控事件验证。子进程脚本的 `sleep(30)` 常用于等待被终止，不代表测试真耗时 30 秒。
- `expand/test_engine.py` 的 HTTP fixture 先占用临时端口、关闭 socket，再启动子进程抢回该端口，并通过 discover 重试等待就绪。存在释放到重绑的竞争；优先由服务绑定端口 0 后报告端口与 ready，或在接口支持时传递已绑定 socket。
- `infra/test_network.py` 的参数化路由测试多次启动真实 HTTP server。保留真实传输代表路径，域名/IP/端口匹配组合交给确定性测试；缩短 fixture 自身停服轮询，显式 join。当前数据不能证明慢项一定由 DNS/IPv6 引起，不先对系统网络做特殊配置。
- 本地 HTTP 测试应显式控制代理继承；测试进程关闭时必须 join 自己创建的资源，而不是单纯放大 sleep。

### 安装验收的边界

现有 wheel 测试使用当前解释器的 `pip --target --no-deps`，能验证分发文件和从安装目录启动，但不等于从空环境解析安装全部依赖。它还隐式要求解释器提供 pip。

“新机器只安装声明的 Python 环境即可测试”需要另有干净环境验收，明确测试/build 依赖和时区数据来源；不能继续依靠 Conda 恰好提供 pip、tzdata 或其他工具。该工作可与后续 uv 评估衔接，但不必把联网安装加入每次 Fast/Full。准备好环境或本地 wheel 缓存后再运行门禁即可。

对于数值、布尔、空值等校验，按实际可区分的分支选代表值；不会因为它们是失败测试就全部删除。当前这些测试大多很快，清理收益主要是更清楚地表达语义。

### assets 与 prompts 的目标形态

正式 assets 只在集中资源契约中检查：文件能够打包/初始化；TOML 和 Markdown 元数据可解析；声明的引用、任务链、模型/provider、executor、model-use 和 Skill mount 能在相应 owner 规则下解释。新增一个合法配置、增加一个模型或调整 prose，不应要求同步手写列表。

通用规则测试使用测试拥有的数据。例如两个虚构 provider、一个任务链和最小 domain/action，验证继承、引用、选择与失败归类。adapter 接收测试传入的模型 ID 并原样发给 provider，是有效的精确值断言，不属于固化正式模型配置。

prompts 重点验证消费者组装：role、TaskPrompt 局部性、Skill 来源、动态值、引用正文、失败反馈去向，以及结构化输出约束。不要全文快照、固定句子数、固定中文片段或默认模型名称断言。

现有 `test_phase_prompt_content_preserves_scenario_and_skill_boundaries`、`test_analysis_prompt_keeps_dynamic_limits_and_reference_bodies` 已通过替换为含特殊字符的哨兵文案，检查内容装配与动态值，应保留这一方向。当前 prompts 并非整体都存在字面量测试问题。

标准项目无凭据也能创建、启动并报告模型不可用，是可保留的产品行为；它不需要指定某个 provider 名称或模型清单。若要改变这个产品行为，应明确讨论，不能在资源清理中无意删除其覆盖。

### 需要结合生产代码决定的清理

1. **历史数据兼容**：Home overlay 存在 schema 1→2 迁移测试，也有实际生产迁移分支；Archive 存在旧 Home transition、无日期 workspace 的历史路径。用户已明确不需要兼容，建议同步删除旧分支与专项测试。只删测试会把无消费者的复杂性留在实现中；当前日切恢复、归档不丢内容的行为要另行保留。
2. **故障注入矩阵**：初始化/reset、Home overlay、Archive 中的“提交失败后恢复再失败”等组合值得收缩。建议保留一个提交未完成的恢复验证、一个必要收尾失败的结果验证；删掉没有额外可观察契约的排列。涉及替换用户文件/归档内容的用例先映射实际保证，再决定删除。
3. **源码风格守卫**：扫描整个 infra.config 禁止裸 ValueError/TypeError 是编码规约而非业务主线测试。建议以 owner 边界失败契约和 review 为主，保留真正有价值的导入方向检查；若仍希望自动执行风格约束，可单独轻量检查，不继续扩展业务测试中的源码黑名单。

Home 全组约 3.77 秒、Archive 约 0.85 秒，这些收缩首先服务设计清晰和维护负担，不应夸大为主要性能优化。

## 6. 应保留的关键语义

| Owner | 应保护的契约 | 跨模块代表路径 |
| --- | --- | --- |
| Agent/Runtime | 唯一根队列、generation 激活和失败保留旧服务、控制转移 | 一条真实 reload 成功/拒绝与服务 lease 流程 |
| Turn/Jobs/Execution | Turn 内监督、结束先停并收集 Job，再释放 session | 一个真实受控进程与 Turn 收尾/日切协作 |
| Context/LLM/Phase | Phase 协议失败归类、消息来源、prepare/install、Inspect 展示保护 | 一条真实输入→决策→ActionResult→下一模型请求 |
| Session/Workspace | 已接受输入与完成事实、唯一必要提交、真实文件和投影边界 | 完成 Turn 的保存/重开，以及当日资源刷新 |
| Home/Memory/Reflection | 普通 Turn 与 Reflection 的权限、overlay 与持久事实所有权 | 每种 Reflection 一条装配与来源语义；来源定位组合在 owner 验证 |
| Infra/LLM adapter/Gateway | 外部动态边界解析、三层失败、协议映射 | 每类协议保留主要成功/失败/取消或结果未知的代表情形 |

取消、结果未知、陈旧 service lease、日切顺序等虽然是非成功路径，但本身就是 TinySoul 的主要生命周期语义。应减少重复排列和过度时序要求，不把它们视为无用防御全部清掉。

## 7. 建议实施顺序与验收

以下为确认的实施顺序；实际完成情况以开头清单和第 9 节为准。

1. 统一运行入口、隔离实例目录和环境，明确 asyncio backend；保留本次基线与机器可读耗时输出。先让运行方式可理解、工件可找到。
2. 整理自有配置/结果/生命周期辅助，改掉正式模型与资源内容耦合；删除明确的迁移墓碑断言。建立集中 package-owned 资源验收。
3. 优先分解 SDK/builder 的重复全链路测试；对配置热点另作小范围生产优化。分别测量测试结构与生产优化的收益。
4. 按 owner 收拢重复、清除无兼容需求的生产分支及测试；逐项决定故障矩阵与源码守卫的去留。
5. 调整套件 marker 与文档；完整运行本地门禁和类型检查，并在干净环境复核。并行执行仅在仍有价值时追加，不作为前面步骤的前提。

验收不设“必须删除多少测试”指标：

- 新机器按声明依赖准备 Python 后可运行，不依赖开发者个人目录、凭据、代理或额外异步 backend。
- 默认产物都在项目忽略目录；失败能定位具体测试与工件；无遗留子进程和实例锁。
- 合法新增/修改模型、provider、提示文案和 Action 配置不触发内容快照失败；真正的引用、schema、能力装配错误仍能被识别。
- 关键契约有明确 owner，跨层测试数量由协作风险决定；删除旧测试时说明哪项契约仍被保留或已取消。
- 同机对比 Fast 与 Full 墙钟、慢项和收集时间；分别报告移出 Fast 与实际减少 Full 工作量的效果，不承诺未经测量的速度。

## 9. 实施结果与规约核对

### 统一入口与运行环境

`scripts/test.py` 使用当前解释器调用 pytest；`scripts/test.ps1` 只处理解释器与参数转交。suite 选择、临时环境、asyncio backend、报告和清理由 `tests/conftest.py` 唯一负责。直接 pytest 具有相同语义，路径、`-k`、`-m` 都只缩小 suite；误选 Integration 文件而使用 Fast 时返回 pytest 的无测试状态，并打印 suite 提示。

Fast 排除 Integration、Packaging、External；Full 包含全部本地测试。External 模块保留显式开关，普通目录收集在导入 `test_real_*.py` 前排除；真实模型参数化也检查 suite，显式传入文件不会提前读取个人项目。defuddle 等额外工具不因宿主偶然安装就进入本地门禁。

默认产物位于 `.local-test/runs/<uuid>` 和 `.local-test/reports/<uuid>`，已在 Git ignore 范围内。pytest cache、TEMP/TMP/TMPDIR、LOCALAPPDATA 和 instance registry 都隔离；本地 suite 清除宿主 `TINYSOUL_*` 覆盖，测试需要的配置自行安排，External 保留其显式设置。成功运行清理大目录，失败保留；JUnit、耗时摘要、调用与收集错误详情持续保留。没有新增并行调度或共享活动 Agent。

开发依赖显式声明 AnyIO、pip，移除未使用的 pytest-asyncio；运行依赖补充 Windows 时区数据库 tzdata。`tmp_path` 代替冗余 local_tmp fixture。实际 Python 路径只出现在本地运行记录中，不进入共享配置。

### 效率与同步

ConfigCatalog 只索引不可变 descriptor 的预解析 pattern，按路径层数及末段缩小候选；完整匹配和歧义拒绝保持。没有缓存项目文件、环境、当前配置值或增加失效协议。新增小样本覆盖精确/通配匹配、无匹配、层数、歧义及新 catalog 独立性。

最慢的 Action 配置集成用例由多次 HTTP 修改/reload 收缩成“保存尚未生效→reload→可见性及 timeout 生效”的代表性链路，继承/覆盖交给 catalog owner。HTTP 路由组合改用确定性匹配，真实重定向仍保留；本地服务缩短停服轮询。MCP fixture 自己绑定端口 0，完成启动后发布端口；ACP 用子进程就绪消息替代固定 sleep，关闭与 join 仍执行。
