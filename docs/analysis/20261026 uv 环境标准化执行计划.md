# uv 环境标准化执行计划

状态：pending（方案与范围已明确，尚未实施）

## 目标

将 TinySoul 的 Python 开发和标准安装流程统一为 uv 项目环境，使新机器可以从仓库和锁文件重建环境，并让测试入口、类型检查入口和协作规约使用同一套命令。桌面开发环境中的源码以 editable 方式运行；标准安装从当前源码构建并安装非 editable 包。

本次不实现主机更新脚本，不改变 Agent 项目的 `init`、`reset`、运行数据布局或数据迁移语义，不增加 Conda 兼容路径，也不重设计产品依赖或 Action/Agent 行为。

## 当前情况

- `pyproject.toml` 要求 Python `>=3.13`，声明 setuptools 构建后端、运行依赖和 `dev`、`web-crawl`、`external-tools` optional extras；仓库没有 `uv.lock` 或 `.python-version`。
- `dev` extra 同时包含 pytest、AnyIO、ty、pip、setuptools、Crawlee 和 `external-tools`。Wheel 验收测试使用当前解释器的 `pip` 和 `setuptools`，这些开发依赖不能在迁移时遗漏。
- README 以 `pip install .` / `pip install -e ".[dev]"` 描述 Standard 与 Development，但没有统一 Python 解释器和依赖锁定方式，且混入较多历史迁移、模型 API 和实现细节。
- `scripts/test.ps1` 与 `scripts/typecheck.ps1` 直接选择 PATH 中的 Python 或 `TINYSOUL_PYTHON`；`AGENTS.md` 仍要求 Conda `TinySoul`。`.gitignore` 已忽略 `.venv/`、测试工件和 `.conda/`。
- 测试入口已统一为 `python scripts/test.py`，默认 Fast、`--suite full` 为完整本地门禁；测试缓存和报告位于仓库忽略目录。

## 设计决定

1. uv 是 Python 版本发现/管理、虚拟环境、依赖解析与同步的标准工具。保留 `requires-python = ">=3.13"`；新增 `.python-version` 请求 Python `3.13`，允许同一 minor 的补丁版本更新。
2. 生成并提交 uv 管理的跨平台 `uv.lock`。日常安装和验证使用 `--locked`，依赖声明变化后显式运行 `uv lock` 并审阅锁文件差异。锁文件不可手工编辑，不加入机器路径或本机安装清单。
3. 保留当前 PEP 621 依赖组织和 extras：标准环境选择基础依赖，不带 extras；开发环境通过 `--extra dev` 安装完整开发依赖。当前没有 `[dependency-groups]`，因此不使用 `--no-dev` 表达标准安装。
4. `uv sync` 默认 editable 安装项目，适合开发。标准安装明确使用 `--no-editable`，避免运行环境依赖源码目录。`uv run` 在目标项目环境中调用 TinySoul；不使用 `uv tool install` 作为仓库源码开发入口。
5. 开发源码修改会由后续启动的 Python 进程直接读取；已经运行的后端进程需要重启。uv 负责同步 Python 环境，不承担应用热重载。
6. `.venv/` 和 `.local-test/` 是仓库内可重建环境/工件目录并保持 Git 忽略。项目 Agent 数据放在仓库之外或明确的目标目录；模板变化不自动覆盖已有数据，`reset` 仍是会替换运行数据的显式操作。

## 实施计划

### A. 项目环境元数据

- [ ] 新增 `.python-version`，内容为 `3.13`。
- [ ] 使用 uv 从 `pyproject.toml` 解析当前全部依赖及 extras，生成并提交 `uv.lock`；解决实际暴露的解析或 wheel 兼容问题，不以临时 constraints 文件替代锁定。
- [ ] 检查锁文件包含平台条件而不含本机路径；不在没有运行证据时增加依赖或收紧 `requires-python`。
- [ ] 从 `.gitignore` 移除不再使用的 `.conda/` 忽略项，保留 `.venv/` 和 `.local-test/`。
- [ ] 更新 `pyproject.toml` 中依赖 Conda/TINYSOUL_PYTHON 的类型检查注释；不改变项目运行依赖和 extra 的现有语义。

### B. 标准运行入口

- [ ] 将 `scripts/test.ps1` 改为以仓库根为 uv project，运行锁定的开发 extra 与 `scripts/test.py`；保留 Fast/Full/Integration/Packaging/External、路径、`-k`、工件根和保留工件参数。
- [ ] 将 `scripts/typecheck.ps1` 改为在同一锁定开发环境中运行 `ty check`，移除直接选择系统 Python 和 `TINYSOUL_PYTHON` 的分支。
- [ ] 保持 `scripts/test.py` 与 pytest suite 策略不变；协作文档将 `uv run --locked --extra dev ...` 作为推荐入口，直接 `python` 只在已激活项目 `.venv` 时作为等价方式说明。

### C. 文档整理

- [ ] 更新 `AGENTS.md` 的运行环境、标准门禁及日常测试命令，移除 Conda 默认要求，明确 Fast/Full 和 typecheck 的 uv 命令。
- [ ] 重写 README 的安装和运行主线：uv 安装链接、Python 3.13、Standard 非 editable 安装、Development editable 安装、init/start、凭据说明、前端启动、Fast/Full/typecheck。
- [ ] README 保留简短的 SDK 入口、`reset` 数据影响提示和指向详细设计/测试约定的链接；删除过时的轮次迁移说明、重复架构叙述及机器特定真实 API 示例。
- [ ] 将仍有价值的真实 API 测试配置和 External suite 操作说明收拢到 `tests/README.md`，使用占位路径，不保留个人目录或密钥。
- [ ] 更新 `tests/README.md`，使其安装命令、uv 环境选择、suite 语义和 PowerShell wrapper 行为与实际入口一致。

## 验收

- [ ] 在干净的 uv 项目环境中，锁定安装 `uv sync --locked --extra dev` 成功，且不依赖 Conda、系统 site-packages、个人 Python 路径或外部模型凭据。
- [ ] 验证 editable 环境中的 `tinysoul` 模块来源位于当前 checkout；Python 源码变更无需重装即可被新进程导入。
- [ ] 验证标准安装 `uv sync --locked --no-editable` 成功，CLI 可启动、可在隔离目标目录执行 `init`，且导入来源为该环境内安装的包。
- [ ] 通过 `uv run --locked --extra dev python scripts/test.py`、`uv run --locked --extra dev python scripts/test.py --suite full` 和 `uv run --locked --extra dev ty check`。
- [ ] 验证 PowerShell Fast/Full wrapper 和 typecheck wrapper 使用仓库 uv 环境并保留参数转发；依赖缺失或锁不一致时给出明确失败，不回退到系统 Python。
- [ ] 检查 README 和 AGENTS 的命令可直接从新 checkout 使用；全文当前规约不再要求 Conda，历史归档记录不改写。
- [ ] 运行 `git diff --check`，核对所有计划项、文档链接和最终改动范围后，才能把计划标为 done 并移入 `docs/analysis/done/`。

## 实施前提与待决策项

方案、运行模式和文档范围均已明确，无待维护者裁定的设计问题。实施验证需要可执行的 uv 和 PyPI/缓存访问；当前工作区没有 uv 命令，因此实施时需先准备 uv。是否能在目标 Linux 主机上做第二平台实测，取决于实施阶段可用环境；锁文件本身应保持跨平台解析。
