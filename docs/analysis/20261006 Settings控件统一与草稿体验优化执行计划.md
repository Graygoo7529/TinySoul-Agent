# Settings 控件统一与草稿体验优化执行计划

日期：2026-10-06；2026-10-27 按最新设置实现复核

状态：待逐项确认与实施

范围：`visualization/src/features/settings/` 的共享控件、editors/models 控件、draft/*、SettingsBottomBar、SettingsOverviewPage、pages/labels/i18n，以及 NetworkPolicyEditor、NetworkPage、InterfacePage 的相关呈现。保持字段级 ConfigDraft、apply/reload、集合对象原子提交和模型/Provider 创建逻辑不变；不新增配置面。

## 最新基线

设置区已新增四类 API mode 的模型/Provider 编辑、统一模型候选、独立网络代理页和项目共享界面设置。它们已经接入正确数据链路，本计划不重建这些页面。

- Agent 配置继续使用 ConfigDraft 与底部应用栏；
- Interface 使用 presentationController 的独立即时预览/自动保存，**不得并入 Agent draft、应用栏或 pending activation**；
- NetworkPolicyEditor 继续编辑原子 network 对象，NetworkPage 的已保存路由概览继续只读；
- `session.max_background_chars` 已明确归 Context 页，Session 页的摘要跳转保留，不再执行旧计划中的“移回 Session”；
- 设置底栏位于内容滚动区之外，长页面滚动时仍可见。因此取消“页内 sticky 草稿条”，避免重复计数与重复应用按钮。

## 改进点 1：共享控件与脏状态统一（架构项）

### 现状

`editors/controls.tsx` 与 `models/controls.tsx` 仍有同名 FieldRow/FieldSection、不同 inputClass 和两套开关规格。简单字段有“已修改/恢复默认/基线变化/只读”和撤销；集合对象字段仍有 6px 脏点。NetworkPolicyEditor 又直接组合两套控件，InterfacePage 还有一套外观相同但独立实现的控件。

### 修改范围与内容

- 在 `features/settings/controls.tsx` 建立**纯展示、无 ConfigDraft 依赖**的共享控件层：FieldRowLayout/FieldSectionLayout、inputClass、Select、Toggle、受控 Text/Number 输入及焦点/撤销按钮规格。这个文件替代重复实现，不增加第三套平行 API；
- `editors/controls.tsx` 只保留 DraftFieldApi 绑定、stale/readOnly/details/定位等 Agent 草稿语义；`models/controls.tsx` 只保留集合编辑器、排序、ChoiceToggles、StringList/JsonObject 等集合语义。两者复用共享层，不强求把不同数据的 FieldRow 合并成一个宽泛 props 联合；
- 集合对象列表与字段行改用文字 DraftBadge（modified/new）和字段级撤销，draft key 继续使用现有 `draftKey/parseDraftKey` 与 resetEntries，不把集合路径当裸字符串处理；
- DraftText/DraftNumber 补齐 Escape 恢复未提交文本；受控输入已有该行为时直接复用；
- NetworkPolicyEditor 使用同一共享输入规格；InterfacePage 可复用纯展示控件，但保留自己的保存状态、即时预览和错误重试，不出现 Agent“已修改/应用配置”徽标。

### 预期效果

一套视觉和键盘语义，两个清晰适配层分别服务 Agent 草稿与集合对象；新增网络/模型字段不再选择控件风格，Interface 不被错误接入另一套保存生命周期。

## 改进点 2：字段级新旧值对比

### 现状

字段草稿只有“已修改”，基线与草稿的对比主要在 Overview；长值和对象值不易审阅。`useDraftField` 已能计算 savedBaseline，只需将其纳入明确展示 API。

### 修改范围与内容

- 草稿字段的“已修改”徽标或旁边按钮展开 `基线 → 草稿`；短标量内联，长文本/对象显示规模摘要并可展开 JsonTree；
- “恢复默认”显示当前草稿与恢复默认的语义，不把恢复默认误写为撤销本地修改；
- 集合对象字段复用同一对比呈现；
- 统一使用现有 `valuePreview`（含 redacted 处理）作为摘要来源，Overview 的 previewValue 重复实现一并收口。凭据永远显示脱敏占位，不读取或拼接真实 secret。

### 预期效果

用户在当前字段即可发现误改，Overview 与字段行看到一致的值摘要，凭据不泄漏。

## 改进点 3：底栏草稿明细与 stale 批量处理

### 现状

底栏始终可见且操作完整，但明细要切到 Overview；stale 只能逐条处理；“放弃全部”没有二次确认。

### 修改范围与内容

- 底栏计数处向上展开草稿明细：路径、基线 → 草稿、所属页、单项撤销；点击条目经现有 navigateTo(page, focusPath) 跳转并聚焦；
- 展开区增挂在现有 footer 上，不改变 pending_reload、问题计数、blocker、apply/reload 与窄屏更多操作；
- stale 条目顶部提供“全部采用新值 / 全部保留修改”，逐项调用现有 `resolveStale(key, adopt|keep)`；Overview 保留单条处理；
- “放弃全部”使用行内二次确认，超时未确认自动复原，不新增 Modal。

### 预期效果

不离开当前页即可审阅和收束全部本地修改；底栏仍只有一份计数与主应用入口，不再增加 sticky 副本。

## 改进点 4：保存与恢复默认语义显式化

### 现状

DraftNumber/DraftText 清空即删除 override，但缺少显式入口；Slider 未设置时旋钮停在最小值，容易被误读为当前值。非法数字已有内联错误，无需重做。

当前普通 CatalogField 没有可供前端展示的 owner default 数据；不能拿 saved effective value 冒充默认值，也不能从滑块最小值猜默认值。

### 修改范围与内容

- 有 override 时提供淡色撤销/恢复默认按钮，语义与 SliderField 的 `api.clear()` 一致；
- placeholder 使用“继承默认/未设置”等中性提示。只有后端 catalog 真正声明默认值时才显示具体值；本轮不为此新增端点或虚构默认；
- Slider 未设置态降低滑轨透明度、使用空心旋钮并标注“未设置”，不改变实际 draft 值与校验；
- Escape、blur/Enter 提交与非法输入错误保持统一。

### 预期效果

恢复默认不再依赖“清空输入”的隐式约定，未设置与设为最小值可辨；界面不承诺无法取得的默认数值。

## 改进点 5：可读性、配置归属与导航收口

### 修改范围与内容

- 页头描述取消 line-clamp-1；字段描述完整显示，超长才折叠；
- Overview 待激活 diff 改为结构化路径 + `运行值 → 保存值`，长对象按规模摘要并可展开；
- 保持 `session.max_background_chars` 在 Context 页，保留 Session 页 saved/running 摘要和跳转，不制造两个编辑入口；
- 从 PAGE_COMPONENTS、SETTINGS_PAGES、SETTINGS_GROUPS 与相关 labels/i18n 中移除无配置面的 image-generation 死导航；
- 将 controls.tsx 与 ui.zh-CN.ts 中作为普通 TS 字符串使用的 `&apos;`/`&amp;` 改为实际字符；
- 同步修正 `visualization/docs/design/config-coverage.md` 中专用 Provider 仍写 proxy 的旧描述：当前统一使用 network 对象；模型与网络页面说明以实际 catalog 为准。

### 预期效果

配置说明可读、归属唯一、导航均有真实功能；新网络配置与既有文档不再互相矛盾。

## 实施顺序与验收

顺序：1 的脏状态/共享布局 → 2 → 3 → 4 → 5 → 1 的其余控件迁移。每一步独立可验收，避免一次性重写所有模型页。

1. 简单字段、集合对象、Network 的控件与 dirty/撤销语义一致；Interface 仍独立自动保存；
2. 草稿可见基线 → 草稿，redacted 不泄漏；
3. 底栏明细可跳转/撤销，stale 可批量处理，放弃全部有确认；
4. 恢复默认显式可用，Slider 未设置可辨，无虚构默认值；
5. Context/Session 归属不重复，无 image-generation 死导航和 HTML 实体键；
6. 模型创建/adapter 切换/Provider Chain、网络原子对象、apply/reload 的现有测试继续通过；`npx tsc --noEmit` 与 `npx vitest run` 全绿。

边界：不改 draft key/op、apply 排序和失败分类、集合对象创建/删除/重命名流程、四类 API mode 规则或 presentation 保存协议；不增加页内 sticky 草稿条。
