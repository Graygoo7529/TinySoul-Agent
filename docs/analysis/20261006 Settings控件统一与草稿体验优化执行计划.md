# Settings 控件统一与草稿体验优化执行计划

日期：2026-10-06

状态：待逐项确认与实施

范围：`visualization/src/features/settings/`（editors/controls.tsx、models/controls.tsx、models/ObjectEditor.tsx、draft/*、SettingsBottomBar.tsx、SettingsOverviewPage.tsx、pages.ts、SettingsNav.tsx、各页面文件）。不改 draft 数据模型（字段级路径 draft 保持）、不改 apply/reload 链路、不新增配置面。

## 目标

设置区已有扎实的数据层（字段级 draft、stale 检测、apply 定位失败字段），但呈现层有两套平行控件库（`editors/controls.tsx` 1250 行 vs `models/controls.tsx` 559 行），脏状态两套语言（完整徽标 vs 6px 圆点），用户改配置时"改了什么、从什么改成什么、哪些没保存"三个问题没有稳定答案。本计划统一控件语义、补齐草稿可见性，不重建任何页面骨架。

---

## 改进点 1：控件库统一（架构项）

### 现状分析

- `editors/controls.tsx`（FieldRow/DraftBoolean/DraftNumber/DraftText/DraftEnum/SliderField/CredentialValueEditor/KeyValueMapEditor/FieldSection/SettingsPageBody）服务简单字段页；`models/controls.tsx`（FieldRow/FieldSection/TextInput/NumberInput/Toggle/SelectInput/OrderableRow/ChoiceToggles/JsonObjectInput/StringListEditor）服务集合对象页——**同名 FieldRow/FieldSection 两套实现**；
- 脏状态不一致：editors 的 FieldRow 有"已修改/恢复默认/基线已变化/只读"徽标 + 撤销按钮 + 详情区（`editors/controls.tsx:205-245`）；models 的集合列表只有 6px 脏点；
- 开关规格不一：`DraftBoolean` 高 22px（:301-310），`Toggle` 另一套尺寸；
- Escape 恢复编辑只在 `models/controls.tsx` 的 TextInput/NumberInput 有。

### 修改范围与内容

分两步，每步独立可验收：

- **第一步（脏状态统一，不改组件结构）**：`models/ObjectEditor.tsx` 的对象列表与编辑器头部，把 6px 脏点改为文字徽标（`modified`/`new`，复用 `models/controls.tsx` 已有的 `DraftBadge`）；集合编辑器内字段行补"撤销此修改"按钮（调用字段对应 draft 的 resetEntries——draft key 为 `JSON.stringify([sourceId, path])`，用 `draft/model.ts` 的 `draftKey/parseDraftKey`，key 不当裸 path 用）。
- **第二步（控件正典化）**：以 `editors/controls.tsx` 为正典——
  - `models/controls.tsx` 的 Toggle/SelectInput 视觉规格对齐 DraftBoolean/DraftEnum（高度、focus 环），或薄封装转发；
  - `models/controls.tsx` 的 FieldRow/FieldSection 与 editors 版本合并为一个实现（合并后的 FieldRow props 取并集：`title/description/dirty/actions`），两个文件之一删除，引用统一；
  - Escape 恢复补齐到 `DraftText`/`DraftNumber`（未提交文本按 Escape 还原为当前显示值）；
  - models 独有件（OrderableRow/JsonObjectInput/KeyValueMapEditor/ChoiceToggles/StringListEditor）保留在 models/controls.tsx，但其内部输入控件复用正典 inputClass。

### 预期效果

设置区一套控件语义：任何字段的脏状态、撤销、只读呈现一致；新增配置页不需要在两套库之间做选择。合并后控件代码总量下降，后续改动单点生效。

## 改进点 2：字段级新旧值对比

### 现状分析

字段有草稿时只有"已修改"徽标，**看不到从什么改成什么**；只有 Overview 草稿列表有 28 字符截断预览（`SettingsOverviewPage.tsx` DraftList）。而 `useDraftField`（`editors/controls.tsx:103-153`）其实已经同时持有 `savedBaseline` 与 draft 值——数据都在，只差呈现。注意凭据类字段必须走现有 redaction 语义（`<redacted>` 显示为 `••••••`，复用 `SettingsOverviewPage.tsx:33-38` 的 `previewValue`，不得自写格式化函数绕过）。

### 修改范围与内容

`editors/controls.tsx` FieldRow：

- "已修改"徽标改为可点击（或旁加小按钮），点击展开一行对比：`基线 30s → 草稿 60s`；短值内联（复用 `previewValue`/`valuePreview` 截断），对象/长值显示 `N 个字段变更` 可点开 JsonTree；
- "恢复默认"（delete 草稿）显示 `当前 60s → 恢复默认`；
- 集合对象编辑器的字段行在第一步统一徽标后获得同样能力（复用同一组件）。

### 预期效果

任何改动悬停即见新旧对比；误改能当场发现；凭据字段不泄漏。

## 改进点 3：页内 sticky 草稿条

### 现状分析

草稿计数只在底部 SettingsBottomBar（`SettingsBottomBar.tsx:55-61`，已是中文"N 项未保存修改"）；长表单（如 Workspace 页 3 节 15+ 字段）滚动后底栏不在视口，用户忘记有未应用修改。设置页外的 `SettingsDraftChip` 只提醒"有草稿"，不解决页内可见性。

### 修改范围与内容

- `SettingsPage.tsx` 内容区顶部：当前页有草稿时（`pageDraftKeys(page, drafts)` 已有此计算，BottomBar 在用）渲染一条 sticky 提示条：`本页 2 项未应用修改 · 全部共 5 项` + `[应用]` `[重置此页]` 按钮（复用 `applyDrafts`/`resetEntries`，与底栏同语义）；
- 样式：淡 warning 底色（`bg-warning-soft/60`），sticky top-0，仅页内出现，不与底栏重复全局计数文案。

### 预期效果

长表单任何滚动位置都能看到本页未保存状态并可就地应用；"应用"不再是滚到底才想起的动作。

## 改进点 4：保存语义显式化

### 现状分析

- `DraftNumber`/`DraftText` 的 placeholder 固定是 `"default"`（`editors/controls.tsx:360,481`）——不告诉用户默认值是多少；
- 清空输入框 = 删除 override 恢复默认（:336-341,468-471），这是隐式语义；SliderField 有显式恢复按钮（:439-446），纯数字/文本字段没有；
- SliderField 未设置时旋钮停在最小值（:411-414，注释自承"park the knob at the range start"），视觉上像"当前值=最小值"；
- （修正此前误判：DraftNumber 非法输入 blur 时**已有**内联红字报错，:371-373，此项无需改动。）

### 修改范围与内容

`editors/controls.tsx`：

- placeholder 从 `"default"` 改为具体默认值：catalog field 有默认值时显示 `默认 30`（带单位）；取不到默认值的字段保持 `"default"`；
- `DraftNumber`/`DraftText` 在有 override 时右侧常驻淡色 `↺` 按钮（语义同 SliderField 的恢复按钮，复用 IconButton + `api.clear()`）；
- SliderField 未设置态：滑轨降低不透明度 + 旋钮空心样式 + 旁标小字"未设置"（纯样式区分，不动值逻辑）。

### 预期效果

"默认值是什么"不用猜；"恢复默认"是显式按钮而不是魔法操作；滑块的"未设置"与"设为最小值"不再混淆。

## 改进点 5：底栏草稿明细展开区

### 现状分析

底栏有完整操作（重置此页/放弃全部/应用配置/激活已保存配置，均中文）但看不到草稿明细；明细要切到 Overview 页。"放弃全部"无二次确认。

### 修改范围与内容

`SettingsBottomBar.tsx`：

- 计数文案处增加可点开的向上展开区（ChevronUp 已有类似模式）：列出全部草稿条目——每行 `路径（末两段）+ 基线 → 草稿（previewValue 截断）+ 所属页徽标 + 单项撤销按钮`；条目点击跳转对应页并聚焦字段（复用 `uiStore.navigateTo(page, focusPath)` 与 FieldRow 的 flash 定位，机制已存在）；
- 展开区是**增挂**在现有 footer 之上，不重写底栏任何现有功能（stale/问题计数、blocker 原因、reload 路径保持原样）；
- "放弃全部"加一次行内确认（点击变为"确认放弃全部？"二次点击执行，3s 未确认自动复原——不引入新 Modal）。

### 预期效果

不离开当前页就能审阅全部未应用修改并逐项撤销/跳转；批量放弃有防误触。

## 改进点 6：Stale 基线批量处理

### 现状分析

stale（编辑期间基线变化）目前逐条处理：字段级"采用新值/保留修改"（`editors/controls.tsx:248-263`）、Overview DraftList 逐条——无批量入口。store 的真实 API 是 `resolveStale(key, "adopt" | "keep")`（`draft/store.ts`）。

### 修改范围与内容

- 改进点 5 的展开区内：有 stale 时顶部增加一行 `2 项基线已变化 [全部采用新值] [全部保留修改]`，遍历 stale keys 调 `resolveStale`；
- Overview 页 DraftList 保持现状（单条处理），不重复建设。

### 预期效果

基线漂移场景（如外部改了配置文件）一键收束，不用逐条点。

## 改进点 7：可读性与导航收口

### 现状分析

- 描述文字普遍 11px 且部分截断（页头描述 `line-clamp-1`）——配置语义被埋没；
- Overview 待激活 diff 是 50 字符等宽截断，对象值不可读；
- `session.background_max_chars` 归 Budgets 页，Session 页放只读跳转行补偿——概念割裂；
- image-generation 是无配置面的死导航项；
- `editors/controls.tsx:1219,1224` 把 `&apos;`/`&amp;` HTML 实体写进 TS 字符串当 i18n 键——缺翻译时会原样渲染实体。

### 修改范围与内容

- 页头描述取消 `line-clamp-1`（完整显示）；字段描述保持 11px 但不截断（超两行才折叠）；
- Overview 待激活 diff 改为结构化行：路径 + `旧值 → 新值`（previewValue），对象值折叠为 `N 个字段变更` 可展开；
- `pages.ts`：`session.background_max_chars` 归属移回 Session 页（删除 Budgets 页对应项与 Session 页的跳转补偿行）；
- image-generation 页面从 `PAGE_COMPONENTS`/导航移除（后端出现该配置面时恢复，代码保留在仓库历史中）；
- `&apos;`/`&amp;` 实体键改为普通字符（`'`/`&`），同步 i18n 表键值。

### 预期效果

配置说明完整可读；Overview 能真正审阅待激活差异；导航项全部有真实功能。

## 实施顺序与验收

建议顺序：1 第一步（脏徽标）→ 2（新旧对比）→ 3（sticky 条）→ 5+6（底栏展开区含批量 stale）→ 4（保存语义）→ 7（可读性）→ 1 第二步（控件正典化，放最后因为它触碰面最广）。

验收标准：

1. 集合对象页与简单页脏状态呈现一致；两套 FieldRow 合并为一；Escape 恢复全覆盖；
2. 任意草稿字段可见基线 → 草稿对比；redacted 值不泄漏；
3. 长表单滚动时页内 sticky 条可见可操作；
4. placeholder 显示真实默认值；纯数字/文本字段有显式恢复默认按钮；Slider 未设置态可辨；
5. 底栏可展开草稿明细，条目可跳转定位；放弃全部有二次确认；
6. stale 可批量 adopt/keep；
7. 页头描述完整显示；Overview diff 结构化；无死导航项；无 HTML 实体键。

边界：不改 draft model 的 key 结构与 op 形状；不改 apply 的操作排序与失败分类；不改动 24 个页面的配置项内容与分组语义（除改进点 7 明确列出的一项归属修正）；集合对象的创建/删除/重命名 Modal 逻辑不动。
