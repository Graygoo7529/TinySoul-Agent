## 改进点 1：字段行脏状态与键盘语义收口

状态：done（2026-11-04）

### 现有情况

- 集合对象字段的脏状态仍是 6px 色点（modelControls.tsx:50），与 draft 侧字段行的文字徽标（"已修改"Badge，draftControls.tsx:203）不一致；`DraftBadge`（modelControls.tsx:501）已导出但**零消费**，是本项的天然落点；
- `DraftText`/`DraftNumber` 只有 Enter/blur 提交，**没有 Escape 恢复未提交文本**；而 InterfacePage 的独立数字输入已有 Escape 行为（InterfacePage.tsx:327），键盘语义在设置区内不一致；
- `Toggle`（modelControls.tsx:208）与 `DraftBoolean`（draftControls.tsx:281）是两份独立实现的开关：规格几乎相同但写法各异（`h-5.5` vs `style height:22`、`translate-x-5` vs `translate-x-[19px]`、一个有 `focus-ring` 一个没有）；
- InterfacePage 的数字输入仍硬编码第三份输入框 className（InterfacePage.tsx:319），未接入 `inputChrome`；
- NetworkPolicyEditor 混用两套控件（modelControls 的 TextInput/selectClass + draftControls 的 FieldRow），视觉已随 inputChrome 对齐，结构保留现状即可。

### 修改范围与内容

- modelControls 的 `FieldRow` 把 6px 脏点改为文字徽标：复用 `DraftBadge`（或对齐 draft 侧 Badge 用法），文案与 draft 侧一致（"已修改"）；`dirty` prop 与各消费方调用不变；
- `DraftText`/`DraftNumber` 增加 Escape：恢复为未提交前的显示值并清除内联错误，与 InterfacePage 既有行为一致；
- 开关规格合一：以 Tailwind 类写法为准对齐 `DraftBoolean`（h-5.5/w-10、translate-x-5、补 focus-ring），视觉差仅焦点光晕与 1px 级尺寸；
- InterfacePage 数字输入的硬编码 className 换成 `inputChrome`（保留其独立即时保存生命周期，只统一视觉）；
- 本项完成后 `DraftBadge` 获得真实消费者。

### 预期效果

全设置区脏状态都是文字徽标、输入框键盘语义一致、开关只有一份规格；视觉变化仅为脏点变徽标、DraftBoolean 增加焦点光晕。

### 实施验证（2026-11-04）

- modelControls.FieldRow 的 6px 脏点改为 `DraftBadge`「已修改」（复用既有 `common.modified` 键）；DraftBadge 由此获得真实消费者，死导出消除；
- DraftText/DraftNumber 增加 Escape（恢复显示值；DraftNumber 同时清除内联错误），与 InterfacePage、modelControls TextInput 的键盘语义一致；
- DraftBoolean 对齐 Toggle 类规格（h-5.5/w-10、translate-x-5、focus-ring），并修复开关旋钮错位：旋钮原为 `absolute top-0.5` 无 `left`，依赖静态位置，被 button 的 UA `text-align:center` 挤向中部导致开启态溢出轨道右缘、关闭态居中；两个开关的旋钮统一显式 `left-0` 后几何确定（开启态右缘 2px 内边距）；
- InterfacePage 数字输入接入 `${inputChrome} w-24 text-right`，独立保存协议不变；
- 门禁：tsc 零错误；vitest 102 文件 / 893 用例全绿；build 通过；git diff --check 干净。改动文件：modelControls.tsx、draftControls.tsx、InterfacePage.tsx。

## 改进点 2：字段级基线→草稿对比

状态：done（2026-11-04）

### 现有情况

`useDraftField` 已计算 `savedBaseline`（draftControls.tsx:116）但未暴露给 `DraftFieldApi`，字段行的 details 展开区只有 path/source/readOnly 三行（draftControls.tsx:256-266），用户在字段旁看不到"原来是什么、现在改成什么"，长值和对象值尤其难审阅。另外 `SettingsOverviewPage.tsx:34` 的 `previewValue` 与 draftControls 的 `valuePreview` 是逐字节重复的私有实现（均含 redacted 处理）。

### 修改范围与内容

- `DraftFieldApi` 增加 `baseline: JsonValue | undefined`（即现有 savedBaseline，纯透传，不改计算逻辑）；
- FieldRow 的 details 展开区增加"基线 → 草稿"两行：短标量内联 `valuePreview`，长文本/对象显示规模摘要并可展开 JsonTree；凭据永远显示脱敏占位（沿用 `isRedactedValue` 路径）；
- 删除 Overview 的私有 `previewValue`，改从 draftControls 导入 `valuePreview`；Overview 待激活/本地修改两处的长对象同步获得可展开呈现（复用同一摘要组件）；
- 集合对象字段（modelControls 侧）复用同一对比呈现组件。

### 预期效果

用户在当前字段即可发现误改；Overview 与字段行看到一致的值摘要；一处 redacted 逻辑，凭据不泄漏。

### 实施验证（2026-11-04）

- `DraftFieldApi` 增加 `baseline`（savedBaseline 纯透传）；新增 `ValueCompare` 组件：短标量内联、长文本/对象显示规模摘要（`{count} 个键`/`{count} 项`）+ 可展开双 JsonTree 对照、redacted 两侧只显示 `••••••`（`isRedactedValue` 先于对象判断）、删除 override 显示 `当前值 → 恢复默认`（danger 色）；
- FieldRow 详情区顶部接入对比（仅 dirty 时出现），标签采用「本次改动」——因既有 stale 徽标已占用「基线已变化」（指编辑期间保存基线外部变动），避免一词之差混淆；JsonTree 栏 caption 为「基线 / 草稿」；
- Overview：删除与 valuePreview 逐字节重复的私有 `previewValue`；待激活区改为 div 行 + 内联 ValueCompare（`运行值 → 保存值` 长值可展开）；本地修改区字段条目改为第二行 ValueCompare（基线经 `savedValue` 取回，delete 条目显示恢复默认语义）；清理诊断列表改用共享 `valuePreview`；
- 集合对象编辑页的行内对比按讨论结论不做（modelControls.FieldRow 无详情区），留作后续可选小改进点；
- 新增 i18n 键（双语）：settings.thisChange/valueBaseline/valueDraft/expandValue/collapseValue/objectKeys/arrayItems；
- 门禁：tsc 零错误；vitest 102 文件 / 893 用例全绿；build 通过；git diff --check 干净。改动文件：draftControls.tsx、SettingsOverviewPage.tsx、两个 locale 的 settings.ts。

## 改进点 4：恢复默认显式化与 Slider 未设置态

### 现有情况

- `DraftText`/`DraftNumber` 清空输入即 `api.clear()`（删除 override 恢复默认），但没有显式入口，语义靠用户猜；SliderField 已有恢复默认按钮（draftControls.tsx:429）可参照；
- catalog 已携带 `default?: JsonValue`（当前解析 string/boolean），但 placeholder 仍是固定文案（`t("common.default")` / "default"）；
- Slider 未设置时旋钮停在最小值（draftControls.tsx:401-404），与"已设为最小值"在视觉上不可区分。

### 修改范围与内容

- `DraftText`/`DraftNumber` 在有 override（`api.dirty`）时显示淡色恢复默认按钮，语义与 SliderField 的 `api.clear()` 一致；未设置时不显示；
- placeholder 分级：catalog 声明了默认值时显示真实默认值（当前 string/boolean 覆盖范围内），未声明时显示"继承默认"中性提示；不虚构默认值、不为此新增端点；
- Slider 未设置态：滑轨降透明度、空心旋钮样式、旁注"未设置"；拖动即进入已设置态；不改变实际 draft 值与校验逻辑。

### 预期效果

恢复默认不再依赖"清空输入"的隐式约定；"未设置"与"设为最小值"一眼可辨；界面展示的默认值全部来自真实 catalog 声明。
