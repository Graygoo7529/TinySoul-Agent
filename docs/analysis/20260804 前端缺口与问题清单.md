# 20260804 前端可视化：当前缺口与发现的问题

状态总览：本文汇总 visualization 重构与真实后端联调过程中确认的缺口、已定位的根因和待办项。条目状态：`pending` / `in_progress` / `done` / `dropped`。前端侧代码事实以 `visualization/` 当前实现为准；后端需求以 `visualization/docs/demand/` 为准。

## A. 后端相关问题（前端无法自行解决）

### A1. Endpoint 在特定工作负载下整体挂起 — `pending`（严重）

- 现象：两次独立实例（pid 30888 / port 57000、pid 21376 / port 57702）在处理"帮我在工作区写一个很长的 markdown 文件"类输入后，进程存活、TCP 可连，但 `GET /v1/health` 5s 零字节、WS 8s 零帧，持续数分钟不恢复。
- 影响：主对话 cycle/stage 冻结、状态轮询失败、`stop_turn` 无法下达——用户此前报告的"stage 不即时更新、停止无效"大概率源于此。
- 需求文档：`visualization/docs/demand/20260804-endpoint-responsiveness.md`。
- 排查建议：workspace.write 的 LLM 组合（LLMActionTaskRunner）路径是否阻塞 ASGI 事件循环；Endpoint 服务与 Program 执行是否需要进一步解耦。

### A2. 重启后当天会话与 trace 不可恢复 — `pending`

- 事件缓冲在进程内（2000 条），重启即失；无 `/v1/session/*` 读取端点；model payload 不落盘。
- 需求文档：`visualization/docs/demand/20260804-session-history-persistence.md`（方案 A：Session 只读投影端点恢复骨架；方案 B：LLM 调用投影落盘恢复完整 message stack）。

### A3. WS 鉴权帧只读一次 — `done`（前端已适配）

- 服务端只在连接起始读一次 auth 帧；前端 `setMode` 重发帧不会生效。前端已改为重连生效（`src/api/events.ts`），且当前固定订阅 model 级，无实际影响。

## B. 前端已修复（本轮联调中定位）

- `done` 轮询失败即清空连接、切到断连屏——运行中后端无响应时对话现场丢失、停止按钮被禁用。已改为横幅提示 + 保留现场自动重试；instance 漂移自动重新发现（`src/hooks/useBackend.ts`）。
- `done` 运行中无 Details 入口（首个 cycle 前无按钮）——现在 turn.started 即可打开滑窗（`TurnView.tsx`）。
- `done` 停止判定依赖 2s 轮询有延迟——改为派生 running turn 优先（`ChatView.tsx`/`Composer.tsx`）。
- `done` 用户消息不回显——`app.command.accepted` 无文本载荷且旧代码匹配错误的 kind（`start_turn`）；已改为本地回声 + 首个 message stack `user_input` 段恢复（`src/derive/chat.ts`）。
- `done` WebView2 中 blob 下载不触发导致导出"无反应"——改为 Tauri dialog + Rust 写盘（`src/api/exportTrace.ts`、`src-tauri/src/lib.rs`）。
- `done` 子滑窗在 1280px 宽度下左侧溢出裁切——改为 `left:0; right:<主滑窗宽>` 自适应。

## C. 前端当前已知缺口

- `pending` **Tauri 壳内导出未实机验证**：目录选择对话框 + `write_export_files` 已过 `cargo check`，Web 回退路径已验证；壳内路径需人工点一次确认。
- `pending` **多 cycle 长轮未做实机验证**：多 cycle 的 turn 只经合成事件验证；cycle 边界依赖 scope 帧推断（后端无 cycle 级事件），长轮次下的表现待真实负载确认。
- `pending` **组件级测试薄**：vitest 只覆盖 derive 层与 store 选择器；交互组件无测试（本轮用 Playwright 截图验收代替）。
- `pending` **事件在 2000 条上限处截断**：超长会话最旧事件被丢弃，早期 turn 的 trace 会不完整（与 A2 的后端持久化需求相关）。
- `pending` **gap 恢复丢弃进行中 turn 的 live 视图**：gap 时清空事件重拉权威状态，进行中 turn 仅保留骨架；有顶部提示条，但体验可再优化（例如保留本地已有事件并标记不确定）。
- `pending` **stage 时长为 0ms 时不隐藏**：合成/极快场景下显示 "0ms"，应省略（小 polish）。
- `dropped` 前端本地持久化事件/会话以抗重启：违反"前端不得持久化 model payload"约束，由 A2 的后端方案替代。

## D. 设计层面待确认

- `pending` 主对话浮动状态的活动文案目前为英文短语；是否需要本地化（后端 message 本身为英文）。
- `pending` Monitor 视图展示上限 200 条分页加载，无虚拟滚动；2000 条上限内可接受，暂优化优先级低。
