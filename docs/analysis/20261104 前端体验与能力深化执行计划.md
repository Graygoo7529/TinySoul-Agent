- **设置导航**：分组当前可折叠（SettingsNav toggleGroup）；**检索已存在**——SettingsNav 有 catalog 全文检索（searchConfig）、CollectionList 与 ObjectEditor 的对象列表面板也各有检索框。窄布局行为由 `settings/layout.css` 容器查询驱动：≤899px 页面导航收缩为 48px 栏（触发器只是 Menu 图标，面板内含完整导航）；≤1199px 集合对象列表收缩为"当前对象名 + v"触发器。用户所述"直接进入第一个子页、v 列表难切换"指的是**集合对象级**的紧凑交互。

- **Markdown**：`components/markdown/` 是统一基础能力（ReactMarkdown 10 + codeBlockRegistry 显式注册 + Mermaid/TikZ BlockFrame（含缩放/导出/源码切换）+ rehype-katex 公式 + origin 路由 + streaming 感知），12 处消费方；`.md-body` 单一定义（14px/1.65）；`PlainCodeBlock` 无复制按钮；工作区 TextFileView 编辑态是裸 textarea（已有 edit/split/preview 三态与保存协议）。用户输入气泡为纯文本系**有意设计**，不动。

## 改进点 1：OrderableRow 拖动重设计（修复拖动 bug）

状态：done（2026-11-05）

### 现状

整行 `draggable` + 行内 `<select>`/输入框 → 控件误触发行拖动；drop 高亮整行变色且因 `onDragLeave` 冒泡闪烁；无 `dragend` 清理，拖出区域后高亮残留；放置语义"插到目标行位置"无任何落点指示。三个消费方共用此组件，修复一处三处受益。

### 修改范围与内容（`models/modelControls.tsx` 的 OrderableRow；页面逻辑零改动）

- **拖柄独占**：`draggable` 仅落在 GripVertical 句柄（含其点击区），行体不再可拖；行内控件恢复全部原生交互；
- **插入线指示**：拖动经过时在行上缘/下缘显示 2px accent 插入线（按指针位置判断前/后半行），取代整行 border 变色；
- **清理完整**：`onDragEnd` 复位全部拖动态；`onDrop` 仅在拖柄发起的拖动上生效（dataTransfer 标记自定义 type，拒绝页面内其他文本拖放误入）；
- ↑↓ 按钮与 aria 语义保留，作为等价键盘路径。

### 预期效果

从 select/输入框按下不再"整行被拖走"；拖动中落点是一条明确的插入线；松手即所期顺序。无视觉主题变化。

### 实施验证（2026-11-05）

- `OrderableRow` 重写：行体不再 `draggable`，拖动只从 ⋮⋮ 拖柄发起；dataTransfer 使用自定义 `application/x-tinysoul-reorder` 类型（外来 text/plain 拖放被完整拒绝且不 preventDefault）；目标行按指针上/下半区显示 `insert-before`/`insert-after` 插入线（layout.css 新增两条类：2px accent 线 + 淡光晕 box-shadow）；`document` 级 `dragend`/`drop` 监听保证拖出区域或 Esc 取消后边缘态完整复位；
- 三个消费方（ProviderChainSection / DedicatedModelsPage / LlmTaskChainsPage）调用与数据逻辑零改动；↑↓ 按钮键盘路径保留；拖柄补 `settings.dragToReorder` aria/tooltip 键（双语）；
- 新增 `models/modelControls.test.tsx`（jsdom，6 用例）：行体不可拖/仅拖柄可拖、MIME 标记、插入线上下半区、拒绝外来拖动、dragend 复位、drop 提交并清态；
- 门禁：tsc 零错误；vitest 103 文件 / 899 用例全绿（基线 893 + 新增 6）；build 通过；git diff --check 干净。改动文件：modelControls.tsx、layout.css、两个 locale settings.ts、modelControls.test.tsx（新）。

- **渲染补漏（先出审计清单逐项确认）**：context/messages.tsx、OwnerResourcePanel、SessionRefPanel 摘要、QuestionForm 回复文本等 agent 产出处，逐项确认后改 `<Markdown>`；用户输入气泡保持纯文本；
- registry 增补"新语言注册指南"头注释与契约测试（parse 失败回退、streaming 半栏不渲染的既有语义钉死）。

### 预期效果

同一段 markdown 在任何表面密度一致；任何代码/公式块可复制源与产物、可圈选；新增渲染语言是"一次注册"的事。

## 改进点 7：工作区 Markdown 所见即所得编辑（TipTap）

### 现状

TextFileView 的 .md 编辑是裸 textarea + 分屏预览；DeskTodo 用 TipTap 3 + `@tiptap/markdown` 验证了"即输即排"的可行路径（已批准引入）。

### 修改范围与内容

- 新增 `components/markdown/editor/`（独立子模块）：TipTap 3 React 封装——StarterKit + `@tiptap/markdown` 序列化 + katex 数学节点（复用既有 katex 依赖）+ 代码块低占用渲染（只读高亮样式，不引第三方高亮库）；
- TextFileView 集成：`.md` 文件的 `edit` 模式由 textarea 换成 WYSIWYG 编辑器；`split/preview` 行为保留；**源码对照**入口保留（切换后回到 textarea 语义）以防编辑器异常时无退路；保存协议（Ctrl+S、既有保存链路）不变；
- 非 .md 文件编辑完全不动；
- 编辑器样式复用 `.md-body` 密度 normal，编辑态与预览态同字体同排版（"可见即可读"）。

### 预期效果

工作区 markdown 编辑从"记源码"升级为"即输即排"；与 DeskTodo 同级体验，但不引其代码；异常时有源码退路。

## 改进点 8：前端本地数据目录（受限 fs 能力）

### 现状

前端本地状态全在 WebView localStorage，不可见不可备份；src-tauri 无 fs 能力（已批准新增受限能力）。

### 修改范围与内容

- `src-tauri` 新增 `local_store` 命令组（read/write/list/remove，**限定在用户选定目录内**，路径逃逸拒绝——复用 write_export_archive 的防护范式；tmp+rename 原子写）；目录状态命令（get/set data dir，持久化于应用配置目录）；
- 前端新增 `app/localStore/` 门面：Tauri 目录优先，浏览器 localStorage 兜底并如实标注；借鉴 DeskTodo SaveQueue（串行写 + 修订合并，切目录后不发迟到的写）；
- 收纳：连接档案（address+token，含多档案扩展位）、`tinysoul-ui-state`；首启迁移，原 localStorage 键保留；
- 设置-界面页新增「本地数据目录」区：显示当前位置/打开/更换（空目录复制过去、有数据则载入）、浏览器环境显示"浏览器本地存储"标识；保存失败保留修改并显示原因与重试。

### 预期效果

前端本地数据有一个可见、可备份、可迁移的家；写入语义与 DeskToolkit 同级严谨；为多连接档案等扩展打好地基。
