## 当前基线与设计原则

当前 Catalog 为 62 个 Action，`workspace.inspect` 已归入 inspect 族，矩阵覆盖完整。按结果载荷形状分族仍然合理，不按 domain 拆分渲染器；未知 Action 继续使用 generic 结构化 JSON 兜底。

- gist = 两态摘要：规划态回答“要做什么/输入是什么”，结果态回答“实际做成了什么”；
- 详情 = 规划输入区 + 执行结果区，使用与族语义相符的终端、diff、报告或网页结果容器；
- 字段提取共享：gist 与详情使用同一组 extractor，避免近似逻辑漂移；
- 只展示实际 params/result 字段。缺少状态、计数或正文时少显示，不根据 Action 名称补造成功、运行状态或输出形状；
- 低频族详情保持现有字段视图，只补 gist 摘要。

前置项：`workspace.inspect` 归族已完成；**extractor 共享尚未实施**，随改进点 4 一起落地，不单独制造界面变化。

## 改进点 2：execution 族——终端风格贯穿

状态：**已实施**，包括后续 interpreter 同步。

- 详情规划区为 `# cwd_ref` + `$ command/source_ref + args` 终端块，stdout/stderr 使用终端块；Job 输入与读取输出采用已确认的 JobChip 形式；
- `execution.run` 的 interpreter 在详情和 gist 终端块右上角显示为悬浮芯片；
- 当前 Catalog 使用 `execution.run`，不保留 run_shell/run_script 或 core.job.wait 的旧映射；矩阵为 62 项。

## 改进点 3：analysis 族——意图 + Markdown 报告卡

状态：**已实施**（2026-10-28）。

- 详情保留 intent；`answer/text` 从纯文本 Excerpt 改为 Markdown `md-calm` 报告卡，复用现有 Markdown 组件；长报告折叠而非截断正文；
- coverage 收成指标小字（complete/partial、文件数、源字符数），sources 保持真实 ref 链接；
- describe 展示真实 description 普通文本卡；compose/convert 只呈现 target/source 规划与产物事实，不把 record 元数据当作生成正文；
- `analysisModel.ts` 统一详情与 gist 的文本识别、标题和首行摘要；ResultViewProps 携带 canonical action ID 以区分族内动作；
- gist 结果态补充报告标题/首行与字数，例如 `分析报告 · 860 字符`；describe 显示资源描述摘要；
- 成功、失败、取消、未执行和结果未知仍由外层执行状态表达，不在报告卡内伪造结果。

预期效果：分析意图、真正的分析报告和来源覆盖一眼可分；标题、列表、代码和引用按 Markdown 呈现，而不是一整块预格式化文本。

## 改进点 4：web 族——统一网页结果卡

状态：**已实施**（2026-10-28，按讨论收敛 gist 范围）。

- 三类详情结果卡保留各自事实，不重复大块 Call params：
  - `search_by_kimi`：answer 摘录 + 带来源标题、真实 URL 与 snippet 的来源卡；
  - `fetch_with_*`：extractor 徽标 + title + `content_chars` + excerpt + 原始页面与 Workspace 产物；
  - `discover_pages`：种子标题/链接 + 页面计数与停止原因 + 逐页已访问/失败/候选状态及真实失败原因；
- **gist 保持主要内容**：search 的规划 query 与结果来源列表不变，fetch 的标题与摘录不变；只给 discover 结果 gist 补页面状态和失败原因，不增加来源数、字符数或访问计数；
- `webModel.ts` 统一详情与 discover gist 的字段提取和状态语义；外部链接直接打开，产物 ref 走 ResourceRouter，warning/truncated 不淹没主结果。
- 关联修复 LiveStatus 滚动生命周期：滚动窗口不再保留退出中的 AnimatePresence 副本；新行由 grow-in 与内部 reveal 入场，旧行及其 gist 随窗口更新卸载；手动折叠后 gist 也卸载，已满视口高度不回缩。

预期效果：gist 轻量且不重复，详情能完整区分“得到答案与来源”“抓到正文与产物”“发现页面目录与状态”；新消息置顶时旧 gist 不残留、不回拉。

## 改进点 6：core.reason 补 gist

- 规划态：显示首个 guide_block 的首个非空行，表达本次推理任务；
- 结果态：core.reason 返回的是**任意 JSON 对象**，不是固定 `output` 数组。显示 JSON 徽标，并选择首个可读的标量字段为 `key: value` 截断摘要；没有可读标量时只显示 `JSON 对象 · N 个字段`；
- core.answer/core.ask 保持不渲染 gist。core.answer 当前直接生成 TEXT，ActionResult 为 `{text, references}`，主对话回答卡逻辑不变。

## 改进点 7：低频族 gist 摘要行（详情不动）

- **core.wait**：这是等待意图，不是 Job 完成事实。按 event_kind/topic/source/timeout 显示 `等待 job 事件 · 30s` 等，不显示 `completed`；core.job.status/stop 才展示实际 job state；
- **ACP**：delegate 规划态显示 brief 首行；结果显示实际 `connection_id · job_id 已受理`，没有 state 时不写 running；respond/collect/connect/disconnect 使用各自真实回执；
- **MCP**：search 复用真实命中列表；call 用 params 的 `server_id:tool_name` 加结果内容/项数；describe_* 显示实际服务或工具数；
- **Session organize**：显示 `变更 N 个引用 · 新建 M 个解释`。changed_refs 还包含关系与撤回，不能改写成“修订 M”；
- **Reflection write**：显示实际 ref 与 written/reviewed/decision 等事实。
