# Action 渲染增强（Gist 与详情视图富化）执行计划

日期：2026-10-09

状态：待逐项确认与实施

范围：`visualization/src/features/chat/ActivityGlimpse.tsx`（glimpseBody）、`visualization/src/features/trace/resultViews.tsx`（FAMILY_VIEWS）、`visualization/src/features/trace/SearchResultView.tsx`。三层渲染架构与分类映射（`registry.ts` ACTION_FAMILY）保持不变：对话 trail、过程面板内联、详情面板共用同一映射；gist 内容经 `glimpseBody()` 单源复用。

## 分析与设计判断

### 分簇是否合理

合理，保持不动。13 族是按**结果载荷形状**聚类（而不是按 domain），所以 home/memory/workspace 的写操作天然同族复用 diff 与写入统计——这正是想要的；generic 兜底诚实（原始 JSON + 说明行）。唯一映射遗漏 `workspace.inspect`（catalog 64 中唯一未映射）补一行即可归 inspect 族。

### 当前两层的能力落差

- **详情层**：13 族都有定制视图，但多数是"字段表（FactGrid）+ 折叠文本（Excerpt/JsonTree）"的朴素结构——信息全，但不精致；write 的 diff（刚补）是唯一接近 gist 精致度的；
- **gist 层**：write/execution/search 三族富渲染，其余族是一行文本或 JSON 兜底。

### 设计原则

1. **gist = 两态一句话**：规划态回答"要做什么/输入是什么"，结果态回答"做成了什么"；
2. **详情 = 规划输入区 + 执行结果区**，族风格容器（终端块、diff 卡、报告卡、网页结果卡）；
3. 字段提取共享：glimpse 与详情视图的字段提取抽成共享 extractor，防两份逻辑漂移；
4. 低频族（acp/mcp/session-organize）详情保持字段表现状，只补 gist 摘要行。

## 按族改进设计（逐项实施顺序）

**前置项（基础，先行实施，无界面变化）**：gist 与详情视图共享字段提取 extractor（命中列表/写入统计/计数，抽到 `resultViews.tsx` 共享函数）；`registry.ts` 补 `"workspace.inspect": "inspect"` 归族（matrix 测试同步）。

### 改进点 1：write 族——详情"规划输入区 / 执行结果区"分区

- 详情（diff 已于上一轮落地）：在 WriteView 内加分区——**规划输入区**（diff 卡/指令，来自 params）与**执行结果区**（operation/chars/links，来自 result）各占一个带小标题的区块；无 diff 数据时保持现状；
- gist 不动。

### 改进点 2：execution 族——详情终端风格贯穿

状态：**已实施**（2026-10-09，含 workspace.inspect 归族 + matrix 测试 64 项）

- 详情：`ExecutionView` 改为终端式——规划命令块（`# cwd` + `$ command`，复用 term-block）在上，stdout/stderr 用 term-block 终端块呈现（替换 Excerpt 文本框），状态行（job/kind/state/exit code）保留字段表；
- gist 不动（已是终端块）。

### 改进点 3：analysis 族——意图 + Markdown 报告卡

- 详情：intent 行保留，answer 从 Excerpt 纯文本改为 **Markdown 渲染的报告卡**（md-calm），coverage 收成指标小字（complete · 3 files · 4.2k chars），sources 保持 ref 链接；
- gist 结果态补：报告标题 + 首行 + 字数（`分析报告 · 860 字符`）。

### 改进点 4：web 族——统一"网页结果卡"三段式

- 三动作共用同一骨架（标题区 + 摘录区 + 列表区）：`search_by_kimi` 保持 answer 摘录+来源列表；`fetch_with_*` = 抓取器徽标 + 标题 + 字数 + 摘录；`discover_pages` = 种子链接 + `N 页 · M 已访问 · K 失败` 计数行 + 页面状态徽标列表；
- gist 结果态各补一行：答案首行 / 标题·字数 / 发现 N 页（M 已访问）。

### 改进点 5：inspect 族——微调

- 详情 Read text 折叠区补行号（等宽 + 左侧行号列）；
- gist 结果态补规模：`读到 42 行` / `N 项`。

### 改进点 6：core.reason 补 gist

- 规划态"推理任务：首个 guide_block 首行"；结果态"推理产出：output 首条文本截断 + JSON 徽标"；core.answer/core.ask 保持不渲染。

### 改进点 7：低频族 gist 摘要行（详情不动）

- job-control：`等待 job_7f2a · completed ✓`；acp：`委派 codex：brief 首行` / `conn_3 · job_9 running`；mcp：search 复用命中列表、call → `server:tool · N 项`、describe_* → `N 个服务/工具`；session-organize：`新建解释 2 · 修订 1`；reflection-write：`memory:daily/… · written ✓`。
