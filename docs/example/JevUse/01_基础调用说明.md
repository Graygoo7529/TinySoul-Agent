# Jev 调用说明（TypeSafe API）

调研日期：2026-09-22。本文按 TypeSafe 官方 Quickstart/API 文档整理，并结合用户提供的知乎文章做交叉核对。官方资料可验证的是 API 契约与 SDK 用法；知乎文章中关于底层架构、速度、成本和“零幻觉”的部分，属于厂商发布或媒体转述，不能当作已公开的模型实现证明。

## 一句话理解

Jev 不是聊天模型。调用方提供一份 `state`（文本、JSON 对象或数组）以及一组预先定义的 typed questions；Jev 返回 `Choice`、`Score`、`Noul` 三种结构化判断及概率信息，程序直接据此路由、打分或触发分支。

## 最小调用链

1. 在 TypeSafe 控制台申请 API key。
2. 把 key 放入服务端环境变量 `TYPESAFE_API_KEY`，不要放进前端代码或提交到仓库。
3. 向 `POST https://api.typesafe.ai/v1/systemone` 发 JSON 请求。
4. 读取 `answers` 中与 question id 同名的答案，并由业务代码决定阈值、降级或人工复核。

## HTTP API

```powershell
$env:TYPESAFE_API_KEY = "YOUR_API_KEY"

$body = @'
{
  "state": {
    "message": "我被重复扣款了，请尽快退款。",
    "order_id": "A-104"
  },
  "model": "jev-latest",
  "questions": {
    "refund_requested": {
      "type": "noul",
      "instructions": "用户是否明确要求退款？"
    },
    "department": {
      "type": "choice",
      "instructions": "这条请求应该交给哪个团队？",
      "criteria": {
        "billing": "支付、账单、重复扣款或退款",
        "technical": "产品故障、接口或集成问题",
        "account": "登录、账户或资料问题",
        "other": "以上类别都不适用"
      }
    },
    "urgency": {
      "type": "score",
      "instructions": "这条请求有多紧急？",
      "criteria": ["可排队处理", "本周处理", "今天处理", "关键服务已中断"]
    }
  }
}
'@

Invoke-RestMethod `
  -Uri "https://api.typesafe.ai/v1/systemone" `
  -Method Post `
  -Headers @{ Authorization = "Bearer $env:TYPESAFE_API_KEY" } `
  -ContentType "application/json" `
  -Body $body
```

请求的三个顶层字段是：

| 字段 | 含义 |
|---|---|
| `state` | 要判断的内容，可为字符串、对象或数组 |
| `model` | 官方 Quickstart 使用 `jev-latest`；固定版本评测可使用具体版本 ID，并记录响应里的实际 `model` |
| `questions` | 命名的问题映射；答案会用相同 id 返回 |

### 三种问题类型

| 类型 | 适用场景 | 请求中的 `criteria` | 主要返回值 |
|---|---|---|---|
| `noul` | 是/否判断，例如“是否需要人工复核” | 可选的 `true` / `false` 说明 | `noul`，0 到 1，表示“是”的概率 |
| `choice` | 固定集合中选一个，例如部门、路由、类别 | 对象，键是选项，值是选项说明；最多 255 个选项 | `choice`、每项 `probabilities`、`confidence` |
| `score` | 有序等级，例如严重程度、紧急度 | 有序数组，官方 API 接受 2 到 10 个等级 | `score`、`legend`、`probabilities`、`confidence` |

`score` 是概率加权后的等级值，因此可能落在两个等级之间；如果业务关心“达到最高级的概率”，应读取对应等级的 `probabilities`，不要只看 `score`。

## Python SDK

官方 Python SDK 要求 Python 3.10+：

```bash
pip install typesafe-sdk
```

```python
import os
from typesafe_sdk import Choice, Noul, Score, TypeSafeClient

assert os.environ.get("TYPESAFE_API_KEY"), "set TYPESAFE_API_KEY first"

with TypeSafeClient() as client:
    response = client.system_one(
        state={"message": "我被重复扣款了，请尽快退款。"},
        questions={
            "refund_requested": Noul(
                instructions="用户是否明确要求退款？",
            ),
            "department": Choice(
                instructions="应该交给哪个团队？",
                criteria={
                    "billing": "支付、账单、扣款或退款",
                    "technical": "产品故障或技术集成",
                    "other": "其他请求",
                },
            ),
            "urgency": Score(
                instructions="这条请求有多紧急？",
                criteria=["可排队处理", "本周处理", "今天处理"],
            ),
        },
    )

print(response.nouls["refund_requested"].noul)
print(response.choices["department"].choice)
print(response.choices["department"].confidence)
print(response.scores["urgency"].score)
```

异步客户端使用 `AsyncTypeSafeClient`、`async with` 和 `await client.system_one(...)`。官方 SDK 默认处理重试；直接 HTTP 调用时，对 `429` 和 `529` 使用指数退避。

## JavaScript / TypeScript SDK

官方文档给出的 Node.js 20+ 安装方式：

```bash
npm install @typesafe-ai/sdk
```

```ts
import { choice, TypeSafeClient } from "@typesafe-ai/sdk";

const client = new TypeSafeClient();
const result = await client.systemOne({
  state: { document: "I was charged twice. Please fix this ASAP." },
  questions: {
    category: choice("What is this ticket about?", {
      billing: null,
      technical: null,
      other: null,
    }),
  },
});

console.log(result.answers.category.choice);
```

## 返回结果与程序分支

典型响应形状：

```json
{
  "model": "jev-1.13.0",
  "answers": {
    "department": {
      "type": "choice",
      "choice": "billing",
      "probabilities": { "billing": 0.91, "technical": 0.05, "other": 0.04 },
      "confidence": 0.88
    },
    "refund_requested": { "type": "noul", "noul": 0.96 }
  },
  "usage": { "input_tokens": 180, "output_tokens": 20 }
}
```

业务代码应自行定义门槛，例如：

```python
refund_prob = response.nouls["refund_requested"].noul
department = response.choices["department"]

if refund_prob >= 0.95 and department.choice == "billing" and department.confidence >= 0.80:
    route = "自动进入退款审核"
else:
    route = "人工复核或补充信息"
```

`confidence` 是基于概率分布集中程度的厂商指标，不等于这一次判断必然正确，也不等于业务准确率。上线前需要用自己的标注集测准确率、覆盖率、Brier/ECE，以及低置信度样本的处理策略。

## 适合与不适合的任务

适合：客服分流、内容初筛、风险/严重度评分、Agent 工具路由、是否需要人工复核、校验生成模型输出。

不适合单独承担：聊天、长文写作、代码生成、开放式问答、需要详细解释的推理、精确算术和日期计算。复杂判断应拆成多个原子问题，再由程序组合；需要自然语言解释时，交给生成式 LLM。

## 对知乎文章的核对

用户给出的知乎链接当前无法直接访问，但搜索结果显示其内容与“Jev 爆火硅谷！哑巴 AI 卷疯 14 万开发者”一类文章一致：强调 Jev 不生成文本、输出 Choice/Score/Noul、速度和成本优势，以及与传统 LLM 的 System One/System Two 分工。

可由官方文档确认的部分是：三种问题类型、请求端点、`state/model/questions` 结构、答案字段、SDK 包名和 API 错误码。官方发布文章还明确把 70–500ms、输入 $0.042/百万 token、并行输出和 RLCD 作为 TypeSafe 的产品/评测口径；这些数字和技术说明属于厂商声明，不能直接视为独立复现结果。知乎文章中的“零幻觉”应准确理解为“输出空间和类型由 schema 限定，避免自由文本格式错误”，并不代表业务判断不会错。

## 研究项目的建议接入方式

当前目录已有关于 Jev 技术路线、校准和复现的研究记录。若要把调用纳入实验，建议固定 `jev-1.13.0` 而不是只用 `jev-latest`，保存完整 request/response、`usage`、网络端到端耗时、问题数、候选项顺序和数据集版本；同时保留低置信度人工复核分支。不要把 Jev API 的行为误写成本地可下载模型，也不要据此声称已经复现 TypeSafe 的内部架构或 RLCD 损失函数。
