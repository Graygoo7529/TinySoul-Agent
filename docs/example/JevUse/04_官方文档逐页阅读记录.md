## 官方能力总览

### 核心调用模型

Jev 接收 `state` 和命名的 typed `questions`，通过 `POST /v1/systemone` 返回 `answers`。`state` 可为字符串、对象或数组；同一个 state 可以放多个问题。问题 ID 只用于响应映射，真正语义来自 `instructions` 和 `criteria`。

官方提供三种原语：

- `Choice`：从有限候选中选一个，返回选项、全量概率和 confidence；
- `Score`：在有序等级上评分，返回概率加权分数、等级分布和 confidence；
- `Noul`：判断 yes/no，返回 yes 的 0 到 1 概率，不带 confidence。

官方强调问题彼此独立、可在一次调用中并行求值；复杂判断应拆成原子问题，再由程序组合。`confidence` 是概率分布形状的摘要，不是业务正确率证明；高风险动作应使用更高门槛并保留复核路径。

### 进阶表达能力

`instructions`、Choice 的选项描述、Score 的等级、Noul 的 true/false criteria 都可以是 JSON 结构，而不只是字符串。结构化描述可以加入 `what`、`not_for`、`examples`、待判断字段和比较对象，适合 KG 证据判定、RAG 引用核验和 Agent 策略门控。

深层 taxonomy 可以逐层 Choice；概率接近时保留 beam 分支。抽取场景应先用 regex、parser 或生成式模型找出候选 span，再让 Jev 从候选中选择，最后由代码做日期、金额、字符串和结构校验。

### 官方模式和集成

- speculative fan-out：一次发送可能需要的多个问题，再由代码忽略当前不相关的答案；
- confidence-gated routing：答案决定“是什么”，confidence 决定“是否行动”；
- composite scoring：多个原子分数由代码按权重组合；
- intent routing：在确定性逻辑、专用 LLM 和人工之间路由；
- RAG passage classification、重排、逐行搜索、引用核验和 LLM guardrail；
- function calling：将自然语言映射到函数名和封闭参数集合，但真实函数执行仍由代码负责；
- skill suggestion：先候选排序，再二次复核；
- KG entity alignment：一个 Score 配合多个 Noul 暴露字段冲突；
- SDE cascade、日期提取、预解析值选择、层级分类和 confidence fallback。

### SDK 能力

Python SDK 提供同步/异步客户端、问题和答案类型、模型列表、可配置 RetryPolicy、异常分类、request id、Pydantic `response_model`、日志、不同 base URL，以及 raw question/extra body 的前向兼容。JavaScript SDK 提供 Node.js 20+ 的 ESM/CommonJS 和 TypeScript 类型推断。

本项目对 SDK 的结论和安装指令见 [Python SDK：用途与采用建议](./05_Python_SDK.md)。

### 模型与输入限制

Models 页面记录的当前 Jev 1.13 标识为 `jev-1.13.0`，`jev-latest` 是稳定别名，`jev-preview` 是预览别名；别名会移动，响应的 `model` 字段才是本次实际版本。单请求上下文预算为 64k tokens，`state` 加最长单个问题的预算为 32k；当前输入是文本、JSON 对象或文本数组，不接受图像、音频和视频。官方还提醒速率限制可能动态调整，不能把文档中的限额当作永久 SLA。

## 与本项目两个应用方向的直接对应

### JevKG

优先采用 029 的实体对齐、030 的 RAG passage 分类、031 的引用核验、036 的层级分类。候选实体/边由检索和实体链接生成，Jev 只在有限候选上打分或选择；冲突、时态和写图由程序处理。

### JevSession

优先采用 016 的 speculative fan-out、017 的 confidence gating、019 的 intent routing、027 的 function calling、028 的 skill suggestion 和 032 的 guardrails。Jev 可判断动作类别、上下文充分性和是否需要确认，但权限、参数校验和工具执行必须留在确定性代码。

## 官方限制（必须进入实验设计）

Jev 1.13 文档明确提醒：它可能逐字理解指令，不适合精确数学、计数、日期比较、多层间接引用、大而无关的 state、对抗内容、互相矛盾的 instructions/criteria 和自由文本生成。应把计算留给代码、先过滤 state、显式写边界、测试 adversarial cases，并把生成任务交给生成式模型。
