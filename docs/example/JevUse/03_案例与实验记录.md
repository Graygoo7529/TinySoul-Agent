# 案例与实验记录

本文件记录调用示例的目的、输入 schema 和观察结果。真实 API 响应默认写入被忽略的 `results/` 目录；提交研究结论前应把脱敏后的结果和固定版本写入本文件或单独的实验报告。

## 案例 A：支持工单分流

输入包含用户消息和订单上下文，问题包括：是否要求退款（Noul）、应由哪个团队处理（Choice）、紧急度（Score）。它验证官方 Quickstart 的基本调用路径，也适合作为中文输入的初始基线。

预期代码路径：`examples/run_cases.py --case support`。

记录指标：路由准确率、退款判断的 Brier/ECE、低置信度覆盖率、p50/p95 端到端耗时。

## 案例 B：知识图谱候选边验证

`state` 由候选三元组、文本证据、来源和时间组成。Jev 不负责遍历图或生成三元组，而是对有限候选做：

- `Choice`：接受、拒绝、需要复核；
- `Score`：证据支持程度；
- `Noul`：证据是否明确支持该关系。

图数据库写入、冲突处理、时间有效性和证据回链由程序完成。详见 `../03_JevKG/`。

## 案例 C：Agent 会话上下文门控

`state` 由当前会话摘要、最近工具结果、待执行动作和策略约束组成。Jev 可以判断：是否需要压缩上下文、下一步属于哪类动作、是否需要人工确认。它不替代 Agent 的长程规划，也不应单独执行高风险工具调用。详见 `../04_JevSession/`。

## 2026-09-23：首次真实 API 探索

使用项目根目录 `.env` 中的 key，通过 `examples/run_cases.py` 发送了三次脱敏请求。服务返回版本均为 `jev-1.13.0`；响应文件保存在被 `.gitignore` 忽略的 `results/` 目录。

| 案例 | 主要结果 | input/output tokens | 端到端耗时 |
|---|---|---:|---:|
| support | `refund_requested=0.99`；`department=billing`；`urgency` 期望分数 `1.99`，最高概率为“今天处理” `0.92` | 467 / 70 | 850.3 ms |
| kg | `accept_edge=0.85`；`decision=accept`，概率 `0.89`；证据强度期望分数 `1.94` | 479 / 72 | 1556.2 ms |
| session | `needs_confirmation=0.98`；`action_class=irreversible`，概率 `0.97`；上下文充分性偏低，期望分数 `0.48` | 513 / 80 | 766.4 ms |

这些是单次调用的观察结果，不是准确率或校准结论。尤其是 KG 和 Agent 案例只有人为构造的单个样本，后续需要固定数据集、重复调用、网络位置和模型版本后再比较。

## 2026-09-23：官方 Python SDK 验证

在项目 `.venv` 中安装 `typesafe-sdk==0.7.1`，运行 `examples/sdk_call.py` 成功。SDK 调用返回 `jev-1.13.0`，并额外提供了 `request_id`；本次结果为退款概率 `0.99`、部门 `billing`（confidence `1.0`）、紧急度期望分数 `1.35`（confidence `0.43`），usage 为 406/70 tokens。该验证说明 SDK 配置、类型化问题、响应对象和 request id 可以正常工作，不构成模型质量评估。

同日通过 `TypeSafeClient().models.list()` 做只读检查，账号返回别名 `jev-latest` 和 `jev-preview`；推理响应实际报告的版本仍为 `jev-1.13.0`。模型列表不应替代对每次推理响应中 `model` 字段的记录。
