会话历史：对于 session map 的构建，建议先设计结构化方法，在 turn 结束时保存所需 trace（问答、追问、补充输入、推理 action、所设计的 links），可以采用无模型方法固定构建，并增加 core action 支持新 turn 开始时对前一个成功的 turn 进行整理；我们需要考虑 session map 内哪些是需要语义整理的，哪些是不用的；哪些语义整理仅仅附加一些关系、线索或评判，哪些会重塑语义地图。最原始的形态是一个 history list，包含每个 turn 的 QA，我们可以以 turn 为粒度，把 turn 内部重要的信息也披露出来，例如用户 append 消息、智能体追问消息和用户补充、智能体 core.reason 行动，甚至本轮 turn 中所涉及的 links、事实和资源等）；在此基础上，语义梳理会把每个 turn 的逻辑进一步整理：如果会话在迭代进行，那么简单来看就是 T1->T2->T3，但实际上话题可能是发散树状结构，例如 T1->T2->T3 同时 T1->T4->T5，即最新尾部的 turn 可以线性回溯到一个话题根，而话题根随着会话以树状散发，新的 turn 可能是顺接前一个 turn 推进，也可能是 fork 一个分支，或者是对于前一个 turn 的否定，或者是由于用户追加、agent 提问等发生了 steer 等等… 你可以进一步顺着这个思路发散考虑；因此，在 session map 可能呈现出一种森林的结构，每一个话题都是一个话题树的根，但会话呈现出最新的交互，但从这个交互依然可以追溯出这个话题的历史、这个话题中的相关分支（甚至导致这个分支的原因）、以及其它进行过的话题；更进一步地，在整理时可以补充 turn 与 turn 之间的关系、turn 与 turn 内部推理、关联资源（links）、事实和语义推断，有些事实和资源可以是跨 turn / 跨分支和话题存在的，甚至就是推动 session 发展变化的原因。
