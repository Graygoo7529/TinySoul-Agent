# Getting started with TinySoul

[Project introduction](README.en.md) · [简体中文](getting-started.zh-CN.md)

The Python backend and desktop frontend run separately, either on one machine or with the frontend connecting to a dedicated host. Read the safety notice in the project introduction and use an isolated test environment.

## 1. Prerequisites

| Component | Requirements |
| --- | --- |
| Python backend | [uv](https://docs.astral.sh/uv/getting-started/installation/), which installs Python 3.13 and project dependencies |
| Desktop frontend from source | Node.js 22.12+, pnpm, Rust stable (including Cargo), and the [Tauri system prerequisites](https://v2.tauri.app/start/prerequisites/) |

Windows desktop development also needs MSVC C++ Build Tools and WebView2; see the Tauri guide for macOS and Linux dependencies. A backend-only machine needs neither Node.js nor Rust. A frontend-only machine does not need the Python backend installed.

Clone the repository. Except for the frontend commands, run everything below from the **repository root**. Conda and manual environment activation are unnecessary: uv creates `.venv` using `.python-version` and installs dependencies from `uv.lock`.

```sh
uv python install
```

## 2. Install the backend and initialize its data directory

Choose one installation. Both examples store configuration, conversations, and files in `../my-agent`, separate from the source checkout. Substitute your own path if needed. The initialization target must be new or empty.

### Development installation (for ongoing source changes)

```sh
uv sync --locked --extra dev
uv run --locked --extra dev tinysoul init ../my-agent
```

`dev` includes tests, type checking, and Python dependencies for optional capabilities. The checkout is installed in editable mode: **restart the backend process** to load source edits. A dedicated host can use this installation too.

### Standard installation (base runtime dependencies)

```sh
uv sync --locked --no-editable
uv run --locked --no-editable tinysoul init ../my-agent
```

This installs a copy of the current code into the virtual environment. For MCP/ACP or web crawling, add `--extra external-tools` or `--extra web-crawl` respectively, keeping the same options on subsequent `sync` and `run` commands. Programs required by external services or tools must be installed separately.

**Installation options and configuration templates are independent.** Both examples use the default `standard` template. `init --config-profile development` uses the maintainer's configuration, with some providers, capabilities, and a local proxy already enabled; adjust it for your machine before use. `--extra dev` does not require that template.

## 3. Configure models and start the backend

The initialized data directory contains:

| Location | Purpose |
| --- | --- |
| `.env` | Backend environment settings, model API credentials, and listening address |
| `.auth` | Stable login token generated by `init`, in the form `token=...` |
| `configs/` | TOML configuration for models, tasks, capabilities, and other modules |
| `home/`, `memory/`, `runtime/`, `archive/` | Personal guidance, memory, active data, and archives |

The `standard` template disables model providers initially. Before chatting, add your chosen provider's API credentials to `.env`, enable it in `configs/llm/providers.toml`, and ensure the bindings in `configs/llm/models/` and task model chains in `configs/llm/tasks.toml` refer to available models. You can also configure these through frontend settings after starting the backend, then save and apply. Restart the backend after editing files manually. See the [LLM configuration design](../design/llm.md).

Start a development installation:

```sh
uv run --locked --extra dev tinysoul start --root ../my-agent --mode normal
```

Start a standard installation:

```sh
uv run --locked --no-editable tinysoul start --root ../my-agent --mode normal
```

The backend stays running in the terminal and exposes the frontend connection endpoint. `--mode normal` selects terminal output detail; alternatives are `verbose` and `model`. To run a single non-interactive task, replace it with `--once "Summarize today's work"`; that mode does not open the frontend Endpoint.

## 4. Start the frontend and sign in

Open another terminal and enter the frontend directory from the repository root:

```sh
cd visualization
pnpm install --frozen-lockfile
pnpm tauri dev
```

Local and remote connections use the same address-and-token login. The default local address is `127.0.0.1:1430`. Copy the **value after `token=`** from `.auth` in the backend data directory. The backend requires a valid `.auth` to start; normal restarts do not change the token.

The frontend remembers the address and token locally and reconnects next time. **Log out** clears those local credentials so you can switch hosts. Closing the frontend disconnects it; the backend must remain running. Interface settings offer light/dark themes and Chinese/English, with preferences stored in the connected backend project.

From `visualization/`, `pnpm tauri build` creates desktop bundles. `pnpm dev` starts a browser preview without Rust; some desktop features behave differently there. See the [frontend README](../../visualization/README.md) for further development and check commands.

## 5. Connect to a dedicated host

Set the listening address in `.env` in the host's data directory, then restart the backend:

```dotenv
TINYSOUL_ENDPOINT__BIND_HOST=0.0.0.0
TINYSOUL_ENDPOINT__PORT=1430
```

On your computer, enter a reachable host IP such as `192.168.1.20:1430` and the token from that host's `.auth`. `0.0.0.0` means the backend listens on all network interfaces; it is not a frontend connection address. Allow trusted devices to reach the port over a trusted LAN or VPN, and keep it off the public internet.

The backend's `.env`, `.auth`, TOML files, and runtime data stay on the host; the client stores only its login details. Do not commit credential files. Reconnecting lets you return to a backend that is still running; it does not resume an unfinished Turn after the backend process exits.

## 6. Updates and checks

After updating the checkout, run `uv sync --locked --extra dev` for a development installation, then restart the backend. For a standard installation, run `uv sync --locked --no-editable --reinstall-package tinysoul` and restart. Run `pnpm install --frozen-lockfile` again when frontend dependencies change.

After changing Python dependency declarations, run `uv lock`, commit the lockfile with the change, and sync the environment. Recreate `.venv` on a new machine instead of copying it. Updating source does not overwrite configuration or Home in an existing data directory.

Backend development checks:

```sh
uv run --locked --extra dev python scripts/test.py
uv run --locked --extra dev python scripts/test.py --suite full
uv run --locked --extra dev ty check
```

The first command defaults to Fast. Full includes local integration and packaging checks; run it with type checking before completing code changes. Local tests need no model credentials and keep artifacts under the ignored `.local-test/` directory. See [test conventions](../../tests/README.md) for focused tests, external checks, and diagnosis.

### Reset only when clearing a disposable project

Stop the target backend and run this from outside its data directory:

```sh
uv run --locked --extra dev tinysoul reset ../my-agent --config-profile standard
```

**This preserves `.env` and `.auth` and replaces everything else**, including configuration, Home, Memory, conversations, Workspace, archives, and any `.git` inside the target. The command explicitly selects the standard template; reset defaults to development when `--config-profile` is omitted. Reset clears a test project; it is not a routine update or data migration command.
