# LLM 设计

## 定位

LLM 模块负责把 TinySoul 内部的模型调用请求转换为具体供应商 API 调用，并把模型输出转换为可解释的统一结果。

LLM 模块不负责从语境、状态、记忆或工作区中构造提示词。上层模块负责维护和选择语境内容，并把最终要调用模型的消息栈交给 LLM 模块。

## 边界

供应商、模型、任务调用和模型链应分开理解。

供应商表达外部 API 的接入方式，包括认证、端点、请求格式、参数差异、错误分类和响应归一化。供应商不决定某个业务任务应该使用哪个模型。

模型表达可被调用的具体模型及其能力。上层选择模型时应面向模型能力，而不是直接面向供应商。模型能力应保持抽象但真实，例如文本输入、图像输入、原生文件输入、JSON 对象输出、推理输出和提示缓存支持。

任务调用表达一次模型请求。它接收上层已经构造好的消息栈、期望输出形式、调用参数和可选缓存意图，完成能力校验、模型选择、调用执行、重试切换和输出解释。

模型链表达不同任务用途对应的候选模型顺序，以及失败后的重试和切换策略。链路切换的单位是模型，不是供应商。

## 消息栈

TinySoul 内部使用自己的消息栈表达模型输入，而不是直接使用某个供应商的报文格式。

消息栈由有序消息组成。每条消息保留模型接口可理解的对话角色，例如系统、用户、助手或工具。角色不用于表达 TinySoul 内部语境分类；语境分类应通过额外的来源或范围信息表达。

每条消息可以包含多个片段。第一阶段只需要表达文本、图像和文件输入。纯文本调用只是只有一个文本片段的普通消息，不需要单独设计另一套简化结构。

文件输入只表达本次调用随请求提供的文件附件。LLM 模块第一阶段不维护长期文件引用、供应商文件标识的生命周期或跨供应商文件复用。若模型或供应商不支持原生文件输入，上层可以先把文件转换成文本，再作为普通文本片段加入消息。

## 输出契约

第一阶段只支持纯文本和 JSON 对象两类输出契约。

JSON 对象是 TinySoul 的主要结构化输出方式。供应商支持原生 JSON 输出时应使用原生参数；供应商不支持或能力未确认时，可以通过提示约束和本地解析完成兼容。解析成功只表示模型输出可以被解释为对象，具体业务字段是否正确仍由调用方模块校验。

暂不引入 JSON Schema 作为核心契约。严格 schema 支持涉及供应商能力差异、参数映射和 schema 子集限制，适合在 JSON 对象契约稳定后再扩展。

## 多模态

多模态能力以模型能力为准，而不是以供应商整体能力为准。

图像输入和原生文件输入需要在调用前进行能力校验。支持时由供应商适配层映射为对应 API 结构；不支持时应清晰报错或要求上层转换输入形式。

文本化附件和普通提示文本在模型接口层都属于文本输入，但可以在消息来源信息中保留差异，便于调试、预算裁剪和后续摘要。

## 推理输出

部分模型会返回推理或思考内容。LLM 模块应在统一响应中保留这类信息，但不应把它作为默认业务结果。

推理内容主要用于调试、日志和后续分析。调用方应以正式输出内容和输出契约作为业务判断依据。

## 提示缓存

提示缓存应表达为一次请求的缓存意图，而不是由 LLM 模块维护完整缓存生命周期。

缓存意图包含稳定上下文身份和适合参与缓存的消息范围。供应商支持显式缓存键时可进行映射；不支持时可以忽略。对于自动前缀缓存的供应商，缓存意图可用于帮助上层保持稳定消息前缀。

缓存范围不是模型角色。角色用于供应商对话结构，缓存范围用于 TinySoul 判断哪些消息属于稳定系统提示、长期规则或其他适合复用的上下文。

## 重试与切换

任务可以配置模型链、重试次数和等待时间。失败后切换的单位是模型。

模型链配置只描述任务用途和候选模型顺序；异常恢复逻辑负责根据策略执行重试、等待、切换和链路状态更新；任务调用本身只负责单次模型请求的能力校验、供应商调用和输出解释。三者应保持分离，避免一次调用流程被异常恢复细节淹没。

模型链第一阶段采用顺序尝试策略。一次调用从当前起点开始沿模型链向后尝试；某个模型失败后继续尝试链上的下一个模型。走到链尾仍失败时，才进入下一轮并重新从链头开始。尝试轮数耗尽后返回失败。

个人项目场景下，模型链默认进行有限但较充分的循环尝试，以便人工介入修复网络、密钥或配置问题，同时避免错误配置导致调用永久卡住。需要持续等待时，可以显式配置为不限制尝试轮数。但每次失败都应有明确日志、等待间隔和当前模型状态，避免无间隔快速重试。

应提供重置链路状态的能力，使用户或上层流程可以让模型链回到初始尝试顺序。

模型链可以配置成功模型的偏好时间窗口。某个非链头模型在失败恢复中调用成功后，后续调用可以在一段时间内从该模型继续向后尝试；窗口过期后应重新回到链头模型尝试。这样既能避免频繁打到短时间内不可用的链头模型，也能在一段时间后自动回到优先模型。

## 当前取舍

第一阶段聚焦文本、图像、原生文件输入、JSON 对象输出、推理输出保留、提示缓存意图、模型链重试切换。

暂不实现流式输出、工具调用、严格 JSON Schema、长期文件资源管理、跨供应商文件复用和复杂企业级可靠性机制。这些能力只有在真实调用场景需要时再扩展。
