# 前端界面本地化

前端已接入本地化的固定交互文案由 `src/i18n/` 负责。`zh-CN` 是默认语言，`en-US` 是当前支持的英文语言。语言事实属于项目 Presentation 配置，`uiPrefsStore` 只保存服务端确认值和当前待提交 patch；连接地址、token、导航位置等客户端信息不参与语言选择。

当前正式界面入口已接入双语显示，包括 Shell、连接页、Settings、Chat、Trace、Runtime、Workspace、Home、Memory、History、Context、Resources 及 Markdown 展示外围。切换语言时，已打开的 Toast、Inspector 和配置搜索结果会重新读取当前语言；输入、草稿、正文、模型内容和诊断原文保持不变。下文说明实现结构、职责边界和新增文案规则。

## 文案所有权

- React 组件中的按钮、标题、空状态、加载状态、tooltip、placeholder 和无障碍标签使用稳定 message ID，通过 `useI18n().t()` 读取。字典按 `common`、`settings`、`chat`、`trace`、`runtime`、`workspace`、`home`、`memory`、`history`、`context`、`resources` 和 `presentation` 分组维护。
- 非 React controller 使用 `t()` 读取当前 store 投影。插值参数传入 `t(id, params)`，不把动态值拼入 message ID。
- ConfigCatalog 的 `field.path`、document 的 `documentSet/documentKind/path`、surface/group/collection 的 `id` 和 choice 的 `value` 是翻译身份。中文字典只覆盖确有稳定语义的身份，未知身份返回后端 source 文本。
- 项目、用户、Agent 和模型产生的正文，以及 Action semantic、模型/provider/action 名称、配置值、路径和引用都直接显示。`rawText()` 用于表达这一层边界。
- Endpoint 稳定错误 code 和运行/Action 状态 value 可在 `protocol/` 中提供固定摘要，分别通过 `tError`、`tStatus` 和 `tActionState` 读取；原始 message 和 `details` 仍保留用于诊断，未知 code 不做文本猜测。

新增固定 UI 文案时，同时在 `messages/zh-CN` 和 `messages/en-US` 增加同一个 ID。新增 catalog 字段时只需按稳定身份补中文映射；在补齐之前应能正常回退 source 文本。测试检查字典 key 集合、身份映射和 fallback，不逐项锁定经常变化的模型、provider、prompt 或 Action catalog 内容。

## 验证

`src/i18n/index.test.ts` 验证双语 key 集合一致、ConfigCatalog 身份映射、未知条目回退、choice 按 value 翻译和协议 code 映射。Interface 页面测试验证语言保存，presentation controller 测试验证偏好的保存、失败与连接隔离；页面测试覆盖代表性显示和动态内容保留。当前检查结果为 TypeScript 通过、Vitest 100 个文件/884 个测试通过、Vite production build 通过。
